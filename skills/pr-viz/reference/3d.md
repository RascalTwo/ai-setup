# 3D in a PR film — when it earns its place

From one long review of 3D versions of four stacked PRs (sai-genai-accelerator #1187, #1189,
#1190, #1191). How to make 3D render is viz's `reference/3d.md`; the tour's `"view": "3d"` is in
`scenes.md`. This is what the reviewer kept, what they cut, and why.

## Earn it per PR

- **Depth has to mean something in *this* PR.** A 3D view of the branch stack looked good and
  was cut: it would look the same on every PR, so it belongs on none.
- **3D that says what 2D says is noise.** #1191's before→after scores as 3D lanes added nothing.
  The useful part was the motion (each dot sliding from its old score to its new one), and that
  went back into the 2D scene.
- **What stayed:** a path a request travels (#1190), a dependency chain you walk back through
  (#1189), and the diff tour laid out by module (#1187). In each, position in space is position
  in the system.

## Tell the story in the order it's understood

- Start from what the reviewer sees, then walk to the cause. #1189 opens on the three services
  that broke, then moves back to `register()`, the OTel bundle, and finally the exporter. It was
  the reverse at first, and that read backwards.
- Follow the real flow, verified in code. #1190: the request goes through the function URL and
  waits at the Lambda; a scan goes to DynamoDB, fills, and comes back; then the response goes out
  through gzip. Check every hop. Two briefs were wrong (an API Gateway that doesn't exist, one
  "shared" function that was really two) and the agents caught it by reading the source.
- Cut evidence that isn't the story. A dev `/openapi.json` byte count proved gzip was on. It
  said nothing about the payoff, so it left the scene.

## Everything visible, one thing readable

- Keep the whole structure in frame, with far things small. Fly forward to the part being
  talked about so it's readable and the next one peeks in. Let passed parts fall away. End by
  pulling all the way back, ahead of whatever is changing (the green spreading down #1189's
  chain).
- Several panels on one line: **two → one wide shot of both, held. Three or more → hold on
  each for an equal share, then snap.** Panning across them was hard to read. Read them in the
  order the narration names them (`"order"` on the tour entry), so the camera is on S3 when
  S3 is said.
- **Lines follow the code, not the camera.** A path painted from stop to stop meant nothing.
  A line down each module's lane, from its panel to its next, did.
- **Imports sit as a pane above the code that uses them**, in the same lane and the same step.
  Stepping into depth for imports on their own read as a separate file.
- Give structure a legend and a map: a route map in the heading band (a row per module, the
  current stop lit) and lane names in the overview.

## Look real

- Real screenshot of the real page; official service icons, extruded; labels painted on the
  objects. Name things what the codebase names them (`fast-api-function`, `evaluations-ui`), not
  generic words ("browser", "Lambda · FastAPI").
- Labels: tight padding, permanent if they identify a thing (the gzip filter's name), and never
  a floor slab that exists only to hold a label. Nothing may intersect: blocks ride lanes above
  surfaces.
- Label what a number is: "CPU · 0.29 → 1.00 vCPU", "RAM · 646 / 1769 MB". Don't narrate the
  encoding ("the block's length is its size"). The viewer sees it.

## The code city (built, not chosen)

The repo at the PR's head as a city: a squarified treemap by directory, one building per file
(footprint = lines), changed files lit, callers of the new code amber. Diff panels rise over
their buildings, violet arcs link copied code, amber arcs show calls. It lives in the viz library at `~/.agents/state/viz/pr-1187-city/`: `city.ts`
builds `city.json` from `git ls-tree` + line counts, and `tourCity()` is in that viz's own
`pr-viz.ts`. It was never added to the template.

- **What made it work:** only districts the PR touches (the whole repo was chaos), a legend
  with swatches and words, one viewing angle, low glides of ~1.5 s, and panels rising only after
  the camera settles.
- **Why lanes won for the film:** the city was more immersive but jumpier. Close-ups filled the
  frame with building instead of code, and it said less per second of video. Worth reaching for
  where the repo's shape *is* the point (an onboarding tour, an interactive page someone drives
  themselves) rather than a narrated review.
