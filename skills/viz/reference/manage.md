# Finding and changing vizzes — `manage.ts`

## Finding prior art — `ls` and `search`

Read-only. They never commit, never mutate, and write no index or cache — the
listing is derived from disk on every call. (That's why they don't conflict with
ADR 0005, which rejected a central manifest as *source of truth*, or ADR 0006,
which rejected filesystem scanning as an *authority* mechanism. `discovery.ts`
already builds this exact map to route requests.)

```bash
viz ls                                   # newest first
viz ls --posture=public --listed=listed   # filters AND together
viz ls --central                          # or --local
viz ls --json                             # machine-readable
viz search sankey                         # substring, case-insensitive
```

`search` matches the path, title, description and tags **and the page source**, so
it finds a viz by the *technique* it used rather than only what it was named — the
common case when you're hunting something to reuse.

Each row prints the date, `posture/listed`, the viz's path (which is also its URL),
and its title. The path is what you paste into `--from`.

## Forking one — `bootstrap.ts --from`

```bash
viz create <new-slug> --from <viz-folder>
```

Copies the whole viz dir as the starting point, then re-stamps the copy's identity:

- **`viz:posture` → `local`, `viz:listed` → `unlisted`, always.** A fork never
  inherits `public`. ADR 0006 makes posture the one field that never crosses a
  boundary by inheritance because it's a trust decision; a copy is the same kind of
  boundary. Opt back in deliberately with `manage.ts update`.
- `viz:title` becomes the new slug, `viz:description` is cleared.
- **Not copied:** `comments.json` (review scratch anchored to the original's
  elements), `og.auto.png` (regenerated by `verify.ts --og`), `recordings.json`
  (the source's captured API tape — may hold secrets), `.git`, `node_modules`.
- **Refuses** a mirrored-in dir (`.mirror.json` present) — fork the origin.

`hero.html` *is* copied, so a forked viz keeps a working card to edit down.

# Changing an existing viz

To **move/rename/delete** a viz, flip its **axes**, or edit its **mirror
declarations** — do it with `manage.ts` rather than hand-editing files. It is
author-side only: it never builds and never deploys.

A viz is named by its **folder path**, not a slug (a slug isn't unique across
containers; a path is, and you get shell tab-completion for free — ADR 0008).

Every operation is fail-closed, refuses a mirrored-in dir (edit the origin instead),
and auto-commits with surgical staging. Pass `--no-commit` to opt out.

```bash
# relocate / rename (a rename is just a same-parent move); migrates mirror + vendor config
viz move   <viz-folder> <dest-folder>

# remove the viz folder and its mirror/vendor declarations
viz delete <viz-folder>

# set the axes and the frame metadata — each axis validated against its enum
viz update <viz-folder> [--posture …] [--listed …] [--triaged …]
                                               [--title …] [--description …] [--tags a,b,c]

# edit mirrors.json only — publishing still does the actual pushing
viz mirror <ls|add|update|rm> <viz-folder> [--to …] [--access …] …
```

Three axes exist, and they are independent — setting one never stamps another:

| axis | values | what it controls |
|---|---|---|
| `posture` | `public` · `private` · `local` | access; an undeclared posture makes a build refuse (ADR 0005) |
| `listed` | `listed` · `unlisted` | whether the viz gets a card on the lobby |
| `triaged` | `true` · `false` | audit bookkeeping — "I have consciously reviewed this viz's posture". Never read by a build |

There was a fourth, `kind` (`explanatory`/`operational`). **ADR 0011 deleted it on
2026-08-17** — don't reintroduce it, and note that `--kind` no longer errors cleanly:
it parses as a boolean flag plus a stray positional.

`--title`/`--description`/`--tags` edit the free-text frame metadata in place (an
empty value clears the field), keeping `<title>` in sync with `viz:title`.

## Vendoring — a runnable source copy in another repo

A **mirror** ships a built, sealed artifact. A **vendored copy** ships the viz's
*source*, so it runs from the sink repo alone with no skill installed. Both declare
their edges at the **origin**, in the same `mirrors.json` (ADR 0010).

Pick **mirror** to publish the same viz onto another site under its own framing;
pick **vendor** to hand a repo a copy it owns and can run. Rationale: ADR 0006
(mirrors), ADR 0010 (vendoring).

| | mirror | vendor |
|---|---|---|
| what lands in the sink | a **built, single-file artifact** (sealed if `private`) | a **verbatim source copy**, byte-identical to the origin |
| can the sink run/edit it | no — terminal, `manage.ts` refuses it | yes — it runs standalone with no skill installed |
| refreshed by | `build.ts <origin>` (always) | `build.ts <origin> --push-vendors` (opt-in) |
| `access` means | posture **re-decided** for that sink | posture **acknowledged**; must match the origin's |

```bash
# declare the edge AND write the copy (--access is required)
viz vendor    <viz-folder> --to <sink-viz-pages> --access public|private
viz vendor ls <viz-folder>                      # show declarations
viz vendor rm <viz-folder> --to <sink-viz-pages>  # undeclare

# refresh every declared copy from its origin (see reference/publishing.md)
viz publish  <origin-container> --push-vendors
```

- **`--access` is an acknowledgement, not a re-framing.** A vendored copy is
  byte-identical to its origin, so the only honest value is the origin's own
  `viz:posture` — and it is checked against it. Requiring you to state it means a
  posture that changed since you last looked fails loudly instead of shipping quietly.
- **No `overrides` / `listed` on a vendor entry** (unlike a mirror) — same reason.
- **`vendor-rm` does not delete the copy.** The next `--push-vendors` prunes it,
  origin-scoped, so removal goes through the same path that created it.
- **`vendor-sync`** still pulls a single copy from the sink side; it's the fail-soft
  path when the origin isn't reachable.
- **`vendor-check`** byte-compares each copy against its **live origin** — which is
  what catches the origin moving forward. A pre-commit hook (`vendor-guard`) runs it
  on staged copies.

## Things that will bite you

- **A move changes the viz's id, so the old URL 404s.** There is no redirect, by
  design — these are personal scratch vizzes, not permalinks (ADR 0008). If someone
  is holding a link to it, re-share after the move.
- **`mirror add` requires `--access`** (`public`|`private`). It's the one field that
  never inherits, because access posture across a mirror is a trust boundary
  (ADR 0006). Everything else inherits the viz's own `viz:*` meta.
- **Mirrored-in directories are terminal.** You can't mirror a mirror, and
  `manage.ts` refuses to edit one — go to the origin.
- **`mirrors.json` is machine-local** (auto-gitignored — it maps sibling-repo paths).
  So *declarations* don't survive a fresh clone. The copy's own `.vendored.json`
  receipt is committed and does, which is why the receipt still exists.
- **A move/rename migrates vendor declarations too**, so copies aren't orphaned — but
  the sink's old directory is only renamed on the next `--push-vendors`.

Full design rationale: ADR 0008 (`docs/adr/0008-deterministic-management-operations.md`)
for the operations, ADR 0006 for the mirror semantics, ADR 0010
(`docs/adr/0010-viz-vendoring.md`) for vendoring.
