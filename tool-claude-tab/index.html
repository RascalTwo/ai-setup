The six-step version of one step

Opening a new Claude Code session is the single most common thing I do in a terminal, and herdr had no shorter path to it than prefix+c, type a tab name, Enter, Ctrl-R, c, Enter. Six keystrokes, two of which are a shell history search hoping the right command is still in it, and one of which is naming a tab I am about to let herdr-autolabel rename anyway.

Nothing about that is hard. It is just friction on the most-repeated action in the setup, and friction on a hot path is what a keybinding is for.

One chord, no arguments

prefix+a. A new tab appears, focused, auto-numbered, sitting in the directory the pane you were in was sitting in, with claude --dangerously-skip-permissions already running as its foreground process. There is nothing to type and nothing to confirm.

It shows up in herdr's own help as new tab running claude here, which is the description field of the binding — so it is discoverable rather than being one more chord you have to remember you own.

What it won't do

  • It hard-codes --dangerously-skip-permissions. There is no flag, no env var and no config file — the invocation is the second line of a two-line script. Wanting a different one means editing the script.
  • It never names the tab. No --label is passed on purpose, so herdr auto-numbers it exactly as it would an unnamed prefix+c tab. Naming is herdr-autolabel's job and it does it better, from the transcript.
  • It has no opinion about the directory. The cwd is inherited entirely by herdr, from [terminal] new_cwd. That defaults to "follow", which is why the tab lands where you were — set it to anything else and the tab lands there instead, and claude-tab will not notice.
  • It fails silently. The binding is type = "shell", which runs detached with no pane of its own, so a failed socket call has nowhere to print. The symptom is that nothing happens and you press the key again.

A direct chord works too — key = "ctrl+alt+a" instead of prefix+a. It was not chosen, for two reasons: on macOS, Option is not Alt in Ghostty unless macos-option-as-alt is set; and a bespoke chord is one more undocumented thing to remember. prefix+a shows up in herdr's own help with the description above. The chord is just muscle memory.

Where it lives

Integrates withherdr, and only herdr — prefix+a as a [[keys.command]] binding, and herdr's socket API as the thing the script talks to.
Requiresherdr and jq. Nothing else: no runtime, no wrapper, no daemon.
Its stateNone. It keeps nothing — no directory under ~/.agents/state/, no cache, no config of its own. It is a script that makes two calls and execs itself out of existence, so there is nothing to clean up and nothing that can go stale.
What it installsclaude-tab → ~/.agents/ai-setup/tools/claude-tab/claude-tab, and herdr-keybind.toml merged into ~/.config/herdr/config.toml. Afterwards: herdr server reload-config.
Re-running itSafe. The TOML merge is guarded on the command path, so a second install is a no-op rather than a duplicate binding.

Two calls, nothing else

The whole tool is a two-line /bin/sh script talking to herdr's socket API. There is no supervisor, no config file of its own, no process left behind.

pane=$(herdr tab create --focus | jq -r .result.root_pane.pane_id)
exec herdr pane run "$pane" claude --dangerously-skip-permissions

Call one: create the tab, and let herdr decide everything about it

herdr tab create --focus — with no --label, so herdr auto-numbers the tab exactly as it would an unnamed prefix+c tab. The new tab inherits the focused pane's cwd on its own, because herdr's [terminal] new_cwd defaults to "follow". The response carries the new pane at .result.root_pane.pane_id — which is what jq is there for, and the only reason jq is a dependency at all.

Call two: run it in the foreground, not through a wrapper

herdr pane run makes claude the pane's foreground process, so the tab behaves as if you had typed the command yourself — it types the command into the new tab's shell, so Ctrl-C reaches claude and the command lands in your shell history; when claude exits you are left at that shell prompt. The script execs into that call, so once herdr has it there is no claude-tab process anywhere.

Why herdr still sees an agent

herdr's own agent detection picks claude up from there. The tab reports agent_status: idle once it is ready for input, so the status dots and notification routing work exactly as they do for a hand-started agent — and so herdr-autolabel's Stop hook has a $HERDR_TAB_ID to rename.

No herdr agent start call is needed. That one exists for when you want herdr to validate agent identity before proceeding — which a keybinding does not.

The binding, and the tilde that never resolves

# herdr-keybind.toml — type = "shell" runs detached in the background.
# The script prints nothing and needs no pane of its own; the tab it
# creates IS the visible result.
[[keys.command]]
key = "prefix+a"
type = "shell"
command = "~/.agents/ai-setup/tools/claude-tab/claude-tab"
description = "new tab running claude here"
herdr does not expand ~ in a [[keys.command]] command field. The literal tilde above never resolves — so install.ts bakes in the absolute path at merge time, and what actually lands in ~/.config/herdr/config.toml is a full path. The merge is guarded on that path, which is also what makes re-running the installer a no-op.
