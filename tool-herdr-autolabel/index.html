The problem

A label meant to track a session that wanders can't be written once. Claude Code's terminal title is set from the opening exchange and then frozen, so an hour later it names something you finished forty turns ago. So the input here is the transcript, not the title — the first user message as a topic anchor, plus the last three for recency.

The alternative was the status quo: 6 · 7 · 8 · 9 · 10 down the sidebar, and finding the right session by tabbing through them.

There is nothing to press

It is a Stop hook for Claude Code and Codex, so it fires when a turn ends — every turn, in every herdr tab, with no key and no command. The tab renames itself somewhere in the seconds after the answer lands, and the only thing you ever do to it is the thing that turns it off.

  • To opt a tab out, rename it by hand. Any name that isn't auto-numbered and isn't the slug this set last time makes it back off that tab permanently. There is no flag; the manual rename is the flag.
  • To change the model, set $HERDR_AUTOLABEL_MODEL. Default qwen2.5-coder:7b.
  • Outside herdr it does nothing. No $HERDR_TAB_ID means no tab to rename, and it exits before waking ollama.

What it won't do

  • It never overrides a name you typed. That is the headline feature and also a hard ceiling: once a tab is manually named, this tool is done with it for good, and there is no way to hand it back short of renaming the tab to a bare number.
  • It cannot be right every time. A 7B model reading three messages will sometimes name the tangent instead of the work. It is a label, not a commitment, and the next turn gets another go.
  • It needs a local ollama. Every turn is a model call on your own machine. No ollama on $PATH and the hook is a no-op — which is the intended failure, not a degraded mode.
  • It only ever sees your side of the conversation. The transcript filter keeps type=="user" turns and drops tool results, images and injected system blocks, so work whose subject only ever appears in Claude's replies is invisible to it.

Two constraints worth stating

Label width is the real constraint. The sidebar is kept deliberately narrow, which leaves roughly 10 columns for the label — a 12-char name like backstage-io renders as backstage…. LIMIT is 12 to match the hand-written names it sits beside; the occasional ellipsis is accepted. Widening via sidebar_width (max 36) is available but not wanted here.

The status glyph is herdr's job. Claude's title prefix (✳ idle, ◐◑◒◓ working) is deliberately not carried over — the sidebar already shows status as a colored dot, and those columns are better spent on the name.

Where it lives

Integrates withClaude Code's Stop hook as the trigger, and Codex's too (registered by install.ts as herdr-autolabel codex); herdr for tab list and tab rename, and for the $HERDR_TAB_ID / $HERDR_WORKSPACE_ID the hook inherits from the pane.
Requiresherdr and ollama. (jq as well, in practice — the manifest does not list it, but the transcript read, the label lookup and the message filter all shell out to it.)
Its state~/.agents/state/herdr-autolabel/<tab-id> — one tiny file per tab, containing the last slug this hook set and nothing else. The tab id is run through tr -c 'a-zA-Z0-9' '_' first, so whatever herdr calls a tab can only ever produce a flat filename.
Safe to delete?Yes — deletion-policy: delete. The only cost is amnesia: with no remembered slug, a tab this tool had already renamed now looks manually named, and it backs off that tab. Delete the file and the tab keeps its name forever.
Not its stateThe transcript at transcript_path belongs to Claude Code, and the tab label belongs to herdr. This tool reads one and writes the other; it stores neither.
The modelWhatever ollama has pulled for $HERDR_AUTOLABEL_MODEL, default qwen2.5-coder:7b. That's ollama's disk, not ours.

One turn, from Stop to a renamed tab

Six steps, and the first three are about not doing the work. Arrow keys work, or drive it with the buttons.

← → arrow keys

The flow, per turn

  • Bail early if there's nothing to rename. No $HERDR_TAB_ID (not inside herdr), no herdr, or no ollama → exit before waking any model.
  • Read transcript_path from the hook payload on stdin.
  • Detach. Everything past this point is a model call — and a Stop hook that blocks is one you feel on every single turn.
  • Refuse to touch a human-typed name.
  • Feed the model first + last-three user messages, plus the current slug.
  • Sanitize hard, then herdr tab rename.

Step three is a single line of shell doing the load-bearing work: the whole body from the state directory onward is wrapped in { … } >/dev/null 2>&1 &, and the script's last statement is a bare exit 0. Claude Code gets its zero back in milliseconds and the ollama call finishes in the background, unobserved. That ordering is why the three checks — $HERDR_TAB_ID and two command -v — sit above the detach: there is no point forking a subshell to discover you aren't in herdr.

The two rules that make it livable

Never fight a manual rename. The slug it set is remembered in ~/.agents/state/herdr-autolabel/<tab-id>. Each turn it asks herdr for the tab's current label — herdr tab list --workspace "$HERDR_WORKSPACE_ID", then jq to pick out the one matching $HERDR_TAB_ID — and runs it through one case:

# an auto-numbered label is fair game, and so is one we set ourselves
case "$label" in
  ''|*[!0-9]*) [ "$label" = "$ours" ] || exit 0 ;;
esac

A label of nothing but digits is herdr's own auto-numbering and falls straight through the case untouched. Anything else has to be byte-for-byte the slug in the state file. That makes the rule symmetrical in the useful direction: the tool recognises its own work and nothing else, so a name you typed is a permanent opt-out without needing a flag, a list or an ignore file.

The remembered slug is written only after herdr tab rename returns success (line 80's &&). A rename that failed therefore doesn't leave the state file claiming a name the tab never had — which would make the next turn mistake herdr's real label for a human's.

Hysteresis is the model's job, not a heuristic. The current slug goes into the prompt alongside an instruction to keep it:

# the line that stops the thrash
Current slug: ${ours:-none}
If the conversation is still about the same thing as the current
slug, reply with exactly the current slug.
Otherwise name what the conversation is about NOW — the latest
messages matter most.

Without it, one piece of work gets renamed every single turn — tcc-fix, ghostty-fda, mac-privacy, all the same session. With it, only a real pivot moves the name.

What the model is actually shown

The transcript is JSONL, one record per message, and almost none of it is useful here. One jq filter keeps select(.type=="user") and handles .message.content being either a bare string or an array of blocks, in which case only .type=="text" blocks survive. Two grep -v passes then drop anything starting with <, [Image or Caveat: — tool results, pasted images and Claude Code's own injected notices, all of which are user-role records that you did not type.

What's left is fed in as two slices: head -1 | cut -c1-300 as the topic anchor, and tail -3 | cut -c1-300 for recency. Both ends matter. The first message is what the session is; the last three are what it has become.

Why 7b

qwen2.5-coder:7b, overridable with $HERDR_AUTOLABEL_MODEL. Loaded with --keepalive 2m, so it stays resident through a working burst and unloads when you stop. Chosen by bake-off on real transcripts, not vibes:

ModelSession about CSS bugsAbout an OpenAPI specThis session
qwen2.5:0.5bviz-sai-chan1-2-words-ra ⚠terminal-ses
qwen2.5-coder:7bcss-bug-fixingopenapi-specterminal-tab

0.5b echoed the instructions back as the answer. Don't go below 7b without re-running the bake-off.

The sanitizer assumes the model misbehaved

Small models pad, quote, capitalize, and explain. Output is forced through first-line-only → lowercase → [a-z0-9-] → trim. They also ignore the length limit: ~2 of 3 answers overshot 12 chars, so the cut falls back to the last word boundary rather than shipping css-bug-fixi.
ollama run "$MODEL" --keepalive 2m
  | head -1                     # drop the explanation it added underneath
  | tr '[:upper:]' '[:lower:]'
  | tr -cs 'a-z0-9' '-'         # -c everything else, -s squeeze runs: "Css Bug Fixing." → css-bug-fixing-
  | sed 's/^-*//; s/-*$//'      # → css-bug-fixing

Then the length cut, which is the fussiest line in the script. cut -c 1-12 gives css-bug-fixi; the guard checks whether character 13 was a hyphen, and if it wasn't — meaning the cut landed mid-word — it drops back to the last - with ${slug%-*} and ships css-bug. A tab named after two-thirds of a word is worse than a tab named after one word.

Last gate before the rename: if the surviving slug is empty, or is already exactly the tab's current label, the whole thing exits without calling herdr. A no-op rename would still be a write, and writes are what make a sidebar flicker.
