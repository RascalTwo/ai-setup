↓  WHY IT EXISTS

A calendar event was carrying the whole prompt

The weekly "Upgrade AI setup" job lived as the description of a Sunday calendar event: a paragraph of instructions and a source list, run by Kelpie. It always looked at "the past week", so it could only run weekly, it had no memory of what it had already proposed, and its first real test showed it skipping YouTube and the Copilot changelog while reporting them as read.

Now the event says only kelpie: ai-setup and "Run the upgrade-ai-setup skill." The instructions, the sources and the memory live here.

When it fires

  • On schedule: the recurring calendar event (work account), synced into Timeline Studio as an Agent task that Kelpie picks up.
  • Ad hoc: "upgrade my AI setup", or "what's new that I should adopt".
  • Any cadence: change the event to daily and each run covers only the day since the last one.

What it doesn't do

  • It never changes the setup. Proposals go in the chat; you say yes or no.
  • It doesn't judge existing health. Cruft, drift and dead references are ai-setup-audit's job.
  • It doesn't watch whole long videos. Every video's transcript is read; on-screen reading is limited to the segments that matter, and a skipped segment is reported with its timestamp.
  • It doesn't hide gaps. A source it could only partly read is reported as partial, never as read.

How it's wired in

The skill skills/upgrade-ai-setup/SKILL.md: the steps and the source list, in one file.
Declared kind: skill, state: true, deletion-policy: retain.
Integrates google-calendar: the recurring "Upgrade AI setup" event on the work account, synced to Kelpie.
Requires gh, curl, jq, yt-dlp and ffmpeg.
Its state ~/.agents/state/upgrade-ai-setup/runs.jsonl, one line per run: the window, each source's status and cursor, and every proposal with your decision. Retain it: deleting it resets the window to 7 days and forgets what was already proposed and declined. Test runs write runs.test-*.jsonl beside it.

From the last run to a short list

One run, end to end. The window comes from the last line of runs.jsonl. Each source is read through its dated view: GitHub releases through gh api, blogs through their RSS or Atom feeds, Hacker News through the Algolia API, YouTube through the channel's UULF and UUSH uploads feeds, then yt-dlp captions or transcribe-media, and read-video-locally for what is on screen. Subagents do the reading, so raw pages and transcripts never reach the main context.

Undated sources: a changelog with no dates is never read whole. The skill first looks for a dated view of the same data (a repo's releases, or commits?path=<file>&since=), and otherwise reads only what is newer than the cursor the last run recorded.
