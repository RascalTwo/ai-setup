↓  WHY IT EXISTS

A fresh session inherits the files and none of the argument

Open a new session on the same repo and it can read everything on disk: the code, the plan, the commits. What it cannot read is the conversation. The approach you tried and dropped, and why. The claim the assistant made at two o'clock and retracted at three. How you said you want errors surfaced. The last thing you typed. Those facts live in exactly one place, and it is about to be thrown away.

The skill's own provenance file reports the measurement behind that. On a 173k-token session, a blind exam of conversation-only facts scored the successor at 17% with no handoff, 41% with upstream's /handoff, 62% once the same handoff was given the section list in template.md, and 74% with rescue mode. The biggest single step was not a cleverer summary. It was a better list of questions for the summary to answer.

Two failures sit around that. You walk away from a session and its prompt cache expires with no handoff written; reopening it would rewrite that whole expired cache just to ask it to summarise itself. And work that has fanned out into parallel streams gets crammed into one document, so each fresh agent wades through two other agents' business to find its own.

Four doors into one document

disable-model-invocation: true is in the frontmatter, and agents/openai.yaml sets allow_implicit_invocation: false for Codex. Nothing fires this on its own; you do, or the auto-handoff hook does.

/r2-handoff [what next] The plain one. This session writes its own handoff into the OS temp directory (not the workspace). Words after the command say what the next session is for, and the document is tailored to it. The final reply is the file's path and nothing else.
/r2-handoff split [narrow] The remaining work fans out into parallel fresh sessions. It proposes streams, waits for you to merge, split or approve, writes one shared document and one per stream, and replies with a launch line per stream.
/r2-handoff rescue <tab | pane | session id> For a session you already walked away from. Name it by its herdr tab label, tab or pane id, or session id. Claude Code sessions only.
AUTO HANDOFF <path> Not typed. The tools/auto-handoff Stop hook asks for it at 250k of context (or when an idle session's prompt cache is about to expire), then types /clear and read <path> and continue. The skill asks nothing and writes to the path it was given.

It carries conversation. It can't conjure what nobody said.

  • It earns its keep only on conversation-only facts. When the session's state was fully recorded in git, plans and files, the exam could not tell the arms apart. So the skill refuses to duplicate those: specs, plans, ADRs, issues, commits and diffs are referenced by path or URL, never restated.
  • The evidence is thin, and says so. One session, one run, LLM answerers and grader. The gap between the section list (62%) and rescue mode (74%) is 12 points of that, so treat it as a lean, not a result.
  • Rescue reads Claude Code transcripts only. resolve.py exits rather than guess when the matched agent is anything else. Codex has the plain handoff and split, not rescue.
  • The digest is lossy on purpose. Tool results and thinking are dropped; a fact that lived only in a command's output is recovered by a targeted lookup in the full transcript, or reported as missing. It is never read whole.
  • It never splits on its own. Auto mode may add one line suggesting /r2-handoff split. A split that finds a single stream writes a plain handoff and stops.
  • Auto mode can raise the next session's model and effort, never lower them. A lower choice is ignored; and there is no Opus high on the menu.
  • Secrets get redacted. The first block, kept word for word from upstream, says to strip API keys, passwords and personal information. Whether a given one slipped through is a reading job.

Where it lives, and what it leaves behind

The skill skills/r2-handoff/: SKILL.md, template.md (the section list), PROVENANCE.md, scripts/resolve.py, scripts/digest.py, agents/openai.yaml.
Declared kind: skill, state: false. No deletion-policy, because there is nothing to delete.
Its state None kept. A handoff is a baton, not a record. It is written to the OS temp directory on purpose, and the OS cleans it up. The lineage line is built for that: any breadcrumb whose file is gone is kept in the trail and marked (gone), so the chain stays countable.
Integrates herdr, rescue mode only: resolve.py runs herdr tab list and herdr agent list to turn a tab label into a Claude session. Called from tools/auto-handoff for the auto flow.
Requires python3. Both scripts import only the standard library (json, re, glob, os, subprocess, calendar, time, sys).
Derived from mattpocock/skills' handoff. SKILL.md's first block is upstream word for word; the section list, split, rescue and auto modes are this repo's.

Nine sections and a lineage line, whichever door you used

Every mode writes to the same shape. It opens with one lineage line so a successor can find the session it came from: from session <id> · transcript <path> · cwd · date · continued from · earlier. The earlier list is the breadcrumb trail, oldest first, copied from the handoff you continued from with that handoff's own parent appended. A successor opens only the one it continued from, never the older ones.

Then nine sections, in order, each saying none rather than vanishing, with anything inferred marked (inferred) and anything verified on disk just now marked (checked now). Section 6 is the unusual one: not just what was tried and dropped with the exact symptom, but claims the assistant made that later proved false, so a successor does not trust them. Toggle to see where each section goes when the work splits.

the same ten rows, redistributed

The partition rule is mechanical, and it is the first thing split does: two steps share a stream when they touch the same file or one needs the other's output. Only steps with no shared file and no dependency become separate streams. It then shows you each stream with a recommended model (Opus for ambiguous design or work that can lose data, Sonnet for the rest, Haiku only for mechanical work) and waits. Every stream document opens by naming the shared one as the first read.

Rescue never reopens the session

The session is idle, its cache has expired and nobody wrote a handoff. Seven stages turn a tab name into a document, and only one of them is a model.

The funnel is the whole trick: a transcript of several megabytes goes in, about thirty thousand tokens come out, and no model touched it.

resolve.py: one answer or a list of candidates

python3 scripts/resolve.py <target> prints one session as JSON (session_id, transcript, title, tab, bytes, age_minutes) or exits 1. A target that matches the session-id pattern (line 24) skips herdr entirely. Anything else is matched against herdr tab list and herdr agent list by tab id, pane id, tab-label substring or terminal title. A match whose agent is not claude stops with a message saying rescue reads Claude Code transcripts only. Zero or several matches stop with the candidates printed, tab and session id side by side, so the next move is "ask the user which".

The transcript is found by glob, ~/.claude/projects/*/<id>.jsonl, and age_minutes comes from the last assistant line. The script scans for the literal "type":"assistant" and parses that one line only, rather than parsing every line of a multi-megabyte file.

The digest is deterministic, and it throws away the right things

scripts/digest.py is no LLM. Its docstring says what it is for: an 8.6 MB transcript becomes roughly 30k tokens. Walk one made-up transcript through it, one rule at a time.

The subagent writes it, so this context never holds it

Stage six is one general-purpose subagent with a prompt the skill spells out. It may write one file only and run read-only commands. It reads the digest fully, and uses the full transcript for targeted lookups only: when the digest leaves a fact open (did a command succeed, why was an approach rejected, did the assistant retract something) it greps or jqs for it, and counts the lookups. It follows template.md, checks every path with ls, and replies in under 200 words: the output path, a four-line summary, the lookup count, and where the digest was not enough. The prompt also carries one line you would not think to write, that you dictate by voice, so odd words may be homophones.

The calling session relays the path and summary and reads the document back only if you ask. That is why the handoff costs this conversation almost nothing.

A fork, so upstream's changes can be patched in. The first block of SKILL.md (five instruction paragraphs, about a fifth of the file by size) is mattpocock/skills' handoff, unchanged and in order. The section list, split, auto and rescue modes, scripts and manifest are additions. Keeping the base verbatim means an upstream edit arrives as a diff against a recorded blob rather than a rewrite, and ai-setup-audit's freshness check re-offers it the moment upstream changes.
