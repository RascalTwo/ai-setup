The problem

Token-heavy work — a long refactor, a research sweep, six independent tasks — burns Claude quota and context on exactly the jobs that deserve it least. The work isn't hard, it's just big. And the free lunch won't last forever.

Reach for it when

Say "delegate to codex", "have codex do it", "offload this", "spawn a codex agent", "don't use my Claude tokens for this" — the transcriber's code X, codecs and co-dex all mean the same thing. Then:

  • A task is token-heavy or long-running and quota matters.
  • You want an independent second opinion from a different model on a diff or a design.
  • Several independent tasks can fan out cheaply.

Give it everything up front. Codex is a capable agent but starts cold — it has none of this conversation — so the prompt carries the goal, the definition of done, the exact file paths, and the working dir. And when the context is already a document, pass the path, not the contents: a handoff doc, a spec, an ADR. The artifact stays reviewable before launch, re-runnable after a bad turn, and handable to claude --bg instead without rewriting a word.

Don't reach for it when

  • The user asked Claude to do it. Delegating isn't a loophole around the ask.
  • The job is trivial — the ~5–10s Codex startup is the floor, not a bug, and it costs more than it saves.
  • Codex isn't authenticated.

There is no "ask before acting" in headless mode. Approvals exist only in the interactive TUI; exec under the bypass flag never pauses before a risky action, it just does it. That is the price of an unattended run, and it is why the working dir is scoped with -C. To lock a call down instead, drop the bypass flag and use the graduated sandbox: -s read-only, workspace-write, or danger-full-access.

It also can't be interrupted with a question mid-turn. If Codex needs something it ends the turn and says so in its final message — which is the mechanism that makes the resume loop necessary rather than optional.

The turn

Think of it as the Agent tool, but the compute is on OpenAI's dime. Codex runs as a headless sub-agent, does the real work, and hands back a result to relay. Because it authenticates with your ChatGPT subscription, none of it touches Claude tokens — that's the entire point.

One delegation, from the preflight that proves the economics to the file the answer is read out of.

The loop on the right is the part that isn't obvious. One codex exec is a whole autonomous turn, not one action — and when Codex needs a decision it doesn't hang, it finishes and says so, leaving Claude Code to answer on your behalf and resume the same session.

The receipt

One preflight proves the whole premise — if it doesn't say ChatGPT, the economics don't hold:

# want: "Logged in using ChatGPT" → billed to ChatGPT, not Claude
codex login status
The catch: logged in with an API key instead? Then it spends real OpenAI money. The saving still holds against Claude, but that's a different trade — so it gets flagged, never assumed.

Why each flag is there

  • < /dev/null — the #1 gotcha. Without stdin redirected, codex exec blocks on "Reading additional input from stdin…" and hangs forever.
  • --output-last-message <file> — the clean way to collect the answer. Stdout carries banners, token counts and, with --json, a full event stream.
  • --dangerously-bypass-hook-trust — skips the first-run "trust this hook?" prompt. Without it, a headless run can hang on an untrusted lifecycle hook.
  • --skip-git-repo-check — lets Codex run outside a git repo, harmless inside one. -C <dir> sets the root the task is about.
  • -a / --ask-for-approval is not an exec flag — it's top-level only, because exec is non-interactive by design.

Two cheap variants: -m gpt-5.5 to pin a model, and --oss --local-provider ollama to run against a local model instead — literally zero cost, weaker output, good for bulk.

Getting a typed result back

Pass --output-schema and result.json comes back as exactly that shape — the equivalent of the Agent tool's schema. Pair it with a status field and the resume loop stops being prose-parsing:

{ "status": "done" | "needs_input", "question": "…", "result": "…" }
Strict mode bites immediately. Codex enforces OpenAI strict structured output: every object needs "additionalProperties": false and every property listed in required, or the call dies with a 400 invalid_json_schema before doing any work at all.

Watching a long one

Add --json and tee it to a log: each line is an event, and the command_execution events show exactly which shell commands Codex ran. For long delegations, launch in the background and poll the log rather than blocking — and grab the thread.started event's thread_id if you intend to resume, or skip the id entirely with codex exec resume --last.

On resume, options go before the positional <thread_id> and prompt, and -C is not a resume flag — the working dir is inherited from the original session.
