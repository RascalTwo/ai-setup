The constraint that makes this lane exist

Two sibling skills point the same Terraform provider at Ansible and at a Kubernetes operator. This one exists for a narrower reason: a hardened Windows shop that bans Terraform and Ansible but allows PowerShell. Nothing needs approving, procuring or installing, because the runtime is already sitting on the machine.

Battle-tested on terraform-provider-keycloak v5.8.0 → a 101/101 resource surface of class-based DSC resources, proven live against a local Keycloak.

Two ways to run the same classes

It is explicitly invoked — the manifest carries disable-model-invocation: true, so "port the provider to DSC", "DSC resources for X" or "no MOF / no LCM / no install" starts it and nothing else does. What it builds then runs two ways:

  • Windows, in-box: Invoke-DscResource -Name X -ModuleName M -Method Set -Property @{…} — no MOF compile, no LCM service, no install.
  • Portable, any pwsh 7 (including Linux CI): call the class's Get/Test/Set directly through a tiny factory function — no DSC engine at all. Same classes; the [DscResource()] tag is kept for the Windows path, and on that path you could drop the attributes entirely.

The classic Configuration{} + MOF + Start-DscConfiguration + LCM path still exists, and the skill says to avoid it: it runs as SYSTEM, and it's legacy.

What you permanently give up

DSC has no state file. That isn't a gap to close later — it's the deal. No plan. No prune-on-removal. No automatic dependency graph. The bundled runner reads a declarative .psd1 source-of-truth and loops Test-then-Set in a dependency order you declared yourself. The skill's instruction is to say so on the scorecard rather than let it be discovered.

  • Terraform-only mechanics don't port at all. id, internal_id, *deletion_protection, import, write-only *_wo attributes and regenerate-triggers are excluded from the parity denominator, and each non-port gets documented rather than faked.
  • The field audit only sees flat attributes. It reads block.attributes from the schema dump — a resource's nested block_types (smtp_server, otp_policy, authorization, federated_identity) never enter the denominator, so a 100% field-parity print is 100% of the flat surface.
  • Write-only secrets are never read back, so they stay out of the drift compare by construction. A secret-only change is undetectable, exactly as it is for the provider.

The ceiling is written down too

Resources that genuinely need absent infrastructure — real LDAP, SMTP, an external IdP, enterprise features — are marked blocked, with the captured error attached, and that ceiling goes in PARITY.md in bold. The skill is pointed about this cutting both ways: "blocked — needs infra" is usually wrong, and has to be verified against a live error before it is believed.

The two shipped documents are usually the point: PARITY.md (the precise claim, how it was proven — surface, field audit, behavioral — known deltas, the state/plan/prune losses) and EFFORT.md (timeline, LOC, agent and token counts, honest caveats — an AI swarm is not human effort, porting a mature provider is easy mode, and ownership plus CI is the recurring cost).

Port, don't invent — but read the Go, not just the schema

A mature provider is years of pre-discovered knowledge; the provider is the spec. But terraform providers schema -json gives you the field surface only. It does not encode the REST path, the HTTP verb, how references resolve, or server-side transforms — those live in the Go and only prove out live.

Two traps that cost real time: session/token lifespans are duration strings in the schema but integer seconds in the API (send a string → 400), so those properties are typed [nullable[int]]. Realm roles PUT/DELETE by name, not by /{id}, which is why the base class carries a SelfPath($rep) hook a subclass can override to /roles/{$this.Name}. A field named correctly but typed or pathed wrong passes a name audit and fails live.

The same lesson keeps paying out. Clients and client-scopes are keyed by UUID while users write names, so ResolveClientUuid / ResolveScopeUuid live on the base and accept either — one base fix cleared 13 protocol mappers at once. A discriminator like access_type (CONFIDENTIAL / PUBLIC / BEARER-ONLY) becomes two booleans, publicClient and bearerOnly, mapped in AlwaysBody() and compared through an overridden FieldsMatch(). And freeform maps (attributes, extra_config) come back as a PSCustomObject full of server-computed keys: assigning that to a [hashtable] property throws outright, and comparing a user's partial map against the server's full one flaps forever — so only user-declared keys are managed, merged per key, exactly as the provider does it.

One file, and the engine inside it

The module must stay a single .psm1 — DSC discovery scans it — with the .psd1 manifest listing every class in DscResourcesToExport. Inside, roughly 370 lines of shared layer carry everything the resources don't repeat: a connection base with GetToken() that re-fetches per call and never caches (master-realm admin tokens are short-lived and a long test outlives one), Api(), ApiGetOrNull mapping 404 to $null, and the uuid resolvers. On top of it a resource base implements Get / Test / Set once against a generic collection/{id} engine, with subclasses setting hooks — CollectionPath, LookupKeyJson/LookupKeyValue, FieldMap, ListFields, AlwaysBody, CopyIdentity.

Two PowerShell traps are handled there rather than per resource. @(@{…}) | ConvertTo-Json emits a bare object instead of a one-element array and the POST 400s, so list bodies are piped with -AsArray — the positional form ConvertTo-Json $Body -AsArray double-wraps into [[…]]. And a [DscResource()] class whose Get() returns [object] fails validation at module load, so instances are built with [Activator]::CreateInstance($this.GetType()).

Two gates, both executed — never self-reported

The fan-out is parallel family agents, and the skill is blunt about why the gates can't live in their prompts: one "behavioral fix-wave" reported "88/93 green" and had changed nothing — 85k tokens across 11 agents that no-op'd. A gate that lives in a prompt gets gamed; a gate the orchestrator executes cannot.

  • Field parity — Field-Parity-Audit.ps1 regex-walks the assembled .psm1 for class Keycloak* blocks, pulls each [DscProperty…] … $Name, normalizes by stripping underscores and lowercasing, and compares that set against every schema attribute marked required or optional — skipping id, internal_id, terraform_deletion_protection and import. Deterministic, so it is enforceable: loop until it prints 0 missing. Expect your own hand-built exemplars — the big core resources — to be the guiltiest.
  • Behavioral parity — the live cycle, run by the workflow, in a throwaway realm per family: create → Test true → drift out-of-band → Test false → converge → Test true → Absent → Test true. Only a real green counts.

Agents also never write the shared module: because the .psm1 must stay one file, families write to per-family scratch files and the orchestrator splices them in, then rebuilds the factory map, the manifest and the runner and runs the load-check. Parallel edits to that one file collided in a real build, which is how the rule was learned.
