↓  WHY IT EXISTS

Everything inside is pixels

Horizon Client is a macOS window containing a picture of a remote desktop, so the accessibility tree stops at the wrapper: no buttons to query, no labels to match, no element tree to walk. Every click is a coordinate, and every check is a screenshot.

Worse, input does not arrive the way it leaves. Focus decides whether a keystroke lands at all, typed text can arrive garbled, and the screen keeps changing under you: toast notifications, snap popups, a lock screen. An agent that drives it like a normal app burns its effort on clicks that silently did nothing.

This skill is the operating discipline that makes it efficient: probe before working, keep batches small, paste instead of type, read data through APIs instead of UIs, and load only the notes that apply to this runtime, this guest OS and this task.

Fires on any VDI ask

It is model-invoked: the agent reaches for it on its own whenever the user asks it to work in their VDI, Horizon or Omnissa, a remote or virtual desktop, or a machine reached by hopping from one. Type /omnissa-horizon-vdi to force it.

SKILL.md opens with a Load what applies list. The agent reads exactly one runtime file, the guest-OS file that matches the first screenshot, and a task file only when the task needs it. Everything else stays out of context.

What it will not do

Reading is allowed when the user asks. Acting needs a go-ahead per action. Sending messages, joining meetings, submitting forms, changing tickets, deleting data, re-running jobs, restarting services or transmitting sensitive data each wait for an explicit yes.

Stop and ask at any login, MFA, lock screen or password prompt. Those need the human; the skill never enters credentials.
  • It cannot read the remote UI structurally. Only pixels, and only from a fresh screenshot or zoom.
  • It won't trust a stale coordinate. Every batch re-derives from the latest frame.
  • It leaves no litter. Probes are task-shaped; files open "Just once"; dialogs close with Cancel or Don't Save.
  • It keeps notes generic. No hostnames, projects, people or client details go into the skill or into memory.
  • macOS host only. The client, the runtimes and the clipboard sync are all Mac-side.

Load only the branches that apply

The router is the architecture. A Claude Code run on a Windows guest reading a web app loads claude-code.md, guest-windows.md and web-app-apis.md, and nothing about DeskPad, sky or deployed builds. Adding a Linux guest or a new recipe is one new file and one router line; no existing branch grows.

Paste, never type

On Claude Code, typed text into Horizon arrived as one repeated letter, so every string goes through the clipboard: 

open_application("Omnissa Horizon Client Next")   // write_clipboard refuses while the terminal is in front
write_clipboard("https://…")
wait 1s                                          // Horizon syncs the Mac clipboard into the guest
click field → ctrl+a → ctrl+v                    // the guest's chords
zoom on the field                                // read back; a lagged sync pastes the old text
key Return

The read-back is the part that matters: a paste that landed the previous clipboard looks exactly like success until something else breaks.

Read the API, not the page

When the data lives in a web app, the guest's browser is already signed in, so the app's JSON API is one pasted URL away. It gives exact timestamps where the UI says "2 weeks ago", and text dense enough to zoom-read in strips. web-app-apis.md keeps GitLab's endpoints for commits, diffs, raw files, code search, deployments and pipelines.

Hop carefully

A remote desktop can be a jumping-off point to further machines, each in its own window with a connection bar. The agent names the machine from that title before acting, reports which one it was on, and treats every hop as read-by-default. deployed-builds.md covers the common question on the far side: which build is running, read from the startup log and from the config inside a copied artifact.

When input stops landing

  1. Re-query state with a screenshot.
  2. Click well inside the remote content.
  3. Rerun the probe: a task control, or the guest file's fallback probe.
  4. Then the runtime's own fix: on Codex, restore the window size on DeskPad.

On a Windows guest, the snap-layout popup near a maximize button and toast notifications both swallow clicks. The fix is the same first move: click well inside the content, then retry.
