Sessions were told to show progress, and didn't

app-panel has a progress tool, and every session's instructions say to call it for work over a minute. Even with the tool loaded up front, sessions rarely did. Glancing at a session told you it was busy, never whether you had two minutes or thirty.

session-eta stops asking the model and draws the bar from outside the turn.

Nothing to run

  • Installed as hooks on UserPromptSubmit, PreToolUse, PostToolUse and Stop in Claude Code's settings.
  • A turn past 45 s gets a bar titled Back in… · <your request>, refreshed about once a minute, and marked done when Claude stops.
  • A command that took a minute or more before (say npm test) gets an estimate the moment it starts.
  • Measuring a change: python3 replay.py scores the estimate against real past turns.

What it won't do

  • It is an estimate. Replayed on 15 real turns, the median miss was 1.40× either way. Read "back in ~9m" as "5 to 13".
  • It shows activity, not intent. It reads what Claude did and said, not what it plans next.
  • It steps aside for any turn where Claude calls mcp__app-panel__progress itself, so there are never two bars.
  • herdr only. With no HERDR_PANE_ID or no panel for the pane, it does nothing.
  • It needs Ollama. With the Mac loaded, an estimate can take 30 s; the bar keeps filling toward the last one meanwhile.

Where it lives

Integrates with Claude Code hooks: UserPromptSubmit, PreToolUse .*, PostToolUse .*, Stop. It posts to app-panel's /progress endpoint, the same one app-panel-progress uses.
Requires python3 (standard library only) and ollama with qwen3.5:9b (override with $SESSION_ETA_MODEL). Platforms: macOS, Linux.
Its state ~/.agents/state/session-eta/: sessions/ (one file per session), durations.jsonl (command times), actuals.jsonl (turn lengths, seeded by replay.py seed), estimates.jsonl, errors.jsonl.
Safe to delete? Retained. sessions/ is scratch; deleting actuals.jsonl or durations.jsonl throws away the history the estimate leans on until it rebuilds.

One turn, end to end

  1. Turn starts. UserPromptSubmit resets sessions/<session>.json (a task notification keeps the last real request as the title) and starts a detached watch process.
  2. Recording. Each PreToolUse adds the call to pending, and the matching PostToolUse moves it into events with how long it took. A foreground Bash command of 5 s or more is appended to durations.jsonl under command_key(), so timeout 300 npm test files as npm test. This is about 40 ms with no model.
  3. The watchdog. Hooks fire only between tool calls, so one long subagent would otherwise go unseen. watch() wakes every 5 s and, from 45 s into the turn, runs an estimate at most once a minute. It exits when the turn changes or stops.
  4. Estimating. estimate() gives qwen3.5:9b (JSON mode, think: false) the request, Claude's last three paragraphs, the steps so far, and what's running with its past durations. The model returns stages and minutes left. history_end() takes the median length of past turns in actuals.jsonl that outran this one so far. The time shown is the geometric mean of the two end times, the variant replay.py scored best.
  5. Drawing. The result goes to the pane's app-panel host as stages, stage and eta, and the bar fills toward it until the next estimate.
  6. Turn ends. Stop posts status: done and logs the real length. An estimate that comes back later is dropped. If another Stop hook sends Claude back to work, the next tool call restarts the watchdog.
