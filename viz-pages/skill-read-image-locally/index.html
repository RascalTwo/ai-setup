The cost you don't see

Images are not like text. A native image Read adds roughly 1–2k vision tokens to the context — and unlike a one-off tool result you can forget about, it stays there and accumulates every turn for the rest of the session. Five screenshots into a debugging loop, a meaningful slice of the window is spent on pictures you already extracted two numbers from.

The decision boundary

Image reading is intent-dependent, so the routing is too. The same PNG belongs on either side depending on what you actually want out of it — and the prompt you pass carries that intent. A local model is only ever as good as the extraction instruction you hand it.

  • Structured / known extraction → this skill. HUD and dashboard values, table contents, log or screenshot text, error messages, specific labeled fields, “what does this text say”.
  • Holistic visual judgment → the native Read tool. Layout and aesthetics, “does this look right”, subtle or ambiguous scenes, dense unfamiliar UIs, “why does this look off”. A small local model answers those with a generic caption that silently misses exactly what you were looking for.

Using it

Always pass the specific extraction intent — never a generic “describe this image”. Pass --json when you expect a structured shape and the engine validates the output is real JSON.

# Read HUD values out of a screenshot
python3 vision_judge.py /tmp/frame.png --prompt "Extract the SCORE and LIVES values."

# Force a structured shape
python3 vision_judge.py /tmp/dash.png --json \
  --prompt 'Return {"cpu_pct":int,"mem_pct":int} from this dashboard.'

# on success, a header line then the answer
[read-image-locally OK] model=… <latency>

Models are tried in tier order, cheap and fast first — default gemma4:e4b, then gemma4:12b. It needs Ollama reachable at http://localhost:11434 with those models pulled.

It is an optimization, never a hard dependency. If every local tier fails — Ollama down, model missing, empty or invalid output — the engine prints LOCAL_VISION_FAILED and exits non-zero. That is the signal to read the image natively with the Read tool. Native Claude is simply the last tier of the same ladder, not an error path.

How it's wired in

The skill itself is only the engine. The routing rule — the part that has to reach an agent before it reflexively reaches for a native Read — lives in AGENTS.md, which both Claude Code and Codex read. That is deliberate: it travels by prompting, with no hook to install or keep alive.

# AGENTS.md — Image Reading, Local-Vision-First
- Structured/known extraction → `read-image-locally` skill — HUD/dashboard
  values, tables, log/screenshot text, errors, specific labeled fields. Give it
  a specific instruction, never a generic caption; on `LOCAL_VISION_FAILED`
  read natively.
- Holistic visual judgment → native `Read` — layout/aesthetics, "does this look
  right", ambiguous scenes, dense UIs. A local model's generic caption silently
  misses these.

The engine has its own tests covering both the success and the failure path — run them after touching it, because the failure path is the one that keeps this an optimization rather than a single point of failure.
