A new app starts from choices, not recall

This skill records what Joseph builds with, so a new app starts from his choices instead of from memory. It covers the language, runtime, framework, lint, format, types, test runners, coverage, visual checks and gates, by kind of app: web app, server, CLI, Python.

A standard is not an opinion. Each one is written as a rule, a one-line reason, the repos it comes from, and where it is enforced: a lint rule, a gate in the check command, or "not enforced yet". It earns its place from two or more of his recent repos (newest wins on a split) or from a decision he made with evidence.

How to test well (scope, stand-ins, flakiness, what coverage means) lives in r2-testing-paradigm. This skill says which tools carry it out.

Name the kind, then read

The skill fires when you start a new app, script, service or repo; choose a library, framework or tool; set up tests, lint, types or CI; make a test findable by role; or hear "get this in line with my stack".

  • Name the kind of thing you are building, then read the shared files (shared.md, test-stack.md, and testable-apps.md for anything a person or browser uses) and the one kind page that matches. The card above is that table.
  • A repo often holds several kinds (a web app plus its API plus scripts): read each.
  • "Get this in line with my stack" goes to reference/adopt.md: the output is a gap table Joseph approves before anything changes.

Read the standards as labelled. Candidate means one repo does it: use it if it fits, but it is not a rule. Not decided yet means Joseph parked it: record what the repo does and ask before standardising.

What it doesn't decide, or package yet

  • Four kinds only. Web app, server, CLI and Python have pages. A content site, a published library or a browser extension gets the shared rules only, with no kind page yet. A thing that isn't a listed kind still gets every shared rule.
  • Styling and routing are not decided. Joseph parked both on 2026-11-07. The web-app page records what his repos do; ask before standardising.
  • The custom glue is not packaged yet. The coverage kit, the screenshot approval step and the step helpers need code no package provides. Copy it from the repo named as its source into scripts/ or test-kit/; Joseph will extract each piece into npm and Python packages under the RascalTwo GitHub account once his repos follow this skill. Write as little as the requirement allows, and never drop a requirement because no package does it.
  • It doesn't invent standards. A new one needs two recent repos agreeing, or Joseph's decision, with the evidence (repo, file, date) recorded next to it. When a repo's newer choice contradicts a standard, raise it with Joseph rather than editing either.

How the test stack fits together

Why Istanbul everywhere

Measured against V8 coverage on a 342-test suite, V8 over-credited per-test coverage (functions a test never called counted as run), depended on vitest's undocumented module wrapper, and was slowest. Mixing V8 for browsers with Istanbul for vitest can't merge branches. Joseph accepted the cost: browser tests run an instrumented bundle about 1.8× the size and take about 55% longer, the whole check about 39% longer.

Getting an existing repo in line

The other mechanism is reference/adopt.md. It audits first and changes nothing, shows Joseph a gap table, then adds one approved piece at a time, each proven by a gate that has been seen to fail.

A gate you haven't seen fail isn't a gate. The violation is a data-testid locator, a lint error, a dropped strict flag, an uncovered line or a changed screenshot.

The gap table is ordered, cheapest and most protective first

  1. The check command, hook and CI, so every later piece is gated.
  2. Format, lint, types.
  3. Tests run by the right runner, one result list.
  4. Coverage (Istanbul, merged, floor) and per-test coverage.
  5. The locator rule and Given / When / Then.
  6. Screenshots and approval.
  7. Runtime moves (Bun to Node, puppeteer to Playwright) and framework moves.

Each row has the rule, today's state with evidence, the change, its size (S, M, L) and what Joseph would notice. Large moves become their own tasks rather than rows done in one sitting.
