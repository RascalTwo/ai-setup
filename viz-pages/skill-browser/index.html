No browser tool was best at everything

Three tools could drive a browser for an agent, and none was right for every job. On 2026-11-13 they were measured head to head on your real, signed-in Chrome. OpenCode Browse was the fastest and cheapest, and never took focus. agent-browser attached to your Chrome pulled Chrome to the front about 6 s into a run and hid your tab for 14–17 s. claude-in-chrome was the slowest.

Median seconds, three runs each: TodoMVC (it writes) browse 10.9, agent-browser 18.3, claude-in-chrome 25.5. A GitHub project board (read-only, signed in) browse 47.2, agent-browser 49.3, claude-in-chrome 53.3. All three passed 3/3 on both.

The skill turns that table into a rule: one default, one headless path, one relay-backed fallback, one last resort.

When it fires

  • Whenever a task needs a browser: reading or acting on a web page or signed-in site, testing a web app, filling a form, or taking screenshots, recordings or PDFs of a page.
  • It works under claude -p too. Every path does.
  • Kept artifacts (screenshots, recordings, PDFs) go in ~/.agents/state/browser/<task>/.

What it won't do

  • browse needs the extension connected. browse status must say Extension: connected. If it does not and you cannot reconnect now (reopen Chrome or run browse pair), the skill uses agent-browser through the relay.
  • browse ignores default timeouts. page.setDefaultTimeout and context.setDefaultTimeout do nothing, so every action carries its own { timeout }. In the measured claude -p run, two selectors matched nothing and each waited out Playwright's 30 s; the run took 162 s.
  • Headless agent-browser has no logins. It runs its own Chrome for Testing and does not touch your screen or your tabs.
  • The relay path is not lockless. It needs "upstream":true on curl -s 127.0.0.1:9333/stats first, and you open your own tab with tab new. See the cdp-relay poster for what it cannot do.
  • claude-in-chrome is last. It is for an older skill that names it, a slideshow GIF, or when both other tools failed. "Permission denied for this action on this domain" is final for that site: the skill tells you and uses another path.
  • Logins, 2FA and payments are yours. In browse the script calls handoff() and you finish in the tab.

Where it lives

Integrates with Chrome: the OpenCode Browse extension (the default), and cdp-relay as the fallback.
Requires The cdp-relay tool, the commands browse and agent-browser, and by hand: Chrome, and the OpenCode Browse extension paired with browse pair.
Its state state: true, so ~/.agents/state/browser/ is its folder. The SKILL.md names no file in it; screenshots, recordings and PDFs go in ~/.agents/state/browser/<task>/ per task.
Safe to delete? Yes, deletion-policy: delete. What the skill leaves behind is artifacts you chose to keep.

One page task, end to end

A skill with no code of its own. Its architecture is the order of the choices and the recipe it hands each path.

The default path: browse, seven steps

  1. Check. browse status shows Extension: connected. Disconnected means reopen Chrome or browse pair.
  2. Open a session. browse session new <name>, one per task. Agent tabs open in the background of your Chrome and never take focus.
  3. Run one script. browse execute -s <name> --timeout-ms 60000 '<async Playwright code>' with the whole sequence (fill, click, read, return) in one script. That is where its speed comes from: 2 calls on TodoMVC against 9–10 for the others. snapshot() returns a page outline with refs; return only what you need.
  4. Time every action. locator.click({ timeout: 5000 }), because the defaults are ignored.
  5. Screenshots. files.path("name.png") gives a temp path; write the screenshot there, return the path, then cp it into ~/.agents/state/browser/<task>/. Other paths are refused.
  6. Hand off. Logins, 2FA and payments: handoff() in the script, you finish in the tab and click Continue.
  7. Finish. browse session delete <name>. Done means the session is gone from browse session list.

The other paths

  • Headless: agent-browser --session <name> open <url>, then snapshot -i (refs like @e3), click @e3, fill @e5 "text", get text, screenshot <path>, record start <file.mp4>. Chain commands with && and end with close.
  • Relay: the same commands with --cdp ws://127.0.0.1:9333/devtools/browser/relay. Open your tab with tab new --label <name> <url> and finish with tab close <name>. Attached any other way, agent-browser pulls Chrome to the front; the relay keeps it in the background.
  • claude-in-chrome: its mcp__claude-in-chrome__* tools, loaded in one ToolSearch call. find sees only the accessibility tree, so refs go stale and hidden, off-screen or virtualized elements are missing; use javascript_tool or re-read the page right before acting.
