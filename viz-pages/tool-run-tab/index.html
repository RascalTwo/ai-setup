The prompt asked for the wrong thing

herdr's built-in new_tab on prefix+c asked for a tab name before it made the tab. I never typed one. herdr-autolabel renames tabs from what happens in them, so the name prompt was always an Enter to skip. Then I typed the command I had opened the tab for. The prompt asked for the one thing I didn't have and ignored the one thing I did.

A lot of those commands are one-shots: a build, a test run, an install. For those, the tab outlives the command. Closing it and finding the way back to the tab I was on was manual, because herdr on its own lands you on whichever tab was last.

It is the sibling of claude-tab: claude-tab is prefix+a for the one command I run most, and run-tab is prefix+c for every other one.

prefix+c, or prefix+shift+c

  • prefix+c: a small popup (60% wide, 5 rows) with a run> prompt. Type a command and press Enter. A new tab opens, focused, in the focused pane's cwd, with the command typed into its shell. The tab stays open afterwards.
  • Empty Enter: a plain new tab, the same thing the old new_tab gave you.
  • Ctrl-C: cancels. Nothing is created.
  • prefix+shift+c: the prompt reads [close on exit] run>. Same as above, but the tab closes when the command exits. If you are still on that tab, you land back on the tab you started from.

Both show up in herdr's own help as new tab running a command (empty = plain tab) and new tab running a command, closed when it exits. Those are the description fields of the two bindings.

What it won't do

  • It never names the tab. No --label is passed, so herdr auto-numbers it. Naming is herdr-autolabel's job.
  • It will not pull you back from somewhere else. In close-on-exit mode the jump back happens only if you are still looking at the command's tab when it finishes. If you have moved to another tab during a long command, you stay where you are.
  • Close-on-exit does not care whether the command worked. The appended step is joined with ;, not &&, so a failing command closes its tab too, and the output goes with it. If you need to read the output, use plain prefix+c.
  • The command is typed, not exec'd. It goes through the new tab's shell, so pipes, aliases and && work and the line lands in your shell history. In close mode, the appended ; run-tab --back <origin>; exit lands in history too.
  • It has no opinion about the directory. Like claude-tab, the cwd comes from herdr's [terminal] new_cwd, which defaults to "follow".
  • It takes over prefix+c. The snippet unbinds herdr's new_tab (new_tab = ""). Nothing is lost, because an empty prompt gives the same plain tab.

Where it lives

Integrates withherdr, and only herdr: prefix+c and prefix+shift+c as [[keys.command]] bindings with type = "popup", plus herdr's socket API as the thing the script talks to.
Requiresherdr and jq. The script runs under /bin/zsh, whose vared is the prompt. No daemon, no runtime.
Its stateNone. It keeps nothing: no state directory, no cache, no config of its own. The origin tab id travels inside the command line it types, so there is nothing to clean up and nothing that can go stale.
What it installsrun-tab → ~/.agents/ai-setup/tools/run-tab/run-tab, and herdr-keybind.toml merged into ~/.config/herdr/config.toml by install.ts. Afterwards: herdr server reload-config.
Re-running itSafe. The TOML merge is guarded on run-tab in the config, so a second install adds nothing.

Three calls, then the shell takes over

The whole tool is one zsh script. It reads a line, records where you are, makes a tab, and hands the line to that tab's shell. In close-on-exit mode, the shell calls the same script back when the command finishes.

# the part every prefix+c runs
cmd=''
vared -p "${1:+[close on exit] }run> " cmd || exit
origin=$(focused)
pane=$(herdr tab create --focus | jq -r .result.root_pane.pane_id)
[[ -z $cmd ]] && exit
[[ $1 == --close ]] && cmd="$cmd; ${0:A} --back $origin; exit"
exec herdr pane run "$pane" "$cmd"

Read the line first, and record where you are before moving

The binding is type = "popup", not claude-tab's type = "shell", because the prompt needs a terminal and a popup does not disturb the layout. Inside it, zsh's vared reads the line. Ctrl-C makes vared fail, and || exit leaves before anything is created. focused() is herdr tab list | jq -r 'first(.result.tabs[] | select(.focused)) | .tab_id'. It has to run before the tab is created: --focus moves the focus, and after that the focused tab is the new one.

Create the tab, then check for an empty line

herdr tab create --focus, with no --label, is the same call claude-tab makes. The tab takes the focused pane's cwd through [terminal] new_cwd, and jq pulls the new pane's id out of .result.root_pane.pane_id. The empty-input check comes after the create on purpose: an empty line has already made the plain tab it asked for, so the script just exits.

Type it into the shell, don't exec it

herdr pane run types the command into the new tab's shell and runs it. claude-tab hands it one fixed command. run-tab hands it whatever you typed, as one string, so it is shell syntax. Because the shell is still there when the command finishes, prefix+c tabs stay open and the line is in history. The script execs into this last call, so no run-tab process is left in the popup.

Close-on-exit is the shell calling run-tab back

With --close, the typed line becomes $cmd; ${0:A} --back $origin; exit. ${0:A} is zsh for the script's own absolute path, so the callback does not depend on PATH. $origin is baked in as text, which is why run-tab keeps no state. When the command exits, --back runs inside the new tab, where herdr has set $HERDR_TAB_ID to that tab. It compares that with the focused tab. If they match, you are still watching, so it calls herdr tab focus $origin. If they don't match, it does nothing. Then exit ends the shell, and the tab closes with it.

The binding, and the two things it changes

# herdr-keybind.toml. install.ts expands ~ (herdr does not), and writes
# new_tab = "" into your existing [keys] table to free prefix+c.

[[keys.command]]
key = "prefix+c"
type = "popup"
command = "~/.agents/ai-setup/tools/run-tab/run-tab"
description = "new tab running a command (empty = plain tab)"
width = "60%"
height = 5

[[keys.command]]
key = "prefix+shift+c"
type = "popup"
command = "~/.agents/ai-setup/tools/run-tab/run-tab --close"
description = "new tab running a command, closed when it exits"
width = "60%"
height = 5
herdr does not expand ~ in a command field. As with claude-tab, install.ts replaces ~/ with the absolute home path when it merges the snippet into ~/.config/herdr/config.toml. That merge is guarded on run-tab, which is what makes re-running the installer a no-op.
