The provider is already the spec

A Terraform provider is a machine-readable description of a service's manageable surface: docs/resources/ enumerates every resource, the Go schemas define the fields, and the acceptance tests encode years of API edge-case knowledge. Phase 0 is three gh api calls — the resource list, the release tag you'll pin your parity claim against, the test-suite size. Those three numbers become the denominators for every claim you make later.

Then the question that decides everything: does a typed SDK for the target API exist in your implementation language? If yes, the port is mostly reconcile-wiring. If no, budget a client-wrapper layer first and say so in the ledger — it's the difference between hours and days, and the honest headline of any measurement.

One lever, decided once

The chassis is a single generic reconcile path every resource reuses — and you build it inline yourself; never delegate it. Credentials come from a namespaced Secret via connectionRef, so one operator serves many target instances and creds never land in CRs or git. Specs carry typed fields for the common knobs plus a free-form additionalConfig overlay deep-merged over the representation, so full API reach doesn't require a typed field for everything.

serialize desired (NON_NULL)  # from the CR spec
overlay additionalConfig      # the escape hatch, merged on top
fetch live
  absent  → create, re-fetch for the id
  present → subset-diff (every desired field must match live)
            → merge-update on drift

Delete is finalizer-backed with deletePolicy: delete|orphan; status carries ready, message, resourceId, lastSync, observedGeneration. Then one or two exemplar resources go end-to-end green before any fan-out — the exemplar exists to eat the chassis bugs once. In the reference build both chassis defects surfaced in the first exemplar's e2e run, and nine parallel implementations inherited the fixes for free.

A continuous loop turns small bugs into infinite ones. Fields owned by a different endpoint silently no-op on update — set them on create, then strip them from the drift compare, or you get an eternal 30-second PUT loop. Same for masked secrets: servers echo **********, so a secret left in the compare breaks the drift check. Exclude those keys and re-set them only on real writes.

CRDs are not one-to-one with resources

Providers explode variants into separate resources — N *_protocol_mapper types, M vendor-flavored *_identity_provider wrappers. One CRD with a type field covers a whole family, so expect the CRD count to land at roughly a third to a half of the provider's resource count at full parity. That collapse is exactly why the capability matrix exists: without it "11 CRDs" says nothing about coverage.

Waves are sorted by business value, not alphabet. Same-shape mechanical resources parallelize cheaply; a domain that needs new chassis ground gets its own exemplar-first hour before its wave fans out. One agent per resource, an isolated git worktree each, docs/PATTERN.md as the contract, and compile-only inside the worktree — the integration e2e runs once after merge, by you.

You can't run their tests. You can port every behavior.

The acceptance tests are the highest-value artifact in the provider repo: each *_test.go is a behavioral spec whose fixtures translate roughly 1:1 to CR YAML and whose check functions read as assertion checklists. You cannot execute them — the test engine shells out to the terraform binary — so you port the behaviors instead, into verify/verify.d/NN-<resource>.sh scripts that run against the real API with no mocks anywhere.

Each script is self-contained and builds its own prerequisites through raw API calls, never through other CRDs. Four beats every time: create → update via CR patch → out-of-band drift-heal → delete and assert gone.

Merge is the deploy; git revert is the rollback

When it's asked to be real: a JVM-mode image, CRDs from the build output, a Deployment plus scoped RBAC. For a GitOps story, the CRs live in a git repo watched by Flux or Argo — one namespace per environment×instance with its own connection Secret, prune plus finalizers so a git revert genuinely rolls back.

And the demo the skill says to script, because it's the single most persuasive artifact this produces: edit the resource in the target's own admin UI, then watch the operator put it back within 30 seconds.
