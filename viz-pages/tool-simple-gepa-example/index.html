GEPA is easier to see than to read about

GEPA optimizes a prompt by having a model read the feedback on failed examples and propose a better instruction. Described in a paper it is abstract; inside a real project it is buried under that project's data and metrics.

simple-gepa-example strips it to one script you can run in a minute and watch in Phoenix: before, the optimizer's reflections, after.

Run it

  • Start Phoenix: docker compose up -d --wait in tools/simple-gepa-example (UI on localhost:6006).
  • Run: uv run simple_gepa_example.py. It prints accuracy before and after, a per-example difficulty table and the optimized instructions.
  • Knobs at the top of the script: LM_KIND (ollama or bedrock), JUDGE_KIND (llm or rules), TOTAL_EXAMPLES.

What it won't do

  • It is a toy. The task is positive/negative/neutral sentiment on built-in sentences; there is no train/test split.
  • It is not installed. install.ts does not wire it anywhere; you run it by hand.
  • Bedrock needs your own AWS credentials; the default is a local qwen3:8b on Ollama.
  • Pinned to dspy==3.0.3. Newer DSPy may move the GEPA imports.

Where it lives

Integrates with DSPy's dspy.GEPA, Ollama on localhost:11434 (or Amazon Bedrock), and a Phoenix container from docker-compose.yaml receiving OpenTelemetry traces.
Requires uv, docker and ollama; Python 3.12+, dependencies locked in uv.lock.
Its state None of its own. simple-gepa-example writes nothing to disk; traces live in the Phoenix container.
Safe to delete? Nothing to delete; docker compose down removes Phoenix.

One run, end to end

  1. Trace. phoenix.otel.register(auto_instrument=True, endpoint="http://localhost:6006/v1/traces") instruments DSPy and LiteLLM.
  2. Baseline. create_simple_examples() shuffles the built-in labelled sentences and takes TOTAL_EXAMPLES; test_program() runs dspy.Predict(SimpleClassifier), a signature with no instructions, over them.
  3. Feedback. The metric returns a score plus generate_feedback(): "Wrong! Your output should have been…" followed by an LLM's explanation, or one built from fixed sentiment word lists when JUDGE_KIND = 'rules'.
  4. Optimize. dspy.GEPA(metric=metric, auto='light', reflection_lm=lm).compile(program, trainset=examples): the reflection model reads the feedback on failures and proposes new instructions, keeping the best.
  5. Compare. test_program() runs the optimized program, prints the accuracy change, the difficulty table and optimized_program.signature.instructions.
