Every turn pays rent on the whole pile

A Claude Code session at 250k tokens sends all 250k with every request. Mostly that goes through the prompt cache at the cheap read rate, which is what makes long sessions bearable, and it is also why they get slowly more expensive: each turn re-reads everything that came before it, including the forty files you read two hours ago and have not needed since.

Then you go to lunch. The cache lives an hour. Come back after it and the entire context is rewritten, not read, at the write price. In the pricing table this tool's replay script uses, that is 40 cache reads' worth on Opus and 20 on Sonnet, paid in one request for a session that had mostly stopped being useful.

The two usual exits both cost something. Let the harness compact and you get a summary of the session. Or notice it yourself, run /r2-handoff by hand, /clear, paste the path in — which works exactly as long as you are watching. This tool is the second exit with you taken out of the loop: same handoff document, same fresh start, nobody has to remember.

It is not magic, and the page below does not pretend it is. The measured saving is about 15% of main-chain cost, from a replay of real sessions rather than a promise, and the weakest input to that number is named under the limits.

Nothing to press, one thing to turn off

It is a Stop hook plus a line in the statusline, so it watches every turn of every Claude Code session inside herdr and acts when one crosses a line. What you see is the context meter drop. If something is holding it back, you get a message telling you what.

auto-handoff off This herdr pane only. Run it with a leading ! from inside Claude so the shell, not the model, runs it. on undoes it.
auto-handoff off --all Everywhere. on --all undoes it.
auto-handoff status Global and per-pane state, plus a phase if a handoff is in flight.
AUTO_HANDOFF=0 claude This launch only. Also off or false.
AUTO_HANDOFF_TOKENS The trigger. Default 250000.
AUTO_HANDOFF_IDLE_TOKENS The idle gate, 150000. The statusline reads it too.
AUTO_HANDOFF_STATE Where state lives. Point a test session somewhere else so the global off switch does not apply to it.

Two ways it fires. At the end of a turn at or past 250k it hands off and sends the continue prompt for you. If you have walked away from a 150k+ session and 55 minutes have passed with no reply, it hands off then, while the cache is still warm, and types the continue prompt without sending it, prefixed with a note naming what the session was. You come back to a cleared screen that says what happened.

What it will wait forever rather than do

  • It will not hand off while anything runs. A subagent, a workflow, or a shell. A dev server or a watcher that never ends blocks auto handoff until you stop it. Over the threshold, every stop shows you a systemMessage naming what it is waiting on. Shells are on the list although /clear would keep them (tested 2026-10-03), because a shell a subagent left behind is still unfinished work.
  • It will not type over you. If the prompt box has anything in it, the injector polls every two seconds, for up to 30 minutes, then gives up without clearing anything.
  • It only works inside herdr. Only herdr can type into a live session. Outside it every verb is a no-op.
  • It trusts an undocumented field. The task list it gates on, background_tasks, is in real Stop payloads but not in the hooks docs. A payload without it counts as busy, so a Claude Code change makes this tool stop, not kill an agent.
  • The next model is a short menu. The handoff may ask for exactly three pairs (haiku high, sonnet high, opus medium) and may only raise the model and effort the session already had. There is no Opus high, and no way to downshift.
  • The key input is the weakest one. The 250k figure leans on an assumed 30k of files re-read in each new session. The README's own next step is to measure it after a week of real handoffs and rerun.
Subagents and workflows do not survive /clear. That is why it waits for them rather than listing them in the doc. Background Bash, monitors and scheduled tasks do survive, so the handoff is told to list each one with its ID, purpose and output path.

Where it lives

Integrates with Claude Code twice: as a Stop hook (auto-handoff stop, timeout 10, registered in settings/claude-code/settings.json) and from the statusline, where statusline-context.sh calls auto-handoff idle every refresh once context passes the idle gate. herdr is the other half: it types /clear, the model switch and the continue prompt into the pane. The handoff itself is written by the r2-handoff skill's Auto section.
Requires herdr and python3. The script is one file of standard library.
Its state ~/.agents/state/auto-handoff/, one small file per herdr pane: <pane>.json holds the phase of a handoff in flight, an empty <pane>.json.off is that pane's off switch, an empty off is the global one, and log.jsonl gets a line for every Stop that gets as far as counting tokens.
Safe to delete? Yes, deletion-policy: delete. Nothing here is a record worth keeping. Know what you are deleting, though: the off switches too. A pane you had switched off will start handing off again, and a handoff mid-flight is forgotten.
Not its state The handoff documents go to the OS temp directory as handoff-auto-<pane>-<epoch>.md, so they are cleaned up by the OS and are not under state. The transcript belongs to Claude Code, which this reads and never writes.

The Stop hook is a two-visit state machine

stop() (line 97) is called twice per handoff and tells the visits apart by one field in <pane>.json. On the first visit there is no file and the hook decides. On the second the phase is writing and it only has to check that the document arrived. A third phase, injecting, is the injector's claim on the pane: any stop that sees it returns immediately, so a Stop firing during the injection cannot start a second one. 

{"phase": "writing",
 "path":  "…/handoff-auto-<pane>-<epoch>.md",
 "t":     1791095291.7,    ← the doc's mtime must be ≥ this
 "enter": true}           ← false on the idle path: typed, not sent

The "must be newer than t" test on line 122 is what stops a leftover file at the same path from passing for a fresh one. And if the phase is writing but the file never showed up (interrupted, or the model declined), line 129 wipes the state and starts over, unless stop_hook_active says this stop is itself the product of a block, in which case it just stops, rather than block-looping.

Busy is checked before the doc, and again after

running(hook) (line 70) reads background_tasks from the Stop payload and keeps the entries whose status is running. It is consulted at line 108, before either visit does anything, so a busy session never gets as far as asking for a doc. The case it has to survive is subtler: a task still running after the doc was written.

A doc that predates a task's result would lose that result. The result lands in the old context, which is about to be cleared, so line 114 deletes the half-made doc, wipes the phase, and waits. When the task finishes its notification starts a turn, that turn's Stop re-runs the check, and the handoff is asked for afresh, with the result in context.

An absent background_tasks key returns a single made-up entry, so busy is truthy. The default for "I cannot tell" is to do nothing.

It never types into a draft

The injector is launched with start_new_session=True (line 126), which makes it its own process group, so it outlives the hook that spawned it. It first runs herdr agent wait --until idle --until done (line 199), because the Stop that launched it is still returning, then sleeps one second. Then draft_empty() (line 155) reads the visible screen through herdr agent read --source visible, finds the last line starting with ❯, and accepts it only if the box is bare or is the dimmed Try "…" placeholder of a fresh session. The prompt glyph is followed by a no-break space in that placeholder, which is why line 157 normalises \xa0 first. 900 checks, two seconds apart, and the for … else: return on lines 203–208 means a timeout leaves your session untouched.

What the handoff asks for, and what the injector reads back

The block reason (instruction(), line 87) tells Claude to read the r2-handoff skill and follow its Auto section, write to the exact path given, and end the turn. That section adds two lines after the lineage line in the document, and the injector reads both back, one with a regex and one (on the idle path only) with a prefix test: 

Topic: refactoring the retry layer; remaining: the two failing integration tests
Next session: model sonnet, effort high
^ next_session() (line 189) matches ^Next session: model (\w+), effort (\w+)
  and accepts only a pair in CHOICES: haiku/high, sonnet/high, opus/medium

/model and /effort are typed after /clear (lines 212–217), when the cache is already gone, so a switch costs nothing. The value is passed through upgrade() (line 182), which returns it only if it ranks above the session's current one. The current one was read before the handoff by current() (line 168) from the last main-chain reply, and an unknown one is treated as the top of the scale, so the switch is skipped rather than risk a downgrade.

The idle path asks, and the same Stop hook decides

idle() (line 139) is called with the statusline's payload every 30 seconds while the session is above 150k. It needs the quiet gap to fall in [55 min, 60 min), because after an hour the cache is already gone and there is nothing left to save. It also needs herdr agent get to report idle or done, and no file for the pane already. Then it saves the phase with enter: false and sends the instruction itself via herdr agent prompt.

Notice what idle does not do: check for background tasks. The statusline payload has no task list. It does not need one. The instruction starts a turn, that turn ends in a Stop, and that Stop goes through the busy check on line 108 like any other. The one place the check lives is the one place that can see the data.

Why 250k

sweep.py replays every main-chain request since 2026-09-22 (237 sessions) as if the session had handed off at each threshold from 100k to 700k, charging a handoff its real costs: the doc-writing turn at full context, then a new session whose 41k measured baseline, the doc and the files it re-reads are written to the 1h cache. Each bar is the band within 1% of the best threshold; the dot is the best.

Run on 2026-10-03 at the central assumptions: 30k re-read, cache reads at 0.35× on the subscription meter. The last column is the saving at 250k.

The row to look at is the third. Sonnet and Haiku prices pull the best threshold down to 210k, since a Sonnet cache rebuild costs 20 reads against Opus's 40, and 250k only costs Sonnet 0.3 points. One number stays within 1% of the best everywhere, so there is one knob. The assumptions matter more than the model: moving the re-read from 0 to 30k to 60k moves the Opus optimum from 180k to 250k to 270k.
