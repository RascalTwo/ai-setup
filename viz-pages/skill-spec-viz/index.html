Sign-off proved you were willing, not that we agreed

A Kelpie refine run used to hand you a text description and some questions. You read it, it sounded right, you signed it off, and an agent built it. The misreads showed up at review, after the build, when they were expensive. Clicking sign-off only ever proved you were willing to.

spec-viz makes the agreement something you can look at. One page per task: a hero you can glance at and think “oh, that’s the feature”, then concrete examples and non-examples you judge ✓ or ✗. A wrong concrete case is caught at a glance; an abstract sentence gets nodded through.

You judge, you say why, you sign off

  • A refine run builds it and opens it for you. Or say “spec this” on any task.
  • Click ✓ or ✗ on each example and assumption. A ✗ means: say what’s wrong in the 🎙 💬 pill, press Send corrections, and the agent revises the page.
  • Sign off unlocks only when every one is ✓. It then records your judgments on the task, sets Refined in Timeline Studio, and the build starts on the next tick.
  • #{"mode":"film"} on the URL plays a one-minute narrated version in the page.

What it doesn’t do, yet

  • It proves you judged what the agent wrote, not that the agent understood. A good spec depends on the agent writing good cases.
  • One size for every task. A lighter spec for a tiny task is parked.
  • This Mac only. Reading and signing from a phone is next.
  • The film is played in the page, one voice (Kokoro), never rendered to an mp4.
  • Re-opening a spec on a task that is already building has no button: sign-off is refine-only, so you confirm in the build agent’s pane.
  • Not tested end to end on a live task when this was written.

Where it lives

Skill skills/spec-viz/ (a viz template, scripts/build.ts, the instructions). It integrates with kelpie (the button runs its signoff; the spec’s folder is the task’s run folder), pr-viz (reads spec.json; see pr-viz/reference/spec.md) and grill-me-viz (a pointer to it). It requires the viz skill and bun. It keeps no state of its own: each spec is a viz in the viz library, with a copy of the signed spec.json in the task’s run folder, so deleting one only loses that spec.

One sign-off, end to end

The agent writes one spec.json, checked by spec.schema.ts on both sides. entry.ts picks the spec page (spec.ts) or the film (film.ts) from the URL’s hash. Each click logs a judge line through the viz feedback widget, so a reload restores them. Sign-off is the page’s one action:

The backend refuses unless it is a real POST with every verdict “ok” (a viz verify load can’t act), and the spec is saved only after Kelpie accepts. Kelpie’s signoff writes the quoted judgments as a [dispatch] signoff comment, then sets refinedAt; the refine run ends and the tick starts the build, whose briefing reads the signed spec.json. Later, pr-viz seeds its acceptance criteria from the ✓ examples word for word.

The film comes from the same words: script.ts turns the spec into scenes, scripts/build.ts writes narration.json from them, and viz verify compiles the voice clips and times each beat to them.
