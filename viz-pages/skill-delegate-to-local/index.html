↓  WHY IT EXISTS

Both other meters were nearly full

Near the weekly Claude limit, handing work to delegate-to-codex still costs something: it moves the bill to ChatGPT quota. Some tasks are small enough that neither meter should move at all, and a model already sitting on this Mac can do them.

delegate-to-local runs one Claude Code turn on qwen3.6:35b-a3b (a mixture-of-experts model with about 3B parameters active, 23 GB on disk) through Ollama's Anthropic-compatible endpoint. It works like delegate-to-codex, but the compute is this machine.

Reach for it when

Say "delegate to local", "use Qwen" (the transcriber may hear "Quinn"), "run it locally", or ask to save quota with a local model. Then:

  • The task is small and well specified, with a test or an exact check: implement a function against tests, fix a named bug, make a one-file edit.
  • The prompt carries everything. The model starts cold: the goal, an exact definition of done (the test command that must pass), exact file paths relative to the working dir, and the files it must not touch. 
# run as a background Bash call; a task takes 1-7 min, the first call adds ~30 s to load the model
~/.claude/skills/delegate-to-local/scripts/delegate-local.py -C <working-dir> "<task prompt>"

# options: --minutes N (default 30) · --model M · --resume <session_id>

When it finishes it prints one line (done, error, or timed out after N min, plus the run folder and session id). Read result.md in the run folder, not stdout. Prefer a git repo with a clean tree as the working dir, so the change is a reviewable diff.

What it will not do

  • Hard or ambiguous work. The model is much weaker than the orchestrating Claude. Design, ambiguity, judgement and broad repo reading stay with Claude.
  • Fire on usage level alone. It is never triggered automatically because a quota is running low; the user asks for it.
  • More than one run at a time. There is no fan-out. On a 36 GB Mac a second large model does not fit, so the launcher refuses a second run and refuses to start while another model of 2 GB or more is loaded.
  • Download anything. A missing model is a refusal that names the size and the ollama pull command. The user pulls 23 GB, the skill never does.
  • Ask a question mid-turn. It never blocks for input. If it needs something it ends the turn with the question in result.md, and the orchestrating Claude resumes the session with an answer.
  • Be asked before it acts. It runs with --dangerously-skip-permissions in the working dir, like Codex's bypass mode.
"Done" is a claim, not a result. Before reporting the task finished, the orchestrating Claude reads the diff (looking for edits outside the task, deleted or weakened tests, stubs) and runs the tests or the check itself.

Where it lives

The skill skills/delegate-to-local/SKILL.md and one launcher, scripts/delegate-local.py. The SKILL.md tells the orchestrating Claude how to run it, how to write the prompt and how to check the work.
Declared kind: skill, state: true, integrates: claude-code → headless local-model subagent, requires.commands: [ollama, claude].
Its state ~/.agents/state/delegate-to-local. It holds run.lock (a pid file), claudehome/ (the isolated Claude Code config dir) and runs/<timestamp>/, one folder per run. Safe to delete: claudehome is recreated on the next run and the run folders are only logs. Deleting claudehome only costs the ability to --resume earlier sessions.

One run, from refusal check to result.md

delegate-local.py is a thin launcher around claude -p. It does three jobs: prove it is safe to start, start Claude Code in a cage pointed at Ollama, and write down what came back.

Everything left of the command is about keeping the cage shut: the user's own setup never reaches the model, and nothing about the run depends on which Claude session launched it.

The pre-flight is four questions and a note

Each check is a plain HTTP call to Ollama or a file read, and a refusal exits 2 with a message that says what to do. The skill relays the message and acts on it only with the user's go-ahead. Swap usage (sysctl vm.swapusage) and memory_pressure -Q are printed to stderr as a note and never block a run: most of the swap is in use on an ordinary day. If the lock names a dead pid it is ignored, and the launcher removes it when the run ends (in a finally).

Why the launch looks the way it does

  • Config dir plus --safe-mode plus --strict-mcp-config. None of the user's hooks, MCP servers, skills, plugins or CLAUDE.md load. The parent's CLAUDE* and ANTHROPIC* variables (session id, messaging socket, subagent model, auth) are stripped before the new ones are set.
  • Every model alias maps to the local model. If Claude Code reaches for an Opus, Sonnet or Haiku alias for a subagent or a background call, it still lands on Ollama.
  • The session id is chosen first. With --session-id <uuid> set before the child starts, a timed-out run still has an id that --resume accepts.
  • stdin is /dev/null and the child gets its own process group, so the timeout can kill the whole tree.

Why Claude Code is the harness

It was benchmarked, not assumed. On four agentic tasks with this model, Claude Code passed 4 of 4 (about 13.5 minutes in total), Qwen Code passed 3 of 4 (a stream error on the hardest one), and Codex with --oss passed 0 of 4, because the model never saw its tools.
