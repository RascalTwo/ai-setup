Two half-senses, one timeline

A frame-by-frame native read of a video burns thousands of vision tokens. The local route costs ~0 — but no single local model does the whole job: Qwen3-VL (via mlx-vlm) sees and can't hear, Whisper hears and can't see. Feed Qwen3-VL the transcript as timestamped text and the two halves line up: "spoken X at 0:42" against "frame at 0:42 shows Y". A vision-only model then behaves like an audio+video one, locally, with no Omni model needed.

The hearing half isn't reimplemented here — transcription is delegated to the transcribe-media skill (MLX Whisper, GPU-accelerated), falling back to the openai-whisper CLI if that sibling script isn't present. One speech-to-text engine, shared. Word-level timestamps are the point: they're what anchors deictic words like "here" and "this" to a moment.

The narration is the query list

In narrated mode you don't author questions — the speaker already did. Every comment in the voice-over becomes a claim verified against the video at its own timestamp. In silent mode (an agent's own screen capture, no audio) Whisper is skipped and your --question drives it, which upgrades self-verification from a flipbook of stills to motion over time: did it animate, or teleport? — a question one screenshot cannot answer.

# narrated clip — the transcript drives verification, no question needed
python3 read_video.py demo.mp4

# silent clip, the agent-self-verify path
python3 read_video.py /tmp/capture.mp4 \
  --question "Does the red ingredient slide onto the plate, or jump there instantly?"

# run the heavy model once, query the text many times
python3 read_video.py demo.mp4 --timeline > /tmp/demo.timeline.txt

Always pass a specific intent. Like read-image-locally, a video model is only as good as the prompt; never expect anything useful from a vague request. And subjective calls — "is the easing juicy, is it fun" — stay a human's, in both modes.

Boundaries, measured

  • Use it for "how many in-between states were there" — position over time, presence, a scalar that ramps. For easing-feel, continuity or bounce, the still grid hides it: use the video path, or a human.
  • The model smears a hard edge by ~2–3 tiles, reading an instant jump as a short ramp. Separating a true snap from a sub-0.2s tween is therefore marginal — raise --tiles and judge on rise-width, not on "any intermediate value".
  • For a pure colour or brightness trajectory, a direct pixel read (PIL over the frames) beats any model. Reach for the model when the per-frame question is semantic — where, what, whether — not a number you could just measure.
  • Montage needs Pillow for the sheet build.
  • English only in practice: the transcribe step is invoked with --language en hard-coded.
ollama's qwen3-vl:8b is image-only. Its runner does no temporal video encoding — don't route video through ollama. mlx-vlm is the video path. (ollama stays fine for single images and read-image-locally.)

It is allowed to fail

On any hard failure — mlx/Qwen3-VL load error, empty output, both samplers exhausted — the engine prints RVL_FAILED … and exits non-zero (2 for a missing file, 3 for no usable output). That's a designed exit, not a dead end: extract frames with ffmpeg and read them natively. The Whisper step is separately best-effort — if it throws, the run catches it, warns on stderr and simply continues in silent mode.

ffmpeg -i video.mp4 -vf fps=2 /tmp/frames/f%03d.png   # then Read the frames

The same trick makes a clip in the first place, with no new dependency: drive a sequence through the app's screenshot hook, then ffmpeg -framerate 10 -pattern_type glob the burst into an mp4 and question it. That works even where OS screen recording is blocked for the app — a Godot window driven by computer-use, for instance.

Where it lives

The engineskills/read-video-locally/read_video.py — one command, routing internally. tests/run-tests.sh builds a narrated and a silent clip with ffmpeg + macOS say and checks silence detection, word timestamps, prompt construction for all three modes, and the RVL_FAILED path.
Requiresffmpeg/ffprobe for audio extraction, silence detection and frame sampling; mlx-vlm (Apple Silicon, verified on Python 3.14) for Qwen3-VL; Pillow for contact sheets. The model auto-downloads on first run.
Integratescrv (claude-real-video, MIT, pipx install claude-real-video) for frame selection, and mlx-vlm as the local video model. It also calls a sibling skill: ../transcribe-media/transcribe.sh, resolved relative to read_video.py's own realpath.
Its stateYes — ~/.agents/state/read-video-locally/, and only that. Inside it, cache/crv/<key>/ holds one crv output directory per video, where <key> is the first 16 hex of sha1(realpath:mtime:size). That is a pure recomputation cache: a second question about the same video skips re-extraction, and the key changes the moment the file does.
Safe to deleteYes — deletion-policy: delete. Remove ~/.agents/state/read-video-locally/ whole, at any time. Nothing there is an original; the next run re-extracts frames and costs you the extraction time, once.
Not its state~/.crv/memory.db is crv's own corpus, not this skill's. Any bare crv run writes it and crv-ask searches it. This skill does not own it, does not relocate it, and by default does not write to it: run_crv() sets CRV_NO_MEMORY=1 unless you pass --remember, because this engine gets pointed at client recordings and should not quietly start an index. With --remember it contributes to that corpus, in place. Redirecting it under ~/.agents/state/ would split the user's index in two and leave crv-ask searching the half this skill never wrote.

The mode is measured, not declared

has_speech() asks two questions of ffmpeg. First ffprobe -select_streams a -show_entries stream=codec_type: no audio stream at all means silent, immediately. Then ffmpeg -af volumedetect -f null -, whose stderr carries a mean_volume: -NN dB line that gets regexed out and compared against SILENCE_DB = -50.0. A muted-but-present track therefore reads as silent, which is the common case for a screen capture recorded with an input device attached.

The transcript is not a transcript, it is a prompt

transcribe() shells out to ../transcribe-media/transcribe.sh --format json --language en and flattens segments[].words[] into {start, end, word}. build_prompt() then emits the narration twice: once as plain running text, once word-by-word as [m:ss.t]word. The duplication is deliberate — the plain form is readable, the stamped form is what lets the model ground "look at this" to a frame. The instruction that follows turns every spoken comment into a claim to confirm or contradict, with a timestamp.

Silent mode gets a different prompt entirely, and the difference is the whole reliability story below: the question is appended with "first walk through the timestamped frames in order and note the position/state of the relevant subject in EACH frame. Only after that per-frame pass, answer." With neither speech nor --question nor --timeline, it refuses rather than guessing: RVL_FAILED: silent video and no --question given.

The router, and the retry that is really the router

pick_sampler() is three lines: no crv on PATH → uniform; otherwise crv when duration(video) >= CRV_MIN_SECONDS (20.0), uniform below. Short clips stay uniform on purpose — crv's job is deleting near-duplicate frames, and a smooth tween is a run of near-duplicates, so dedup would eat the very frames that answer "did it slide or teleport?". The honest routing axis is the question, not the clip; sniffing the question is brittle, so duration stands in for it.

Which makes the retry the real safety net. order is built as [first, the_other], and the two samplers fail on opposite content — so whichever way the proxy guessed wrong, its counterpart is exactly the one that recovers it. --frames crv|uniform or --frames-dir pins a single entry and disables the retry.

clip ≥ 20s, crv present  → crv        scene-selected + deduped
clip < 20s               → uniform    # a correctness call, not a speed one
crv missing or failing   → uniform + a warning naming the downgrade
answer degenerates       → the other one, automatically

What crv is actually invoked as

run_crv() runs crv <video> -o <cache> --no-transcribe --overwrite with CRV_NO_MEMORY=1 in the environment. --no-transcribe because crv ships its own Whisper and this skill already has the GPU one — running both would transcribe twice. The output directory carries a frames.json, and crv_frames() reads it, resolves each frames/<file>, and raises if any listed file is missing rather than silently reading a short clip. Over --max-frames (48) it strides with round(i * last / (cap - 1)) — spanning the full range, so the first and last frames always survive, because a plain len/cap step drops the tail and the tail of a clip is usually the payoff.

Contact sheets, not loose stills

crv_grids() tiles the selected frames into numbered sheets, and tile #n is the #n of the timestamp map, so the model can cite real times. This is load-bearing, not cosmetic: measured on a 44-frame phone-UI capture, 24 raw stills made Qwen3-VL degenerate into one repeated caption for 14 consecutive frames, while the identical frames as sheets read every screen correctly. The prompt prefix then says three things the model would otherwise get wrong — consecutive tiles are time passing in one recording rather than separate pictures; never repeat a description for consecutive tiles without re-reading each; and the tiles are not evenly spaced in time, so derive any duration only by subtracting the printed timestamps, never from tile adjacency.

Both paths land in _generate(), which runs python -m mlx_vlm.generate --model … --max-tokens 1200 --temperature 0 --repetition-penalty 1.05 with either --video … --fps 4 or --image <sheets>, then splits the CLI's echo at <|im_start|>assistant and strips the trailing generation-stats block, so the caller gets the answer and nothing else.

The detector that decides whether to retry

looks_degenerate() is what closes the loop. It strips index, timestamp and markdown scaffolding from every line with re.sub(r"[\d:().,\[\]#*_>-]+", " ", line), keeps bodies longer than 25 characters, and walks consecutive pairs looking for a run of four near-identical ones, where "near" is difflib.SequenceMatcher(...).ratio() >= 0.93.

Two measured degenerations, and why equality wasn't enough. The first was the same sentence for 14 consecutive frames — an exact repeat. The second was "similar to the previous one but a different layout" four times running, with only the ordinal changing. An exact-match check sails straight past the second, and stripping the scaffolding is what makes the first comparable at all: a per-line timestamp differs every line, so leaving any of it in makes identical captions compare as distinct.

Montage mode, when the video path averages the answer away

The video path samples frames as a temporal sequence and merges adjacent pairs, so a brief event — a fast tween, a six-frame transition — buried in a mostly-static clip gets averaged into a gist. The model reports a flat "it's a green plate" and misses the change entirely. --montage reframes the temporal question as a spatial one: build_montage() auto-trims the settled tail by frame-diff (mad(), mean absolute difference) so the transition fills the grid instead of getting two tiles while ten are wasted on a static end, paste_grid() numbers them into one PNG written beside the video as <stem>.montage.png, and it is read in image mode.

# the model returns a per-tile 0–10 trajectory, never a verdict
snap  → 0,0,0,0,0,3,6,9,10,10,10,10
tween → 0,0,0,3,5,6,7,8,9,10,10,10
# the prompt never says "snap" or "gradual" — so the model can't be led.
# the CALLER computes the verdict from rise-width.

The lever is prompt framing, not model size

Narrated verification is strong and stable — the transcript anchors the model. Motion was the hard part, and the fix wasn't a bigger model. A plain "does it slide or teleport?" made both the 4-bit and the 8-bit model lazily call a smooth slide a teleport. Enumeration framing — walk the frames one by one, note each position, judge afterwards — fixes it, and is now baked into the silent-question branch of build_prompt().

The 8-bit default earns its place in combination with that framing, not on its own: asked to enumerate, 4-bit sometimes degenerated into repeated junk (x=10, x=10, …) while 8-bit enumerates cleanly every time. Qwen3-VL-8B-Instruct-8bit is ~10 GB; bf16 isn't worth it, since 8-bit is near-lossless and faster on Apple Silicon where inference is bandwidth-bound.
