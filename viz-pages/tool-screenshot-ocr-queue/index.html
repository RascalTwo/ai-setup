Text trapped in pictures, one at a time

Pulling text out of a run of screenshots (a long chat, a settings page, slides) meant OCRing each image separately, or pasting them one by one into a cloud model and paying vision tokens for each.

screenshot-ocr-queue turns it into a capture session: you only take screenshots, and the OCR happens behind you on the local model.

Start it, capture, press Enter

  • Run python3 ~/.agents/ai-setup/tools/screenshot-ocr-queue/screenshot-ocr-queue.py. Whatever is on the clipboard already is ignored.
  • Capture with Cmd+Ctrl+Shift+4; each one prints 📸 captured #n, then ✅ #n done with an ETA for the rest.
  • Press Enter, or pass --count N to finish after N captures. A sound and a notification say the text is ready.
  • Options: --prompt changes the OCR instruction; --models sets the Ollama fallback order.

What it won't do

  • It is not exact. The output starts with a warning line because local OCR makes transcription errors.
  • Only images count. Copying text while it runs is ignored, not queued.
  • macOS only. AppKit for the clipboard, pbcopy, afplay and osascript for the hand-back.
  • The first image is slow when MLX is used: the ~10 GB model loads once per run.

Where it lives

Integrates with The macOS pasteboard, an MLX Qwen3-VL model, and the read-image-locally skill's vision_judge.py as the Ollama fallback.
Requires python3 (Pillow, pyobjc; mlx-vlm optional), ollama, and the read-image-locally skill. Platform: macOS.
Its state ~/.agents/state/screenshot-ocr-queue/output.txt: the last run's text, overwritten every run. Captures go to temp files.
Safe to delete? Yes, deletion-policy: delete: it only holds the last run, which is also on the clipboard.

One capture session, end to end

  1. Watch. watch_clipboard() polls NSPasteboard.changeCount() every 0.3 s. A change with a PNG or TIFF on it is saved to a temp PNG and put on work with its capture index.
  2. OCR. process_queue() takes each item and calls ocr(): ocr_mlx() runs mlx-community/Qwen3-VL-8B-Instruct-8bit, loaded once and kept resident; on any error ocr_vision_judge() runs ~/.claude/skills/read-image-locally/vision_judge.py --prompt … --models … and drops its [read-image-locally OK] header line.
  3. ETA. Seconds per megapixel over finished images, times the megapixels still queued.
  4. Finish. Enter (or --count) sets stop; the watcher exits, the worker empties the queue, and main() joins it.
  5. Hand back. Results are joined in capture order with ---, prefixed with the accuracy warning, piped to pbcopy, written to ~/.agents/state/screenshot-ocr-queue/output.txt, and announced with afplay and an osascript notification.
