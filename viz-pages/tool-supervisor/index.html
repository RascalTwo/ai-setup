The built-in guard caught one shape of the leak

Claude Code was putting the account's email address into User-Agent headers (anthropics/claude-code#107757). The built-in cc-plugin-privacy mod (2.1.317) refuses a shell call that holds the logged-in address and names a User-Agent. That's one address, one tool, one shape.

A past session here got straight past it. A subagent wrote a script whose User-Agent named a different personal address, then ran the script by name against Wikimedia. No shell text held the address, so nothing matched. With Kelpie running sessions under --dangerously-skip-permissions, there's no permission prompt left to catch it either.

veil guards what comes in (tool outputs). The supervisor guards what goes out (tool calls): well-meaning mistakes, prompt injection, and actions nobody approved.

Nothing to run: it's already watching

  • Every call, every session. The supervisor is a PreToolUse hook on .*, so it sees subagents and Kelpie runs too. A deny holds in bypass mode, and Kelpie's own --settings hooks add to the user hooks rather than replacing them (both tested on 2.1.319).
  • A refusal reaches Claude as the deny reason: which rule, why, and "don't retry it in another form; if the user asked for exactly this, tell them". You can still run the command yourself.
  • Your addresses are collected fresh on every call from the google skill's accounts.json, ~/.gitconfig, the Claude login, and ~/.config/supervisor/emails.txt for any others.
  • After changing a rule, run python3 tools/supervisor/supervisor.test.py (44 cases, under a second) and python3 tools/supervisor/replay.py [days], which runs the rules over your real transcripts and lists what they'd have refused.

Only calls that are wrong whoever asked

  • No intent calls. pkill, git branch -D, cloud deletes and npm publish are only wrong if you didn't ask. Over 30 days every one of their 391 hits was intended work, so the supervisor leaves them alone. They need a local judge that reads your prompt, which is the follow-up task supervisor-local-judge.
  • A script run by name is opaque. The command rules read the text the shell runs. A heredoc written to a file or a string inside Python is data. The address rule is the one exception: an address beside a User-Agent is refused anywhere, including a file being written, which is what catches the Wikimedia leak.
  • Fails open. A crash or a timeout lets the call through. One unchecked call is better than every call in every session stopped.
  • Claude Code only. Codex has no supervisor yet (task supervisor-codex).
  • Replay, 2026-11-08: about 102,600 calls over 30 days, 12 refused: the Wikimedia leak, one fake token in test code, and the rest the deliberate probes and write-ups from the session that built it.

Where it lives

Integrates with Claude Code hooks: a PreToolUse hook on .* in settings/claude-code/settings.json (timeout 10 s) running python3 -I tools/supervisor/supervisor.py, and a statusline widget, tools/statusline/statusline-supervisor.sh, which shows a yellow 🛡⚠ while the supervisor has crashed in the last hour.
Requires python3. Nothing else: no model, no network, no packages.
Its state ~/.agents/state/supervisor/: log (one line per refusal), errors.log (crashes, read by the statusline), and replay-hits.jsonl from the last replay.
Safe to delete? Keep it, deletion-policy: retain: the refusal log is the only record of what the supervisor stopped. Nothing breaks without it; the folder is recreated on the next refusal or crash.

One tool call, end to end

Claude Code fires PreToolUse before a tool runs and starts supervisor.py with the call as JSON on stdin. main() collects your addresses with my_emails() and hands the tool name and input to check(). If check() names a rule, main() prints a permissionDecision: "deny" and the tool never runs; if not, it prints nothing and the call goes ahead.

  1. Skip prose. Skill, Agent, SendMessage and TodoWrite carry words to a model, never run, so check() returns at once.
  2. Address anywhere. The whole input, raw and once percent-decoded, is searched for one of your addresses within 160 characters after a User-Agent, curl -A or wget -U. This runs for every tool, so a Write of a script is refused before the script exists.
  3. What leaves. outbound() returns the part of the call that reaches the network, or nothing: a Bash command only if it matches NET (curl, ssh, git push, requests, fetch and so on) and isn't all-localhost; a WebFetch URL; browser input except find queries and summaries; any MCP tool except the local ones. as_run() first drops heredoc bodies no interpreter reads.
  4. Own service or not. Hosts in IDENTITY_HOSTS (Google, GitHub, Atlassian, AWS, Microsoft, Slack, Anthropic and the rest) hold your accounts, so your address may go there. Anywhere else, my-email refuses. Each token shape in TOKENS is bound to its issuer: a GitHub token to github.com, an sk-ant- key to anthropic.com; any other host gets secret-out, as does uploading ~/.ssh, .env or a .pem.
  5. Shell rules. On shell_only() text (no heredocs, no quoted strings): remote-code for curl … | sh; destroy for rm -r of home, a top-level home folder or a system folder, or mkfs, diskutil erase, dd of=/dev/; history for a force-push to main, master or trunk.
  6. Answer. A hit appends the rule, tool, session and mode to ~/.agents/state/supervisor/log and prints the deny. An exception anywhere appends to errors.log and prints nothing, so the call runs.

The two lessons from tuning live in the code on purpose: an address or token going to its own service is normal (Atlassian basic auth, gws, the Timeline Studio token), and data is not a command. The first draft refused 900 calls over 30 days; tuning around these two cut it to 12.
