The draft is the deliverable

Most automation's definition of done is "it's live." Here it's the opposite: the end state is a page with unpublished changes on it. Confluence autosaves as the edits land, so nothing is lost — the human opens the tab, reads what changed, and publishes. The skill says to tell them that when handing back.

Drafts are per user and survive tab closure, so closing the tab doesn't discard the work. Until someone publishes or discards, everyone else on that page sees an "unpublished changes" marker.

The API shows you a page that isn't there

Fetching the page through the Atlassian API returns the published version. If the page has unpublished changes — yours from five minutes ago, or the user's from last week — you read stale content and edit against a version that no longer exists. So the current text comes from the editor tab, never from the API.

When the two disagree, the editor is right and the difference is a draft. Reloading the edit-v2 URL pulls the current server-side draft, which is the whole fix for a stale tab.

Delete with a Range, not with the keyboard

Coordinate- and keyboard-based selection failed twice before this recipe existed. It's precise, needs no coordinates, and cannot overshoot:

const root = document.querySelector('.ProseMirror');
const el = /* the <p> or <li> you want to clear */;
el.scrollIntoView({ block: 'center' });
root.focus();
const r = document.createRange();  r.selectNodeContents(el);
const s = window.getSelection();   s.removeAllRanges();  s.addRange(r);
document.execCommand('delete');    // deprecated. works. 11-for-11.

And the standing rule when there's no way around a visual selection: screenshot the highlighted range before pressing Delete.

Typing is markdown — until it isn't

The editor autoformats as you type: ## , * , 1. , _italic_, backticks, fences, and a bare URL followed by a space. The traps are all about what happens after a construct starts.

  • Inside a list, Enter continues the list. Prefix later items with * and you get literal asterisks — type the marker once, then separate items with newlines in a single type.
  • Tab / shift+Tab nest and outdent — that's how you get a. / b. under a numbered step. Two Enters exit a list.
  • cmd+alt+0 puts the block back to body text — needed after deleting a heading, or the replacement text inherits the heading style.

A pasted Confluence URL becomes a link that displays the raw URL. To show the page title, click it, hit URL on the floating toolbar, and choose Inline — Card and Embed are the other two, and neither looks like an ordinary in-page link.

Images land at the caret

The editor has a hidden file input; uploading to it inserts the media wherever the caret is. So "replace this placeholder with a screenshot" is exactly two moves: clear the placeholder with the Range recipe above — which leaves the caret in the now-empty node — then upload. Allow ~5 seconds per image; the media node renders asynchronously.

With several placeholders, work bottom-up so earlier positions don't shift, and re-query the DOM each pass instead of caching a list of nodes. Returning the remaining count from the JS turns the tool output into a visible countdown. Images themselves come from the browser-capture skill — plus its sanitized-screenshots reference if the page shows real identifiers.

Verify structurally, not visually

List markers render in ways that make a correct document look broken — an image inside list item b. can paint with the b. marker alone on its own line, which reads as a leftover empty bullet. Check the DOM before "fixing" it, or you'll delete something that was fine. The sweep worth running before handing back: count remaining placeholders, and list the inserted images in document order to confirm nothing was missed or transposed.

The other way to lose an image: Escape and stray clicks can node-select a media node rather than placing a caret, and a Backspace there deletes the picture. Blue border plus a caption prompt means node-selected — press ArrowRight to collapse. Also: clicking the editor's empty margin does not focus it, and a stale Table of Contents is expected — macros regenerate on publish.

When it's the wrong skill

This one is for a page a human owns and will review: one section, one paragraph, one image, through the real UI, left unpublished. If the page is generated from a local markdown file that is the source of truth, that's publish-markdown-to-confluence instead — whole body, ADF over the API, published immediately.
