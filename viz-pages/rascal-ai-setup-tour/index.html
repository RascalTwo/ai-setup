    How it gets installed

    Two kinds of thing, and a poster each

    There are 51 owned things here and they divide cleanly in two. The split is not filing — it decides what a thing is allowed to do, where it can keep anything, and what its page has to explain.

    43 skills · 8 tools

    Skills — instructions for the model

    skills/<name>/SKILL.md. Loaded into the agent's context when its description matches what you asked for.

    The agent does the work A skill is prose plus, sometimes, scripts it tells the agent to run. Nothing happens unless a model reads it and acts. steelman is pure method; viz ships a whole CLI. Both are skills, because both are things the model is told.

    Tools — programs that run around the agent

    tools/<name>/, each with its own README and herdr keybinding.

    No model involved A tool plugs into a fixed extension point — a hook, a keybinding, a status line widget — and runs whether or not anything is thinking. The image spool fires on every tool call; the tab renamer fires on Stop. The agent never decides to invoke them.
    The test Would it still happen with no model in the loop? Yes → tool. No → skill.

    Both get a poster

    And the poster is not freeform. Five beats, in a fixed order.

    The poster standard ↗ Why it exists · using it · what it doesn't do · where it lives · how it actually works. The last one is the point: mechanism used to be scattered across asides, so nobody could trace an input end to end.
    Checked, not hoped for bun scripts/check-posters.ts fails on a missing poster, a missing or out-of-order beat, a how beat with no diagram, or a where beat that disagrees with the frontmatter.

    Talking to it

    Most of what reaches these agents is spoken, not typed. That is upstream of everything else here — it is why the rules file opens with homophone guardrails, and why an interrupt key was worth building.

    two halves: in and out

    Voice in

    Local speech-to-text, so nothing leaves the machine to become a prompt.

    My fork of handy.computer Adds a third shortcut that types each word into the focused app as the model commits it, rather than pasting the whole transcription on release. What that changes is that you can see it going wrong while you are still talking. That repo explains itself — it is not this repo's job.
    Why the rules open with homophones Dictation produces plausible wrong words, not obvious garbage — "mark as red" for "mark as read". So §1 of AGENTS.md is: assume homophones may be wrong, and say which reading you took.

    Voice out

    The agent speaks back, which creates a problem typing never had: it is mid-sentence and wrong, and interrupting means losing the turn.

    voicemode-hold ↗ A pane that highlights each word as it is actually played, and prefix+j to hold an utterance mid-word so you can say something into the gap and let it carry on. prefix+m ends the turn; this does not.
    Interjections carry a run-up The last 18 words actually spoken travel back with whatever you said. Without that, "no, that's wrong" has no referent — the agent generated the text but never heard it.

    What it costs

    Worth stating plainly rather than selling it.

    You cannot un-say the sentence The agent's speech is already-generated text by the time you hear it, so interrupting changes what comes after, never the rest of the current utterance. Accepted, not solved.
    Ambiguity is the tax Speech is faster to produce and lossier to consume. The whole evidence-and-confirmation posture in the rules file is paying that tax down.

    What the installer can't do

    bun install.ts gets you the rules, the skills, the tools, the statusline and the subagents. Four capabilities it cannot touch, because they are OAuth flows and per-app toggles behind somebody else's UI.

    click-through, not config

    Behind a connector UI

    Enabled in claude.ai or ChatGPT settings. Nothing local to edit.

    Browser control Claude-in-Chrome extension · Codex's chrome / browser plugins.
    Google · Atlassian claude.ai connectors · ChatGPT connectors. Same accounts, two click-throughs.

    The one that bites

    Desktop control on Claude Code is not a connector toggle, and the part people miss is the last word.

    computer-use, per project Run /mcp in an interactive session, enable computer-use, then grant macOS Accessibility and Screen Recording when prompted. The enable is remembered per project, so it is repeated in every repo where you want GUI control. Needs macOS, a Pro/Max plan, and an interactive session — not -p.

    Pull once, shared by both

    Agent-agnostic: the same daemon and the same store serve Claude Code and Codex.

    Ollama gemma4:e4b and qwen2.5-coder:7b, behind the local-vision and graph skills.
    basic-memory An MCP server over uvx; the installer registers it with both agents and they share one note store.
    Optional: herdr, chafa Without them the keybindings and panes are simply absent, the SessionStart hook exits 0, and ttyimgspool keeps its inline thumbnails (in a kitty-graphics terminal) but loses the prefix+i gallery and the Ctrl+click full-pane view.

    What AGENTS.md does

    Rascal's rules file is less a style guide and more an operating contract: protect voice-driven input, force evidence before claims, route work through the right tools, and make every deliverable prove itself before "done."

    agent behavior control room

    Inputs get cleaned up

    Before the agent acts, the rules reduce ambiguity and force the right evidence source.

    Voice-safe commands Assume homophones may be wrong, confirm weird commands, and prefer the interpretation that fits current context.
    Evidence ladder Use basic-memory first, then domain tools, then web/docs, and only then model recall for consequential claims.
    Memory-first context Search persistent notes at session start and before setup/debugging work, so prior decisions are not rediscovered badly.

    Work gets routed

    The middle of the contract decides whether to plan, delegate, invoke skills, use MCP tools, or inspect a UI.

    Plan plus verification Every change has a proportional Given/When/Then check; failures either get fixed or escalated if the scope changed.
    Skills and MCP first Before ad-hoc scripts against services, check owning skills and loaded tools so repeatable workflows stay encoded.
    Tool hierarchy CLI first, browser automation for browser work, desktop control for non-browser UI, then fallback only when needed.
    Delegation threshold Delegate broad independent research or long output, but keep targeted facts inline when they directly feed the next edit.
    Four mechanisms, named literally Route by who holds the plan. A side task nobody will re-read is a subagent. A fixed plan over many similar items is a dynamic workflow, where a script holds the loop. An evolving plan whose workers must challenge each other is an agent team. A session you opened yourself is cross-session messaging. A workflow takes no mid-run input; a team does — that is the whole difference. Work needing a ruling partway through is a team, or several small workflows with the gate between them.
    Where the parity actually breaks Claude Code has all four mechanisms. Codex has subagents only, defined in ~/.codex/agents/*.toml — so on that side everything else routes back to a subagent or stays inline. This is the one place the two-runtime story is not symmetric. Three shape rules hold either way: only fan out genuinely independent items, partition by file, and never assume taste fans out — a convention with no test behind it needs a review pass over the finished diff.

    Outputs get safer

    The last layer constrains risky behavior and makes repeated shortcuts intentional.

    Local vision first Structured screenshot extraction goes to local Ollama models before expensive native vision reads.
    Hard-won gotchas find in the agent shell is a wrapper that reports an error and still exits 0 — use /usr/bin/find. Don't pipe long-running commands through head. Check gh auth before believing a repo is missing.
    Ponytail default For coding work, prefer the laziest correct solution: reuse local patterns, native features, and the smallest diff that works.
    Impact: fewer confident wrong turns Voice ambiguity, memory search, evidence tiers, and skill-first routing all attack the same failure mode: an agent acting fast from stale or guessed context.
    Impact: faster repeat work The rules bias the agent toward installed capability, local CLIs, repo conventions, and prebuilt skills instead of re-solving common tasks in one-off shell.
    Impact: safer autonomy Falsifiable checks, rival hypotheses before testing, a human gate on anything hard to reverse, and explicit escalation when scope changes — the agent keeps moving without silently widening blast radius.

    How the districts connect

    The important bit is not the count. It is that recurring work becomes named, installed capability.

    Rules choose AGENTS.md tells the agent to check skills before ad-hoc work.
    Installer links Owned skills become live in both Claude Code and Codex paths.
    Manifest imports External packs are reproducible without copying their source.
    Overlays extend Private/company skills layer on top without entering the public repo.

    One pointer, and an empty ~/.claude

    This repo is public, so its settings.json cannot name anybody's home directory layout. Everything installed resolves through a single symlink instead — which is also why ~/.claude ends up containing nothing we chose to put there.

    24 symlinks → 6

    The one machine-local fact

    Where the repo is cloned is recorded in exactly one place.

    ~/.agents/ai-setup → the repo Everything installed is addressed as $HOME/.agents/ai-setup/<tool>/…. $HOME expands in the hook's shell, so a public settings file names a real path without publishing anyone's directory layout.
    Beside overlays.json That file solved the same problem first — a list of local absolute paths that must not go in the repo. The pointer is its sibling, not a new idea.

    Why a symlink, not an env var

    The closer call, and the one that got argued properly before being decided.

    launchd reads no shell profile Hooks inherit the environment of whatever launched the agent. A nightly claude -p under launchd would find the variable unset — exactly where nobody is watching. Settings env: values are literal too: no ~, no $HOME expansion, so the path could only be hardcoded into the public file.
    Broken is visible A dangling symlink is red in ls and the installer self-heals it. An unset variable is visible to nobody until something quietly stops running.

    What is left in ~/.claude

    Four entries, and every one is there because Claude Code looks it up by name.

    CLAUDE.md · settings.json · agents/ · skills/ Each a single symlink, including the two that are whole directories. No bin/, no hooks/ of ours, no loose scripts — those were invented, and ~/.claude/bin was never even on PATH.
    Two files get merged, not linked Everything else is a symlink into the repo — edit a live file and you have edited the repo, and git status shows the drift. No build step, no copy-back. The exceptions are Codex and herdr, which rewrite their own config.toml: a symlink there gets replaced by a real file on the next write and silently detaches, so the installer merges guarded blocks in instead.

    How a tool or skill declares itself

    Forty-six things live in this repo and every one of them answers the same five questions in its own frontmatter. The point is not paperwork — it is that "where does this keep its data" stops being something you rediscover with grep at the moment you need it.

    46 manifests · 13 state owners

    The block

    In README.md for a tool, SKILL.md for a skill, under one namespaced key so it never collides as those formats grow.

    rascaltwo-ai-setup: kind tool or skill · state does it keep anything · deletion-policy retain or delete · integrates what it plugs into · requires what a fresh machine must install.
    Borrowed, not invented retain and delete are CloudFormation's DeletionPolicy values, meaning exactly what they mean there: what happens to the data when the thing goes away.
    requires has a bar What a fresh machine must install or authenticate before it works at all. Not git, not python3, and not a dependency with a working fallback. A list that includes everything is a list nobody reads.

    State has one address

    state is a boolean, never a path — the path is a convention, and writing it down twice is how it drifts out of step with reality.

    ~/.agents/state/<name>/ One directory per thing that owns state, named for the thing. Thirteen owners, from a 1.2 GB image spool down to 60 KB of statusline counters.
    state-owner, for sharing r2-gauntlet reads and writes r2-sdlc's pipeline tree on purpose, so it names the owner instead of claiming a directory or pretending it is stateless.
    Checkable, not aspirational Every directory under state/ has an owner, and every owner has a directory. Both directions hold, which is the only reason the convention is worth anything.

    Whose directory is it

    The rule that took two mistakes in one day to learn. The test is not "does this thing touch it".

    We invented it → we place it The image spool, the karaoke pane's transcript, the pipeline runs, the viz library. Nothing of ours sits in ~/.claude — that belongs to Claude Code.
    It already has one → leave it ~/.voicemode, ~/.crv/memory.db, ~/.okta/okta.yaml, ollama's models, herdr's config. We read them and write to them. We do not move them.
    Mixed directories are the trap ~/.ping/ held their config and our spec cache; only the second moved. Relocating another tool's data fails silently — the owner keeps reading its own default and finds an empty store.
