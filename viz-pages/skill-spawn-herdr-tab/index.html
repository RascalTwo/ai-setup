↓  WHY IT EXISTS

A handoff document is only half a handoff

The document gets written, to a temp path, and then someone has to use it: open a tab, cd to the right folder, type claude with the right model and effort, and get the first prompt through the shell's quoting without it being eaten. A prompt with a double quote, a newline and a $ in it is not a thing you want to escape by hand. When /r2-handoff split fans the work into three parallel streams, you do it three times.

The tools the agent already has do not fit. A subagent lives inside this session, answers to it, and is gone when it is. A background agent (claude --bg) has no terminal; you cannot watch it or type to it. What a handoff wants is neither: a top-level session, in a tab you can see, that owns its own context from the first message. spawn-herdr-tab is that, in one command.

Once it exists it is a session you opened yourself, so you, or the session that spawned it, can reach it by id. It is a peer, not a worker.

Say it, or let another skill say it

It fires on spawn a herdr tab, new tab, or open a new Claude/Codex for X, and it is meant to be called by other skills: the example the skill itself gives is launching handoff docs. Three steps, with the first one being the only judgement call.

  1. Gather the launch. Agent (claude by default, or codex), model and effort only if you gave them, the first prompt, a short kebab-case label and a working directory (this session's by default). It asks once for what is missing and would change the outcome, then says the full launch in one line before running anything.
  2. Spawn. Write the prompt to a file, then run the script. It prints the new tab and pane ids.
  3. Verify. After about five seconds read the pane and confirm the agent's UI is showing the prompt, not a shell error. Report each tab as label → pane_id (agent, model, effort). 
bash spawn.sh --label <label> [--cwd <dir>] [--agent claude|codex]
              [--model <m>] [--effort <e>] [--prompt-file <file>] [--focus]

Several tabs, such as one per stream from a split, are the same two steps repeated. Spawning does not wait on any of them.

What it does not ask, check, or wait for

  • Claude tabs start with permission prompts off. spawn.sh line 17 hard-codes --dangerously-skip-permissions, and nothing in the skill lets you turn it off. The spawned session will not stop to ask before acting. Codex gets no equivalent flag. Spawn into folders and with prompts you would run unattended.
  • It does not know the agent started. It creates a tab and types a line into it, then prints ids. Whether claude exists, took the flags, or hit an error is what the five-second verify read is for.
  • A folder-trust prompt is yours to answer. A directory Claude has not seen before stops at a trust question. The skill tells you which tab is waiting; it will not press anything. Prefer a folder already trusted.
  • It picks no model and no effort. Leave them out and the agent's own defaults apply. The skill's rule is to pass only what you said.
  • Only two agents, and the prompt is a file. --agent is claude or codex, anything else exits 2. There is no inline prompt flag; a prompt always travels as a file.
  • It does not take your screen. The tab opens unfocused (--no-focus is the default), so a batch of spawns does not yank you around. --focus opts in.
  • The label is trusted. It is printed back inside JSON without escaping, so keep it kebab-case as the skill asks.

Where it lives

Integrates with herdr, which it asks to create the tab (herdr tab create) and then to type the launch command into the new pane (herdr pane run). The agent it starts is whichever of Claude Code or Codex you asked for. Other skills, handoff ones especially, are its callers.
Requires The manifest declares no requires at all, only the herdr integration. In practice that is herdr, bash and jq (it reads the tab and pane ids out of herdr's JSON with it), and claude or codex on the new tab's $PATH.
Its state None. state: false. It writes no file of its own. The prompt file belongs to the caller, and the tab belongs to herdr, which holds it until you close it.
Safe to delete? Nothing of its to clean up, so there is no deletion policy. The spawned tab and the session in it are herdr's to close; nothing here tidies them.
In the folder SKILL.md, the 27-line spawn.sh, and agents/openai.yaml, which gives the skill its Codex display name and sets allow_implicit_invocation: true.

The prompt never goes through a quote

The one design decision in spawn.sh: the first prompt crosses five hops, and in three of them it is only a path.

Solid purple is the text itself. Faint purple is a path to it. The shell that expands the path is the new tab's own, not the caller's.

What the six steps do, by line

  1. Parse (lines 5–14). Defaults are agent=claude, cwd=$PWD, focus=--no-focus. An unknown flag exits 2 (line 11), and so does a missing --label (line 14). set -euo pipefail on line 4 means any herdr call that fails stops the script rather than carrying on with an empty variable.
  2. Pick the command (lines 16–20). Claude becomes claude --dangerously-skip-permissions [--model m] [--effort e]; Codex becomes codex [-m m] [-c model_reasoning_effort=e]. The ${model:+ …} expansion adds a flag only when the variable is set, which is how "pass only what was given" is implemented. Each value goes through q() (line 15), which is printf '%q'.
  3. Attach the prompt by reference (line 21). The path is made absolute with cd "$(dirname …)" && pwd, because the new tab starts in --cwd, not where you ran the script. Then %q-quoted, and wrapped as the literal text "$(cat /abs/path)", not expanded here.
  4. Create the tab (line 22). herdr tab create --label … --cwd … --no-focus returns JSON.
  5. Lift the ids and check them (lines 23–25). jq -r pulls .result.root_pane.pane_id and .result.tab.tab_id. A missing key prints the string null rather than failing, so line 25 tests for the empty string and for null, and fails with herdr's raw reply.
  6. Type it (line 26). herdr pane run "$pane" "$cmd" sends the finished line into the new pane's shell. Line 27 prints {"label", "tab_id", "pane_id", "command"}, the command built with jq -Rn --arg so its own quotes survive.

Why a file, not an argument

A prompt passed as an argument has to survive being quoted for the caller's shell, then for spawn.sh, then for the line typed into the new pane, and every layer has its own idea of what a quote, a $ or a backtick means. Passing a path sidesteps all of it: a path is boring. The only place the text is ever read is the end, where the tab's shell runs "$(cat path)" and hands the result to the agent as a single argument.

The result of a command substitution is not parsed again. A $HOME or a backtick inside the prompt file arrives as those literal characters, not as an expansion. That is what makes the prompt safe to be anything. Try it below.
