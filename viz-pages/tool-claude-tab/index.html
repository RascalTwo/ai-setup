↓  WHY IT EXISTS

Six steps to start a session, with no say in the model

Opening a new Claude Code session is the single most common thing I do in a terminal, and herdr had no shorter path to it than prefix+c, type a tab name, Enter, Ctrl-R, c, Enter. Six keystrokes, two of which are a shell history search hoping the right command is still in it, and one of which is naming a tab I am about to let herdr-autolabel rename anyway.

Nothing about that is hard. It is just friction on the most-repeated action in the setup, and friction on a hot path is what a keybinding is for.

The model is the other half. The AI-usage retro (Oct 2026) found Sonnet-by-default left half the weekly limit unused, and no classifier we tried (rules, local LLMs, Haiku, Sonnet and Opus as zero-shot routers) beat a fixed default at picking the exceptions from the first prompt. So the default is Opus 5.5 at medium effort, and the human overrides it with one key.

One chord, one popup

prefix+a opens a small popup with a > prompt. Type the first prompt and press Enter: a new tab appears, focused, running claude --dangerously-skip-permissions --model … --effort … with that prompt. An empty prompt gives a bare session. Esc or Ctrl-C cancels.

Key Does
Tab cycles the model: Opus 5.5, Sonnet 5.5, Haiku 4.5
↑ / ↓ effort: low, medium, high, xhigh, max
Enter launch (empty prompt is a bare session)
Esc / Ctrl-C cancel

It shows up in herdr's own help as new tab running claude: prompt, model, effort, which is the description field of the binding — so it is discoverable rather than being one more chord you have to remember you own.

What it won't do

  • It hard-codes --dangerously-skip-permissions. There is no flag, no env var and no config file; the permission mode is part of the command string the script builds. Wanting a different one means editing the script.
  • It never names the tab. No --label is passed on purpose, so herdr auto-numbers it exactly as it would an unnamed prefix+c tab. Naming is herdr-autolabel's job and it does it better, from the transcript.
  • It always opens in ~, never the directory you were in. The tab lands in the ~ workspace at $HOME whichever workspace has focus, and focus moves there. Starting in a project means cding, or a prompt that says where to work.
  • It does not guess the model. The default is fixed (Opus 5.5, medium, the same as settings.json); picking a different one is your keypress.

A direct chord works too — key = "ctrl+alt+a" instead of prefix+a. It was not chosen, for two reasons: on macOS, Option is not Alt in Ghostty unless macos-option-as-alt is set; and a bespoke chord is one more undocumented thing to remember. prefix+a shows up in herdr's own help with the description above. The chord is just muscle memory.

Where it lives

Integrates with herdr, and only herdr: prefix+a as a [[keys.command]] popup binding, and the herdr CLI as the thing the script talks to.
Requires herdr and jq (plus zsh, which the script runs under). No runtime, no wrapper, no daemon.
Its state None. It keeps nothing — no directory under ~/.agents/state/, no cache, no config of its own. The one thing it writes is a temp file holding the prompt, which the new tab's shell reads once; it is scratch the OS cleans, so there is nothing to keep and nothing that can go stale.
What it installs claude-tab → ~/.agents/ai-setup/tools/claude-tab/claude-tab, and herdr-keybind.toml merged into ~/.config/herdr/config.toml. Afterwards: herdr server reload-config.
Re-running it Safe. The TOML merge is guarded on the command path, so a second install is a no-op rather than a duplicate binding.

A popup, then four herdr calls

The whole tool is one zsh script. The binding runs it as a herdr popup, so it has a terminal: vared reads the prompt and zle widgets bound to Tab and the arrow keys change the model and effort and redraw a status line under it. After Enter it builds one command string and hands it to herdr. 

cmd="claude --dangerously-skip-permissions --model ${models[mi]} --effort ${efforts[ei]}"
ws=$(herdr workspace list | jq -r 'first(.result.workspaces[] | select(.label == "~")) | .workspace_id // empty')
pane=$(herdr tab create --workspace "$ws" --cwd ~ --focus | jq -r .result.root_pane.pane_id)
herdr workspace focus "$ws"
exec herdr pane run "$pane" "$cmd"

The popup: vared and zle widgets

vared -p '> ' prompt is a line editor, so the prompt is edited like any zsh line. Widgets bound to ^I and the up and down arrows (both the ^[[A and ^[OA forms) bump a model or effort index and redraw the status line with zle -M. Esc or Ctrl-C makes vared fail, and the script exits without calling herdr.

The destination: always the ~ workspace

herdr workspace list is filtered with jq for the workspace labelled ~. herdr labels a workspace created at $HOME that way, which is how the script finds it. If it is gone (a workspace disappears when its last pane closes) the script runs herdr workspace create --cwd ~ and uses its first tab; otherwise it runs herdr tab create --workspace … --cwd ~ --focus. No --label, so herdr auto-numbers the tab. The response carries the pane at .result.root_pane.pane_id, which is the reason jq is a dependency. The script then focuses the workspace.

Run it in the foreground, with the prompt in a file

herdr pane run types the command into the new tab's shell, so claude is the pane's foreground process, Ctrl-C reaches it, the command lands in your shell history, and when claude exits you are left at that prompt. The prompt itself travels as a temp file (mktemp), and the command ends in "$(cat file)", so the tab's own shell expands it and quotes and newlines survive. The script execs into that call, so no claude-tab process remains.

Why herdr still sees an agent

herdr's own agent detection picks claude up from there. The tab reports agent_status: idle once it is ready for input, so the status dots and notification routing work exactly as they do for a hand-started agent, and herdr-autolabel's Stop hook has a $HERDR_TAB_ID to rename.

The binding, and the tilde that never resolves

# herdr-keybind.toml — type = "popup": the script asks for input, so it needs
# a terminal. The tab it creates is the visible result.
[[keys.command]]
key = "prefix+a"
type = "popup"
command = "~/.agents/ai-setup/tools/claude-tab/claude-tab"
description = "new tab running claude: prompt, model, effort"
width = "70%"
height = 5
herdr does not expand ~ in a [[keys.command]] command field. The literal tilde above never resolves — so install.ts bakes in the absolute path at merge time, and what actually lands in ~/.config/herdr/config.toml is a full path. The merge is guarded on that path, which is also what makes re-running the installer a no-op.
