Delegating cost more than doing

Handing a task to an agent meant opening a session, pasting the context, and watching it. Nothing stopped two agents editing the same code, nothing noticed when one stalled, and nothing stopped an agent from deciding its own work was done. The plan in Timeline Studio and the agents doing the work never talked to each other.

kelpie joins them: Timeline Studio stays the record of what each task is and whether you've agreed to it, herdr is where you talk to the agents, and a small loop in between does the dispatching.

Mark it, answer it, say yes

  • Hand a task off: set its For channel to Agent in Timeline Studio, in the project's colour. The tick picks it up within five minutes.
  • Answer it: it appears as a tab in the project's herdr space, named ✎ (refine) or ⚒ (build) plus the task. Type in the pane.
  • Finish it by saying so: "sign it off", "approve" or "close it". The agent runs signoff, approve or close, quoting you into the task's history, and its pane closes.
  • Idle? kelpie.ts refine-next starts a refine on the best-ranked task nobody has refined yet. kelpie.ts status shows every run.

What it won't do

  • One build and one refine at a time (max_work, max_refine), and no new run while weekly usage is above the even-pace line.
  • No pushing or deploying. Shipping means merging the task branch into the project's local trunk; publishing stays yours.
  • Safety is guidance, not a sandbox. Agents run with --dangerously-skip-permissions; the briefing and your word are the guard rails.
  • It can't tell when an agent is going in circles. It only flags a pane that sits idle for 15 minutes without handing over.

Where it lives

Integrates with Timeline Studio: reads the plan, writes [dispatch] comments, sessions and the Review channel. herdr: one tab per run, in a space per project. Claude Code: interactive sessions. launchd: com.rascaltwo.kelpie.tick every 5 minutes. ai-tidemark: its weekly usage records feed the gate.
Requires bun, git, herdr and claude.
Its config ~/.config/kelpie/: one projects/<id>.md per project (rename away from .md to switch it off) and an optional config.json.
Its state ~/.agents/state/kelpie/: runs/<project>/<task>/ (each run's worktrees and notes), state.json (stall timers) and tick.log.
Safe to delete? No, deletion-policy: retain: a run folder can hold work not yet merged. The dispatcher deletes a folder itself once its work has shipped.
Not its state The tasks, and every decision about them, live in Timeline Studio as [dispatch] comments, read back on every tick.

One tick, end to end

No daemon and no database. Every five minutes launchd runs kelpie.ts tick, which reads the plan, works out each run's state from its comments, and acts.

  1. Read. timeline-studio.ts lists the project's tasks with For: Agent and its Project colour, and their readiness from /api/ready (signed off, nothing blocking).
  2. Derive. derive() in dispatcher.ts turns each task's [dispatch] comments, Review chip and sign-off into one state: refinable, candidate, working, waiting, input, approved, signed off or finished. Nothing else is stored.
  3. Act. tick() cleans up finished runs, follows panes that moved, flags stalls, relays your comments into live panes, then fills the free build and refine slots by rank.
  4. Spawn. createFolder() attaches each repo as a worktree on agent/<task> and runs setup; herdr.ts opens a tab in the project's space running claude with prompt.md or refine.md.
  5. Hand back. The agent talks to you in its pane and records each step with the kelpie CLI: review, input, then signoff, approve, close or finish on your word.
