Claude reads everything the tools return

Give an agent your mail, your files and a browser and it reads all of it: the doctor's reminder next to the build log, a gift order next to the receipts. Nothing in a tool result is labelled private, and the transcript keeps whatever it saw. Telling the agent "don't look at that" fails the moment a grep or a search result puts it in front of the agent anyway.

veil filters at the one place everything passes through: the tool output, before Claude reads it. The judge is a local model, so the private list and the content never leave the machine.

You write a list, then forget it

  • The list is ~/.config/veil/private.md, plain English, one thing per line, such as "Anything to, from, or about Dana Whitfield" or "Gifts I'm buying for Sam". Be concrete: name people, products and kinds of documents.
  • Off by default until it's fast enough for everyday use: a big output can hit the 60 s deadline and be withheld whole. A statusline widget shows the state: 👁 watching, grey 🙈 off, yellow 👁⚠ failing closed.
  • Switch it with veil on / veil off for this herdr pane, veil on --all for everywhere, VEIL=on claude for one session, and veil status to ask (on, off or down). Claude may switch it only when you ask in chat.
  • Check a model with python3 eval/run_eval.py [model:think ...]: about 120 fake chunks scored for leaks and over-blocking.

A strong filter, not a guarantee

  • It knows what a 9B model knows. qwen3.5:9b passed "Cracking the Coding Interview" under "interview prep" because it did not recognise the title; spelled out in the list, it blocks it.
  • Wording matters. "statements, balances and debts" let a payroll-deposit row of a bank CSV through; "statements and transactions (any deposit, payment or charge)" blocked it.
  • The queue can fail it closed. Ollama here runs one request at a time and finishes requests from killed clients, so other local-model work can push veil past 60 s. It then withholds everything until the queue drains.
  • Counts are not rewritten. A resultSizeEstimate still says how many emails there were. Images are withheld whole, never cropped.
  • Eval, 36 GB Mac, 2026-10-30: one chunk per call leaks 3 of about 120 (2 with the specific list) and over-blocks 2 to 8% in about 115 s. Eight chunks per call leaks 18. gemma4:12b leaks 3 but takes 2113 s. Thinking on is minutes per page, so it is off.

Where it lives

Integrates with Claude Code: a PostToolUse hook (matcher .*, every tool, subagents too, timeout 90 s) running veil hook, and a statusline widget, tools/statusline/statusline-veil.sh.
Requires python3 and ollama (with qwen3.5:9b pulled).
Its state ~/.agents/state/veil/: the down marker while failing closed, per-pane on/off switches, and the eval reports. The private list itself lives outside the repo and outside this folder, in ~/.config/veil/.
Safe to delete? Yes, deletion-policy: delete: it only holds the failure marker, switches and reports, all rebuilt on use. Your private list is not part of this state.

One tool output, end to end

Claude Code fires PostToolUse after a tool returns, and runs veil hook with the call as JSON on stdin. main hands it to hook, which calls scrub; whatever it prints as updatedToolOutput replaces the output Claude sees, and the transcript on disk stores that cleaned version.

  1. Switch check. veil hook returns at once if VEIL=off or the pane or global switch is off. Otherwise it starts a 60 s watchdog (DEADLINE).
  2. Self-protection. If the call mentions config/veil, the whole output is withheld. A chunk that contains a line of the private list is withheld without asking the model.
  3. Cut. walk() traverses the output and keeps its shape. A record small enough to judge whole (an email, an order) gets one vote, so a sender and its subject are judged together; text goes by paragraph; a long paragraph or one of 8+ lines (CSV, ls, logs) goes line by line; each image gets one vote. Units are capped at MAX_CHUNK = 2000 characters.
  4. Vote. judge() sends each unit to Ollama's qwen3.5:9b (thinking off, schema-constrained to PASS or BLOCK), 4 requests at a time, with the private list in the prompt. One chunk per call: batching 8 per call leaked 18.
  5. Rebuild. scrub() swaps each BLOCK for [veil: withheld] (images get withheld.png). The fields type, mimeType, media_type and mime_type (the STRUCTURAL set) are never touched, because Claude Code drops a replacement of the wrong shape.
  6. Fail closed. Claude Code passes the original output through if a hook crashes, times out, prints bad JSON, returns the wrong shape or exits 2 (tested on 2.1.314), so veil does not rely on it. An Ollama failure or bad reply makes blank() withhold every string and image, keeping the exact shape. It writes down and shows a notification at most every 5 minutes, and the statusline turns yellow 👁⚠. The watchdog answers at 60 s, before Claude Code's 90 s timeout.

Example from the fake eval fixtures: in an inbox listing, "re: dinner friday?" from Dana Whitfield is withheld as one record while the newsletters pass, and the screenshot of Dana's thread comes back as the withheld picture.
