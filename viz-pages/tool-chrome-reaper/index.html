Nothing was left to stop the browser

A test run built on Puppeteer or Playwright closes its browser when it ends normally. Killed instead (a closed herdr pane, a timeout, kill -9), it never gets the chance, and the browser keeps running with launchd as its parent and nothing to stop it. On 2026-10-13, 17 of them had grown to about 1,550 processes and filled 47 GB of swap.

No fix inside each tool survives kill -9, so chrome-reaper sweeps from outside, for every tool at once.

You don't run it, it runs

  • Normally: nothing. launchd starts reap.sh at load and every 60 seconds after.
  • See what it did: ~/.agents/state/chrome-reaper/reap.log. Each kill line carries the browser's --user-data-dir, which points at the tool that leaked it.
  • Preview: sh reap.sh --dry-run logs "would reap" and "would remove" lines and does neither.
  • Check it is alive: launchctl list | grep chrome-reaper shows exit status 0, and launchd.err beside the log stays empty.
  • Test it: sh tools/chrome-reaper/reap.test.sh (about 10 s) starts real headless Chromes.

What it won't do

  • Only orphans. A process whose parent is not PID 1 is skipped, so a browser belonging to a test that is still running is safe.
  • Only automation browsers. A process must run from ms-playwright or .cache/puppeteer, or be a Chrome or Chromium with --headless or a Puppeteer/Playwright profile name on its command line. A headless Chrome you started yourself, then orphaned, would match too.
  • No fix for the leak. It cleans up after tests; it does not tell the test to close its browser.
  • Up to a minute late. A browser can run for the rest of its interval before the next sweep, and an orphan is killed with a 2 second wait for each, one after another.
  • Profiles have a grace period. A temp profile is only removed once untouched for an hour, and never while a running process names it.
  • macOS only. It leans on launchd and getconf DARWIN_USER_TEMP_DIR.

Where it lives

Integrates with launchd: com.rascaltwo.chrome-reaper, started at load and every 60 seconds. It watches whatever browsers Puppeteer, Playwright and tools built on them leave behind.
Requires sh, plus the macOS ps, find and grep in /bin and /usr/bin.
Installed copy launchd may not read scripts under ~/Desktop (TCC), where the repo lives, so the plist runs a copy of reap.sh in the state folder. Re-copy it after changing the script.
Its state ~/.agents/state/chrome-reaper/: reap.sh (the installed copy), reap.log and launchd.err.
Safe to delete? No, deletion-policy: retain. The log is disposable, but deleting reap.sh stops the sweep until you re-run the install.
Platform macOS only.

One sweep, end to end

No daemon and no database. launchd runs a short shell script; everything it knows comes from one ps listing.

  1. Snapshot. /bin/ps -Ao pid=,ppid=,etime=,command= feeds a while read loop, one process per line.
  2. Orphan test. Any line whose ppid is not 1 is skipped. A live test is the parent of its browser, so it never gets this far.
  3. Automation test. A command path under */ms-playwright/* or */.cache/puppeteer/* matches outright. A path containing /Google Chrome, Chromium or chrome must also carry --headless or a profile name (puppeteer_dev_chrome_profile-, puppeteer_dev_profile-, playwright_chromiumdev_profile-, playwright_firefoxdev_profile-). Anything else is skipped.
  4. Log, then kill. It appends reap pid=<pid> age=<etime> <--user-data-dir=...> to reap.log, then runs kill, waits 2 seconds, then kill -9. With --dry-run it logs "would reap" and moves on.
  5. Profile sweep. It lists directories in the user temp dir (getconf DARWIN_USER_TEMP_DIR, since launchd sets no TMPDIR) that are older than 60 minutes (-mmin +60) and match the four profile names.
  6. Safety check. A fresh ps -Ao command= is read, and a directory that any running command line mentions is kept. The rest get rm -rf.
