A role, not a process

You are the CEO. The manager exists so you can ask one session what ten are doing instead of walking to ten panes — but nothing it does may assume it is the only one talking to a session. You can and will walk to a pane whenever you want.

Any session can invoke the skill and become the manager. It keeps no memory of what sessions are doing; every invocation it runs fleet for a JSON snapshot, one object per pane, reads the ledger at ~/.claude/fleet/ledger.md, and reconciles. An In progress row whose session has vanished from the snapshot gets surfaced, not resolved — a pane can die without the work being finished, so it asks you.

Two sources, and the disagreement is information

FieldSourceTrust
herdr_statusherdr, by matching text on the terminal screenworks for every agent; breaks silently when Claude Code restyles its UI
signalthe session's own Claude Code hookauthoritative, but null for non-Claude panes and sessions older than the hooks

So the rule is asymmetric: if signal says attention and herdr_status says idle, believe signal. And if neither fires for days across the whole fleet, suspect herdr's detection rules broke rather than believing everyone is calm — herdr agent explain <pane> names the rule that matched.

done and idle are the same underlying state, before and after you have looked at it. Reading a pane from the CLI does not mark it seen, so the manager cannot accidentally clear a done out from under you.

Label, not pane id — and when they lie

The label is what your sidebar shows, so it is the only name you can act on. The title tracks what the session is doing now; the label only changes when something renames the tab. When they disagree, the report says so — a tab labelled fleet running the orchestrator redesign, or one labelled 6, sends you to the wrong pane or to no pane at all. It offers herdr tab rename; it never renames on its own initiative. If label is null it falls back to the pane id and tells you that is what it is doing.

It also can't assume which pane it is: the manager session is not the tab labelled fleet unless it happens to be. It checks. (The sibling that keeps those labels honest automatically is herdr-autolabel.)

400 characters, then a subagent

last_message is truncated to 400 characters — enough to say what a session is asking, not enough to answer a real question about its work. For anything deeper it dispatches a subagent to read that session's transcript and report back in two sentences. Never a transcript into the manager's own context; they run to megabytes and it is holding ten of them. The untruncated text, if genuinely needed, is at ~/.claude/fleet/state/<session>.Stop.json.

Spawning and talking

A new session is always its own tab and never steals focus:

pane=$(herdr tab create --no-focus --cwd <dir> --label <slug> \
       | jq -r '.result.root_pane.pane_id')
herdr agent start <name> --kind claude --pane "$pane" -- --dangerously-skip-permissions
herdr agent prompt <name> "<the task>"

--kind also takes codex, gemini and others — this is not Claude-only. Talking to a session already running is the same prompt call: it types the text and Enter into the pane, so if the session is mid-turn, Claude Code's own input queue catches it. There is nothing to build for queueing and nothing to wait for. Fanning out is just several prompt calls — no special mechanism.

Every session runs --dangerously-skip-permissions. A prompt sent to the wrong pane gets executed without anyone asking. Hence the two hard rules: never write to a pane whose focused is true — that is two writers on one stdin with no lock — and never target yourself. fleet already excludes $HERDR_PANE_ID; do not route around it.

The ledger tracks tasks, not sessions

Two sections, In progress and Done. Rows are tasks; only In progress rows carry a session UUID.

A session's status is never written into the ledger. Status is read live and joined at display time, so the ledger cannot go stale about anything herdr already knows. herdr's done ("a turn finished") and the ledger's Done ("the work is finished") are different claims — only you promote a task between them. Done rows older than 7 days get swept at the top of an invocation; that is the only pruning, and there is no scheduled job.

It is deliberately not a task manager. Backlog and parking-lot columns were considered and cut — if you want those, that is a separate tool and a separate conversation.

Disposable on purpose

No session state in the manager's head, ledger on disk — so /clear costs nothing and beats letting the context compact. When a round of work is finished and the ledger is written, it tells you it is safe to clear. At task boundaries, never at a token threshold: a threshold fires mid-thought and costs you the thread.

herdr's own conventions — pane geometry, naming, targeting, lifecycle — are deliberately not duplicated here. herdr --skill ships with the binary and changes when herdr changes.
