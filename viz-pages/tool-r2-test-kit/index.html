OWNED TOOL · R2-TEST-KIT

Three kinds of test.
One report, and which test ran which line.

r2-test-kit counts Istanbul coverage in vitest and Playwright, records it per test, and merges it into one report, one floor and one exit code.

Vite apps only. Not a test runner and not a bundler plugin for anything else.

Each runner measured coverage alone, and none could say which test did it

A Vite app with component tests in vitest and journeys in Playwright has two coverage numbers that cannot be added, and no single list of every test. Each runner also reports a total, so you cannot ask the two questions that matter when a test changes: what did this one test run, and which tests would notice if I changed this line or this side of an if.

No package did this for Vite, JSX and two runners together, so the glue is written once here. r2-test-kit is what r2-app-stack (reference/test-stack.md) calls for: one check command that ends in one list of every test, one coverage report across logic, component and browser tests, and one exit code.

example/ is a working app wired with it, and its npm run check is the kit's end-to-end test.

Four lines in the app, one script

Install from the folder, since the kit is not published yet:

npm install -D --install-links ~/path/to/ai-setup/tools/r2-test-kit
npx playwright install chromium --only-shell
  • vite.config.ts: mode === "test" && istanbul() in plugins, and setupFiles: ["@rascaltwo/r2-test-kit/vitest"] in test.
  • journeys: import test and expect from @rascaltwo/r2-test-kit/playwright, and have Playwright's web server build with vite build --mode test so the page is instrumented.
  • allurerc.mjs: export default allure({ name: "my app", minTestsCount: 5 }).
  • package.json: check is run-s --continue-on-error clean format lint types test:unit test:e2e coverage cov-map results, with coverage = r2-test-kit merge and cov-map = r2-test-kit cov-map --build.
npx r2-test-kit cov-map --test "adding a mug" what one test ran, per file
npx r2-test-kit cov-map --line src/App.tsx:21 which tests ran that line

Copy example/vite.config.ts and example/playwright.config.ts. clean comes first so a renamed test's old record is not counted again, and --continue-on-error means one failing step does not hide the rest.

What it won't do

  • Vite only. Another bundler needs its own Istanbul plugin (babel-plugin-istanbul) feeding the same records. Not built.
  • No test.concurrent. Tests in one vitest file must run one at a time, or their counters mix.
  • Playwright reads the page fixture only. A page a test opens itself is not counted, and a page left for another origin keeps its stash there.
  • About 5 MB per page. A page's counters must fit in sessionStorage. If not, the test fails with r2-test-kit: a page's coverage did not fit in sessionStorage… rather than reporting less.
  • A browser test has no load record. Each test loads the page fresh, so start-up code is credited to every browser test, because each one really ran it.
  • Unloaded files are found only under src/. Code elsewhere that nothing loaded is not added at 0%.
  • Not published. You install it from this folder, with --install-links: a symlinked kit imports its own vitest, not yours, and its hooks never run.

Where it lives

Integrates with vite: the istanbul() plugin. vitest: a setup file. playwright: a test fixture. allure: the allurerc preset.
Requires node and npm. Vitest and Playwright are the app's own peer dependencies; example/package.json pins what was tested (vitest 5.1.0, Vite 8.3.8, Playwright 1.65.1, Allure 3.33.0).
Its state None. It keeps no state folder of its own. Everything it writes goes into the app it is installed in, under out/, plus coverage-floor.json at the app root.
Safe to delete? out/ yes, clean removes it on every run. Keep coverage-floor.json: it is the floor, and you commit it.
Settings Optional r2-test-kit.config.mjs at the app root: include, inputs, floorFile, reportDir. Filters are functions, not globs: a glob matches nothing under a dot-folder, without telling you.

One test's coverage, from source to a floor

Everything is plain Node ESM in tools/r2-test-kit/src/: vite.mjs, vitest-setup.mjs, playwright.mjs, record.mjs, merge.mjs, floor.mjs, cov-map.mjs.

  1. Instrument the original source. istanbul() (a Vite plugin, enforce: "pre") runs istanbul-lib-instrument on each .ts/.tsx before TypeScript and JSX are compiled, so counters sit in source coordinates with no source-map step, and a JSX && arm is a real branch. It runs for SSR transforms too, which is how vitest loads modules. It skips node_modules and anything the include filter rejects (default: src/** minus tests, .d.ts and main.*). Counters accumulate in globalThis.__coverage__.
  2. Vitest: diff around each test. vitest-setup.mjs keeps a snapshot() of the counters. afterEach calls diff(mark, cov) and writes the difference as that test's record to out/coverage/unit. Whatever ran between tests (imports, hooks around the file) is added up and written once at afterAll as (load) <test file>, which counts in the report and is credited to no test.
  3. Playwright: carry counters across navigations. A full navigation throws the page's window away. So an init script listens for pagehide and writes __coverage__ into sessionStorage as __r2cov:N, which is synchronous and survives a same-origin navigation. When the test ends, the auto fixture evaluates in the last page, takes its own counters plus every stash, sums them, and writes the record to out/coverage/e2e. A call from the page back to Playwright on pagehide never arrives, and reading the page while its navigation request is held hangs; both were tried and measured.
  4. One record format. writeRecord() stores { runner, name, load, files } per test: only counters that moved, plus m, a hash that points at the file's static map (statements, functions, branches) written once to out/coverage/meta/<m>.json. The record's file name comes from the test name, so a rerun replaces its own record.
  5. Merge into one report. r2-test-kit merge checks every input folder (coverage input missing if absent, coverage input empty if no test saved coverage, usually a build without --mode test), rebuilds full Istanbul file coverage from each record and its static map with hydrate(), and adds every included src/ file nothing loaded, at 0%. It writes lcov.info, HTML and coverage-final.json to out/coverage/merged and prints a text table.
  6. Check the floor. coverage-floor.json holds totals for lines, statements, functions and branches. Below it, merge prints COVERAGE FLOOR: lines 80% < 90% and exits 1. Above it, the file is rewritten with the new totals (commit that). Equal leaves it alone. It is checked on totals, not per file.
  7. Map tests to lines. cov-map --build turns each record's non-zero counters into keys per file: a line N, a function N#name, a branch arm N.bBLOCK.ARM, and writes out/pertest/map.json. --test and --line read it back. A function no test called has a zero counter in every record, so nobody is credited for it. V8 coverage over-credits that case, which is why it was ruled out.

The kit's own tests hold 100% lines, branches, functions and statements: npm install && npx vitest run --coverage in the kit, and cd example && npm ci && npm run check end to end.
