↓  WHY IT EXISTS

An agent can't walk out without cutting off its own last word

A session lives in a terminal pane. When you are done, the pane has to go, and there are two ways to get that wrong. Either you do it: hands off the conversation, find the pane, close it. Or you give the agent the power to do it, and now an agent that thinks it has finished can pull the plug on a session you were not finished with.

end-session is the answer to both halves. The trigger is deliberately narrower than the agent's own sense of "done", and the closing is deliberately clumsier than kill: the pane is closed by a process the agent starts, on a timer, so that the agent gets to finish its sentence first. The agent is killing the thing that is talking, so the order of operations is the skill.

Say it plainly. Everything else is a pause.

skills/end-session/SKILL.md line 11: "The user's direct command is the only trigger." Its description lists three phrasings and gives the register:

"end the session" CLOSES the canonical form.
"close it" CLOSES when it is plain from context what "it" is.
"yo, end it" CLOSES casual is fine; it is still a command.
"and the session" ASKS once, in a line, and waits. Dictation garbles "end" into "and", and the cost of guessing wrong is an unrecoverable close (step 1).
"thanks" · "bye" · a finished task STAYS OPEN says the file by name: these "leave the session open".

There are no arguments. It acts on the pane it is already in; there is no way to point it at another one.

It will not walk out on its own

  • It never infers an ending. A finished task, "thanks" and "bye" are named in the skill precisely because each one feels like permission. None is.
  • It will not guess through a garbled command. One question, one line, then it waits. It does not ask twice and it does not proceed on a hunch.
  • It only works inside herdr. Outside, the skill's answer is not a workaround: it says so, tells you to type /exit, and stops. It does not try to find a parent process to kill.
  • It reports unfinished work; it does not tidy it. The goodbye names uncommitted changes, a running background task or an unanswered question, then the session ends with them. The skill defines no step that commits, waits for or cancels any of them.
  • There is no abort. Once the timer is set, the file's instruction is "send nothing after the command". The three seconds are for the goodbye to render, not for second thoughts.
  • It closes one pane: its own. The id comes from $HERDR_PANE_ID, the pane this process lives in.

Two lines of manifest, one hard dependency

The skill skills/end-session/SKILL.md: a single file, 22 lines. No scripts, no hooks, no references. The whole skill is the sentence-by-sentence instruction the model reads.
Declared kind: skill, state: false. requires.commands: [herdr]; no integrates and no deletion-policy.
Its state None. It writes no file, keeps no log and remembers no earlier session. What it changes is not on disk at all: a pane in your herdr workspace stops existing, so there is nothing of it to delete or retain.
Actually depends on The herdr CLI on PATH and $HERDR_PANE_ID in the environment. That dependency lives in prose (step 2), not in the manifest. The check is run live, every time. Other tools here read the same variable to learn which pane they are in: the statusline and ttyimgspool.
Called from Nothing in this repo. No other skill or hook invokes it; the only caller is you saying the words.

Four gates, then the door

The skill is an ordered list, and every earlier step exists to protect a later one. Following one utterance down the file:

Line numbers are skills/end-session/SKILL.md. Red exits leave the session alive; only the last box ends it. 

11 Closes the herdr pane this session runs in. The user's direct command is the only trigger;
   a finished task, "thanks", or "bye" leaves the session open.
13 1. Confirm the command is unambiguous. ... ask once in a line and wait.
14 2. Check you are in herdr: [ -n "$HERDR_PANE_ID" ]. If not, say so, tell the user to type /exit, and stop.
15 3. Say goodbye in one line, naming anything left unfinished. This is the last text you write.
16 4. Close the pane:
19    nohup sh -c 'sleep 3; herdr pane close "$0"' "$HERDR_PANE_ID" >/dev/null 2>&1 &

The last three seconds

Step 4 is one line of shell and the reason the skill is not one sentence long. The agent needs to destroy its own pane, but the pane contains the agent, the shell that runs the command, and the process tree beneath them. So the command is sent first and takes effect last. Step through it:

Reading the one-liner

  • nohup sh -c '…': a fresh sh that ignores hang-up signals, so the timer is not dropped when the tool call's shell exits.
  • sleep 3; herdr pane close "$0": the whole payload. herdr pane close takes exactly one argument, a pane id (herdr pane close --help prints <pane_id>).
  • "$HERDR_PANE_ID" after the quoted script becomes $0 inside it. The calling shell resolves the id and hands it over as data, so the pane that gets closed was fixed at the moment the command was sent.
  • >/dev/null 2>&1 &: no output to hold the tool call open, and into the background. The call returns at once: a sleep 2 variant of the same line, run as a test, came back in a few milliseconds and wrote its effect two seconds later.
The inversion. In the transcript the close command comes before the end of the turn. In time it happens after it. That inversion is the entire design: the goodbye is spoken to a pane that still exists, the instruction "send nothing after the command" keeps the model's output from racing the shutdown, and step 2 makes sure the timer is never set where it cannot work.
