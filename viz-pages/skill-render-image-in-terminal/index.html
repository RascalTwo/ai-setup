↓  WHY IT EXISTS

Claude could see it. You couldn't.

Claude Code's TUI draws text and nothing else. Claude reads screenshots, renders charts, downloads logos — and the transcript showed a file path. The only way to see what Claude saw was a separate gallery pane on prefix+i, or copying the path into open and leaving the terminal altogether. "Show me" had no honest answer.

ttyimgspool fixed the drawing: its hook can now put a picture inline in the transcript. Screenshots, Reads and pastes appear automatically. render-image-in-terminal exists for everything else — the image that is not already a tool Claude ran, but a thing you asked to see.

Say "show me"

The skill fires when you ask to see an image, logo, chart, diagram, screenshot or picture — or when an image Claude produced is the answer. Claude then runs, as its own Bash call:

~/.agents/ai-setup/tools/ttyimgspool/show-image <source>

# <source> is one of
/path/to/logo.svg                 # a local file, any format sips reads
https://example.com/diagram.png   # fetched with curl
clipboard                         # an image on the clipboard — or, failing that, its text as the source

To show something it makes — a chart, a rendered page, a diagram — Claude writes it to a file first, then shows that file. It is done when the command printed its show-image: <png> line; a show-image: <reason> on stderr means nothing was shown, and Claude is told to say why.

In the transcript you get a captioned thumbnail under the call. Ctrl+click it (or the caption) and the original opens full-pane at full resolution; a click, a key or a scroll closes it.

What it doesn't do

  • Kitty-graphics terminals only. Ghostty, kitty, WezTerm — or herdr with kitty_graphics = true. Anywhere else the hook stays silent and you get the show-image: line and nothing more.
  • Ctrl+click, not click. A plain click is Claude Code's, and it only opens an allowlist of schemes; the file:// link becomes a Finder reveal (anthropics/claude-code#95675). Ctrl+click reaches the herdr plugin instead.
  • The thumbnail is fixed when drawn. Up to 40×12 cells, sized at the moment the hook ran; resizing the pane later does not redraw it. The full-pane view is only as sharp as the source.
  • It does not repeat what already shows. A screenshot or an image Claude Read is drawn by the hook on its own; there is nothing for show-image to add.
  • It is not a viewer or an editor. One image per call, as-is. No crop, no zoom inline, no annotation — and no memory of what it showed; browsing old images is ttyimgspool's gallery.

Where it lives

The skillskills/render-image-in-terminal/SKILL.md — a dozen lines of prompt. It tells Claude which command to run, what counts as done, and what not to bother showing. The skill ships no code of its own.
IntegratesClaude Code: the ttyimgspool PostToolUse hook is what draws it. The skill only produces the line the hook is listening for.
Requiresttyimgspool — its show-image script and its hook, reached through ~/.agents/ai-setup/tools/ttyimgspool/. Without the tool installed, the command does not exist.
Its stateNone — state: false. The normalised PNG goes to $TMPDIR, and the copy the hook spools belongs to ttyimgspool, not to this skill.
Safe to deleteNothing of its own to delete. Removing the skill leaves ttyimgspool drawing screenshots, Reads and pastes exactly as before; you just lose "show me" for everything else.

From "show me" to a thumbnail

One request, from your words to pixels in the transcript. The terminal half — uploading over the tty, placeholder cells, the Ctrl+click viewer — is ttyimgspool's poster in full; here it is one step.

← → arrow keys

The skill is a contract, not a program

Everything the model is told fits in four instructions: run show-image as its own Bash call; write anything it creates to a file first; skip images that already appear (screenshots, Reads); and treat the printed show-image: line as done, a stderr reason as a failure to report. "Its own Bash call" matters — the hook scans that call's output, and a line buried in a longer pipeline is easy to swallow.

show-image: every source becomes one PNG

A 22-line bash script. An http(s):// source is fetched with curl -fsSL; clipboard tries osascript for «class PNGf» data and, when the clipboard holds text instead, re-runs itself on pbpaste. Whatever arrives is passed through sips -s format png into $TMPDIR/<epoch>-<pid>.png, so the hook only ever sees PNG. The single line of stdout is the whole interface:

show-image: /var/folders/…/T/1790571037-4411.png   # success → stdout
show-image: not an image: notes.txt                # failure → stderr, exit 1

The hook: a regex, then the drawing

When the Bash call returns, ttyimgspool-hook.py joins every string in the tool response and matches SHOW_RE = ^show-image: (/.+)$. Each hit is spooled under the show-image tool name and handed to show_inline(), which uploads the PNG to Claude Code's tty in kitty APC chunks and returns a systemMessage of Unicode placeholder cells whose 24-bit foreground colour is the image id. Above the cells goes a caption, show-image · <w>×<h> · ctrl+click to enlarge. Claude Code prints that message as text; the terminal paints the picture onto those cells, wrapped in an OSC 8 file:// link for the Ctrl+click viewer.
