A spinner tells a room nothing

When one person drives Claude Code and a group watches, the terminal gives them a spinner and a wall of scrolling tool output. Nobody can say what Claude is on right now, why it took four minutes, or whether the last command worked, without reading over the driver's shoulder. Afterwards the only record is a transcript file nobody opens.

ringside reads that transcript file as it grows and turns it into something a room can follow: the current action, a timeline of everything done, and a retelling in plain English. The same page replays any earlier session.

Open the page, follow or pick

  • Open it on the viz server at http://127.0.0.1:5180/<$REPO relative to $HOME>/viz-pages/ringside/.
  • Follow newest jumps to the most recently written session and switches when a newer one starts. Or choose one of the recent sessions from the list to replay it.
  • Right now, Round, Timeline. Step through rounds with ‹ ›; zoom, pan or brush the overview; choose This round, Last N min or Whole session. Click a bar to pin its details, click again or press Esc to follow the latest.
  • Story and Conversation. The session retold in chapters, and your prompts and Claude's replies with the work between them folded into strips.
  • Share the view. The window, round, selection and session live in the URL hash, so a link opens the same view.

What it won't do

  • It only watches. It reads transcripts under ~/.claude/projects and never writes them, and it cannot steer or stop Claude.
  • The list holds the 15 newest sessions. Older ones are not offered, even though the files still exist.
  • It polls, it doesn't stream. The page asks for new transcript lines every 1.5 seconds, so it trails the real session by about that much.
  • The model's wording can be wrong. Anything marked ✦ is written by a small local model; the bars, times and counts come from the transcript itself, not the model.
  • Without Ollama it still works, just plainer: rule-written labels stay, and the ✦ labels, outcomes, strip summaries and story simply never appear.
  • Its tests don't touch real data. They use fixtures and a faked backend, so a green run says nothing about your own transcripts.

Where it lives

Integrates with Claude Code: reads session transcripts in ~/.claude/projects, and each session's subagents/ folder, never writing them. Ollama: gemma4:e4b at 127.0.0.1:11434 writes the labels, outcomes, rows for scripts, strip summaries and the story. viz: the viz server serves the page and its API routes.
Requires The viz skill, plus bun and ollama on the machine.
The app viz-pages/ringside/: api.ts (server routes), model.ts (the parser), contract.ts (route types), app.ts (the page) and tests/. This poster is a separate folder.
Its state ~/.agents/state/ringside/: five JSON caches of the model's answers, labels.json, outcomes.json, lanes.json, beats.json and stories.json.
Safe to delete? Yes, deletion-policy: delete. They are only memoised answers; the next load asks the model again, so you lose some seconds of waiting, not data.
Not its state The transcripts. They belong to Claude Code, and ringside's page position is only the URL hash.

One tool call, from the transcript to the screen

No database and no push channel. The page pulls, the server reads a file from a byte offset, and a pure parser shared with the tests turns lines into bars.

  1. Find. findSession() checks the session id is a UUID, then looks for <id>.jsonl in every folder under ~/.claude/projects. Helpers are the files in <id>/subagents/, each described by its .meta.json.
  2. Read. /events calls readFrom() for the main file and each helper at the byte offsets the page sent. It returns up to 4 MB, cut back to the last complete line, plus the new offsets. If a file still has more, more is true and the page asks again straight away (up to 20 rounds a poll).
  3. Parse. parseLines() in model.ts turns lines into calls, results, prompts and says. A call pairs a tool use with its result by id; a result that arrives first waits as an orphan until its call turns up.
  4. Sort. laneOf() gives the row from the tool name. For a shell command, shellSteps() splits it into steps and the strongest one wins: Change over Verify over Run over Look. A step that runs an interpreter on a script is marked needsLane, and counts as at least Run until the model decides.
  5. Draw. app.ts keeps calls in order and redraws every 500 ms so running bars grow. The You row comes from waitingSpans(): from each of Claude's final replies to the next prompt, wherever no call is in flight.
  6. Word. For calls in view, two at a time, newest first, the page posts to /label, /outcome (the result is re-read from the transcript at the call's pos), /lane, then /beat and /story. askOllama() sends text through redact() to gemma4:e4b at temperature 0, and a failure returns null. Each answer is written to its JSON cache first-come, so the second viewer reads it for free.

Under viz verify every model route sees the VizAutomation user-agent and answers null at once, so verifying ringside never calls Ollama.
