↓  WHY IT EXISTS

A decision does not belong in a wall of text

An agent mid-task needs a human for four kinds of thing: approve a risky step, review a diff, fill in a few fields, pick some rows. In a terminal each of those is a paragraph and a typed reply: a diff scrolls past, a table is mangled by wrapping, and "reply y to delete 212 MB" is one slipped keystroke from a mistake.

genui-viz puts that question on a card instead, and returns what you pressed as data. The agent writes about 300 bytes of JSON; it never writes UI.

Write JSON, get an answer

The agent runs bun genui.ts show spec.json (or an inline '{...}', or - for stdin). It waits for you, up to 600 s by default, and prints one line: ✓ c-<id>: <what you sent>. It fires when the SKILL.md says a card beats text, or when you say "genui", "show me a card" or "ask me with a panel".

A card is built from one or more components. Every one below is the real thing: the same panel.ts the panel uses, drawing the spec on the left. Press the buttons; the line underneath is the receipt the agent gets.

What a card will not do

      
    
        
  • 
          macOS only for the floating panel. Elsewhere the card opens in a browser tab, which
          ignores the close after an answer.
        
    • 
        
  • 
          It hides itself. The panel shows only while Ghostty is frontmost and the
          card's herdr pane is focused. A card for a pane you are not looking at waits, hidden.
        
    • 
        
  • 
          Highlighting and markdown need a CDN on first use; offline, you get plain text.
          Highlighting is per line, so multi-line strings and comments lose their colour.
        
    • 
        
  • 
          html cards do not redraw. Improving a component redraws every old card; an
          html card stays as it was written. Prefer a component when one fits.
        
    • 
        
  • 
          Free-text questions stay in chat. A card is for a decision, a shape the terminal
          mangles, or a result worth a glance.

Where it lives

      

        
          

            The skill
            
              skills/genui-viz/: SKILL.md, genui.ts (CLI),
              lib.ts, page/ (panel.ts,
              panel.css, index.html), helper/Panel.swift,
              reference/research.md.
            
          

          

            Integrates
            
              viz: cards and answers live in the central library's genui viz.
              herdr: the panel follows its pane, hidden while another pane is focused.
              ghostty: the panel sits at the terminal window's corner.
            
          

          

            Its state
            
              ~/.agents/state/genui-viz.json caches the page directory and URL (safe to
              delete: the next show rebuilds it). The cards and answers themselves are the look-back
              log in the genui viz; deletion-policy: retain, so it is
              kept. The drag offset is in macOS UserDefaults under
              genui-panel.
            
          

          

            Requires
            
              The viz skill and bun. For the floating panel, macOS plus
              the Xcode command line tools to run helper/build once.

The card is data, the drawing is shared

      

        A card is a line of _log/cards and an answer is a line of
        _log/answers, both served by the viz's page-data route. Everything that draws
        lives in page/panel.ts, and ensurePage() copies it into the page
        on every show. That is why this poster's gallery is not a screenshot: it imports the same
        file through a symlink and calls cardBox(card, answer, live, post) with a
        post that prints the receipt instead of POSTing.
      

      
Names are borrowed

      

        Inputs follow MCP elicitation's requestedSchema; display blocks follow Adaptive
        Cards (facts, table, body). The reasoning is in reference/research.md.
