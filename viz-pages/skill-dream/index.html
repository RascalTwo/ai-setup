The predecessor died and nobody noticed

retro, the predecessor this replaces, wrote its findings to markdown reports that piled up unaggregated — and when it quietly stopped running, nothing surfaced that it had. Three root causes, three deliberate design choices here:

  • It required manual invocation → launchd runs dream nightly, unprompted.
  • It wrote per-session reports nobody aggregated → consolidating across sessions is the point; per-session artifacts are ephemeral.
  • It died silently → the dashboard shows "last dream: N days ago" and turns alarming when that goes stale.

03:17, without being asked

The trigger is launchd, not you. com.rascaltwo.dream carries a StartCalendarInterval of 03:17 — minute 17 to miss the on-the-hour thundering herd — with deliberately no RunAtLoad (loading the job should not kick off a dream) and no StartInterval (it is evaluated independently and would double-fire). This machine sleeps at night, and launchd coalesces missed intervals into one catch-up on wake, so the worst case is a single late run, never a backlog.

The skill itself is disable-model-invocation: true — no agent decides to dream at you. You say "dream", or you open the dashboard. Everything below can also be run by hand:

scripts/nightly.sh                        # the full pipeline — what launchd calls
scripts/scan.py --dry-run                 # what stage 1 would funnel
scripts/scan.py --subagents               # also mine <session>/subagents/** (assistant-side only)
scripts/score.py --jobs 6                 # judge them; resumable, re-runs are free
scripts/synthesize.py --min-occurrences 3 --dry-run
scripts/merge-approved.sh                 # merge what you approved in the viz

The one human touchpoint is the dream-queue dashboard. Everything before it is automatic; nothing after it happens without an explicit thumbs-up.

The four things it will not do

  • Never touch main. It is a publish artifact; all work targets private/trunk. Publishing stays a deliberate human act.
  • Nothing auto-applies. Which is exactly why there is no self-modification fence — a proposal that rewrites this skill is just another branch you review.
  • ~/.claude/projects is read-only input. Never written to, never deleted from.
  • Never the find wrapper. Use /usr/bin/find — the shell wrapper rejects compound predicates and exits 0 on failure, so failures look like successes.

And it will not run on battery. nightly.sh matches pmset -g ps for 'AC Power' positively and skips otherwise — an unplugged laptop gets no dream, and a missing or unrecognised pmset counts as "not on AC", because guessing wrong here spends an hour of someone's battery.

Cracking it open

One night, end to end. The order is fixed in nightly.sh: AC gate → PID lock → scan → score → ollama preflight → cluster → synthesize → conflicts → heartbeat. There is deliberately no set -e, because a mid-script abort would skip the heartbeat, and a missing heartbeat is indistinguishable from "the machine never woke up".

The old prefilter was a verbosity detector

Six independent readers audited the original single-stage keyword filter over 86 sessions and measured its recall at 20–64%. It captured zero assistant turns, and its capture rate rose monotonically with turn length — 0% under 20 words, 79% at 200+. It was keeping the narration and dropping the objections. About 60 of 91 misses are unreachable by any pattern list, which is why the judge is not optional.

So the funnel inverted: stage 1 (prefilter.py, no model at all) now admits every substantive human turn plus any assistant segment making a first-person past-tense claim, and stage 2 (score.py) decides. Stage 1 has two writers — scan.py nightly (authoritative, idempotent) and a stop.sh hook every turn, incremental by message-uuid watermark and pure optimization. If every hook fails forever the system still works, and processed.tsv dedupes the overlap.

Subagent transcripts, with the humans thrown out

Assistant self-retraction turned out to be the highest-value signal class the audit found, and subagent output is nearly pure assistant text — so scan.py --subagents mines <session>/subagents/**.jsonl. But a subagent transcript is not a session: there is no human in it, and its "user" turn is a dispatch prompt written by another agent. Stage 1 reads those turns as context only and emits no user-role moments from these files.

Measured, that one suppression drops ~21,500 would-be "human signal" moments — 2.5× the assistant yield — including briefs that read exactly like stated user preferences. Moments are attributed to the parent session so they cluster with the work that produced them, the ledger gives each file its own key (<parent>/<rel-path>), and occurrences collapses one parent's fan-out to 1, so a single event cannot outrank a real recurrence. Against the obvious objection that this is all duplicate text: 99.5% of subagent assistant moments are absent from what stage 1 captures from the parent.

A path that adds five moments. Stage 1 also mines successful Task tool_results in the parent transcript — but 1,881 of 1,884 of those subagent transcripts are already on disk, so --subagents has read them. Turning the path on adds 5 genuinely new moments to 99,137. It exists so capture degrades gracefully if subagent transcripts stop being written, not because value is being thrown away today.

Exactly two stages leave the machine

Transcripts contain client work, so egress is a real cost — and it was paid deliberately, twice: score.py and synthesize.py, each one claude -p call per batch or cluster. Nothing else. The A/B behind that is in eval/RESULTS.md: local synthesis measured 4.5–6.0 out of 12 against Claude's 11.1–11.8. That gap is not "slightly worse" — qwen3-coder:30b proposed hook interception inside the prose-only ponytail skill in 6 of 11 proposals, invented a ~/Desktop/Code that does not exist, and never once declined.

Everything else is local — prefilter.py needs no model at all, cluster.py embeds with nomic-embed-text on Ollama. And the honest footnote the skill insists on: local clustering is not an egress saving. The hybrid was tested and saves zero bytes, because synthesis sends the same candidate text either way. Clustering is local because embeddings are cheap and instant, not because it protects anything.

No taxonomy, no cap, no backfill

The proposal envelope at state/proposals/<id>.json carries only what the dashboard needs to render and sort: title, rationale, evidence, occurrences, blast radius, rank, branch, conflicts. The branch carries the change. There is no type enum, because one proposal may legitimately edit a memory and rewrite a skill and install a third-party skill — and the predecessor's free-text Type field drifted into six spellings of "memory note". A taxonomy that drifts is worse than none.

There is no cap on proposals per night: the list is ranked by recurrence × blast radius, never truncated, and unactioned proposals carry forward and re-rank. Backfill exists — scan.py --backfill --since — but stays deliberately manual: steady state starts from zero, because a proposal mined from a four-month-old session is advice about a setup that no longer exists.

Conflicts are resolved before git ever sees them

Colliding proposals are merged upstream at synthesis, so git rarely sees a conflict; the ones that remain get badged in the dashboard by detect-conflicts.sh, which runs git merge-tree --write-tree against private/trunk before you ever click. merge-approved.sh then squash-merges approved branches serially, in approval order. It is the second producer of these branches — ai-setup-audit works from setup state rather than session history, into the same review flow.
