The predecessor died and nobody noticed

retro, the predecessor this replaces, wrote its findings to markdown reports that piled up unaggregated — and when it quietly stopped running, nothing surfaced that it had. Three root causes, three deliberate design choices here:

  • It required manual invocation → launchd runs dream nightly, unprompted.
  • It wrote per-session reports nobody aggregated → consolidating across sessions is the point; per-session artifacts are ephemeral.
  • It died silently → the dashboard shows "last dream: N days ago" and turns alarming when that goes stale.

The old prefilter was a verbosity detector

Six independent readers audited the original single-stage keyword filter over 86 sessions and measured its recall at 20–64%. It captured zero assistant turns, and its capture rate rose monotonically with turn length — 0% under 20 words, 79% at 200+. It was keeping the narration and dropping the objections. About 60 of 91 misses are unreachable by any pattern list, which is why the judge is not optional.

So the funnel inverted: stage 1 now admits every substantive human turn plus any assistant segment making a first-person past-tense claim, and stage 2 decides. Stage 1 has two writers — scan.py nightly (authoritative, idempotent) and a stop.sh hook every turn (pure optimization). If every hook fails forever the system still works.

Subagent transcripts, with the humans thrown out

Assistant self-retraction turned out to be the highest-value signal class the audit found, and subagent output is nearly pure assistant text — so --subagents mines them. But a subagent transcript is not a session: there is no human in it, and its "user" turn is a dispatch prompt written by another agent. Stage 1 reads those turns as context only and emits no user-role moments from these files.

Measured, that one suppression drops ~21,500 would-be "human signal" moments — 2.5× the assistant yield — including briefs that read exactly like stated user preferences. Moments are attributed to the parent session so they cluster with the work that produced them, and occurrences collapses one parent's fan-out to 1, so a single event cannot outrank a real recurrence. Against the obvious objection that this is all duplicate text: 99.5% of subagent assistant moments are absent from what stage 1 captures from the parent.

A path that adds five moments. Stage 1 also mines successful Task tool_results in the parent transcript — but 1,881 of 1,884 of those subagent transcripts are already on disk, so --subagents has read them. Turning the path on adds 5 genuinely new moments to 99,137. It exists so capture degrades gracefully if subagent transcripts stop being written, not because value is being thrown away today.

Exactly two stages leave the machine

Transcripts contain client work, so egress is a real cost — and it was paid deliberately, twice, with an A/B behind it. Local synthesis measured 4.5–6.0 out of 12 against Claude's 11.1–11.8. That gap is not "slightly worse": qwen3-coder:30b proposed hook interception inside the prose-only ponytail skill in 6 of 11 proposals, invented a ~/Desktop/Code that does not exist, and never once declined.

Everything else is local — prefilter.py needs no model at all, cluster.py embeds with nomic-embed-text on Ollama. And the honest footnote the skill insists on: local clustering is not an egress saving. The hybrid was tested and saves zero bytes, because synthesis sends the same candidate text either way. Clustering is local because embeddings are cheap and instant, not because it protects anything.

No taxonomy, no cap, no backfill

The proposal envelope carries only what the dashboard needs to render and sort. The branch carries the change. There is no type enum, because one proposal may legitimately edit a memory and rewrite a skill and install a third-party skill — and the predecessor's free-text Type field drifted into six spellings of "memory note". A taxonomy that drifts is worse than none.

There is no cap on proposals per night: the list is ranked, never truncated, and unactioned proposals carry forward and re-rank. Backfill exists but stays deliberately manual — steady state starts from zero, because a proposal mined from a four-month-old session is advice about a setup that no longer exists.

The four things it will not do

  • Never touch main. It is a publish artifact; all work targets private/trunk. Publishing stays a deliberate human act.
  • Nothing auto-applies. Which is exactly why there is no self-modification fence — a proposal that rewrites this skill is just another branch you review.
  • ~/.claude/projects is read-only input. Never written to, never deleted from.
  • Never the find wrapper. Use /usr/bin/find — the shell wrapper rejects compound predicates and exits 0 on failure, so failures look like successes.

Colliding proposals are merged upstream at synthesis, so git rarely sees a conflict; the ones that remain get badged in the dashboard by git merge-tree --write-tree before you ever click. It is the second producer of these branches — ai-setup-audit works from setup state rather than session history, into the same review flow.
