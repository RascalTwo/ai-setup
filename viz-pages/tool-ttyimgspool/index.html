The problem

Claude Code looks at images constantly — screenshots it takes, images you paste, files it reads. You never see any of them. And you never will inline: two processes cannot interleave writes to a tty owned by a full-screen TUI, so a large image gets shredded mid-payload and arrives as literal base64 text. That's not a feature waiting to be built. It's the terminal.

So the images go somewhere else. A hook spools them per session; prefix+i in herdr opens a gallery scoped to the session in the pane you're already in, and the pane goes away when you leave it.

What gets captured

A PostToolUse hook runs on every tool call, plus UserPromptSubmit. The rule that matters is the asymmetry in the card: an image path is spooled when a tool was asked to act on it — open shot.png, cp, ls — and ignored when it merely showed up in the tool's output. One ls ~/Pictures would otherwise flood the gallery. Base64 images in output are the exception, and are captured: those are images Claude actually looked at.

The same file mentioned twice is stored once — dedup is by basename plus byte size.

The keys

# gallery
1…9 then Enter   open image N   (type the whole number; nothing fires until Enter)
Backspace / Esc  correct or cancel the number
] [              next / previous page
a                toggle this session ⇄ all sessions
q                quit

# single image
n p              older / newer
g                back to the gallery
d                delete this image
C                delete all (confirms)

Numbering is global: image 36 is 36) on page 2, not 1).

Which session is "this" session

Sessions are scoped by herdr's agent_session for the pane, which the hook and the viewer each resolve independently — so they agree without passing anything between them. Claude Code's own session_id is deliberately not used: a session running as a background job reports the job id instead, and the two would disagree.

If a session has no images of its own, the gallery falls back to showing every session rather than an empty screen. a toggles back.

The status line

🖼 8 · 10m — how many images this session has, and how long ago the newest arrived. It turns yellow when something landed in the last two minutes, and disappears entirely when the session has none.

Install

bun install.ts     # symlinks both scripts, installs chafa, merges the keybinding
herdr server stop  # then reattach
The restart is not optional the first time. The gallery depends on herdr's experimental.kitty_graphics, and that setting only takes effect on a full server restart.

Requires herdr, chafa, and a terminal that speaks the kitty graphics protocol (Ghostty, kitty, WezTerm). Without chafa the hook still spools images — only the viewer goes blank. Two env vars tune it: TTYIMGSPOOL_DIR (default ~/.claude/ttyimgspool) and TTYIMGSPOOL_KEEP (default 100, pruned when the gallery opens).

What it doesn't do

  • No inline images in the transcript — see above; not fixable from here.
  • No click-to-open. Terminals can't run a command from a click, and an OSC 8 file:// link opens Finder, not the image.
  • herdr only for the keybinding and session scoping. The viewer itself is plain bash plus chafa and runs anywhere — you just launch it yourself, and lose scoping.
