↓  WHY IT EXISTS

The problem

Speech-to-text is the boring prerequisite for half the interesting work — reading a narrated video, salvaging a meeting capture, mining a voice memo. So every skill that needed it re-derived the same Whisper command, badly. And the obvious one, the plain openai-whisper CLI, quietly falls back to CPU and grinds.

Worse than slow: the re-derived commands all shared the same silent failure. Whisper invents phrases over quiet audio and loops on them, and a looped transcript is structurally perfect — right file size, plausible word count, evenly spaced timestamps. One meeting archive produced 1,992 consecutive Next., 2,625 × Up., 1,027 × Yeah. Nothing in the output said so.

Reach for it when

  • You want a fresh transcript of the speech in a file on disk — a recording with no caption track, or a clean re-transcription.
  • You need it local — nothing uploaded, ~0 Claude tokens.
  • You want machine-readable output: --format json gives a word-timestamped transcript.

Not this skill: what a video shows visually → read-video-locally. An already-embedded caption track → extract-video-subtitles (ffmpeg stream copy, instant). A Drive/Meet recording behind a browser → extract-gdrive-transcript.

The receipt

Point it at a file. That's the whole interface:

# writes txt/vtt/srt/tsv/json into <stem>.transcript-<model-tag>/ beside the recording
skills/transcribe-media/transcribe.sh ~/Movies/"2026-07-15 16-33-32.mkv"

# or capture just the transcript path — it is the last stdout line
transcript=$(skills/transcribe-media/transcribe.sh meeting.mp4 --format txt --language en | tail -1)

Options: --model · --output-dir · --format {txt,vtt,srt,tsv,json,all} (default all) · --language (omit to auto-detect; en is faster and avoids misdetection) · --keep-wav · --engine {auto,parakeet-mlx,mlx_whisper,parakeet,whisper.cpp}. Everything after -- is forwarded verbatim to the engine.

Fine print

  • It transcribes speech, and only speech. What is on the screen, who is gesturing, whether the demo worked — none of that reaches it. That is read-video-locally.
  • First run per model downloads it (turbo ≈ few hundred MB) to ~/.cache/huggingface; cached after that.
  • Needs ffmpeg/ffprobe plus at least one engine: parakeet-mlx or mlx_whisper on Apple Silicon, onnx-asr Parakeet or a built whisper.cpp binary elsewhere. With none installed it says so rather than guessing.
  • Hard recording? --model mlx-community/whisper-large-v3 buys accuracy with time.
Verify content, never structure. The defences below stop the loops seen so far, but the danger was never a crash — it was a transcript that passes every structural check and is wrong in every word. sort -u file.txt | wc -l against total lines is the cheapest tell.

Where it lives

Entry point skills/transcribe-media/transcribe.sh — a shim that finds a working Python 3 and execs transcribe.py, which is the implementation and runs on Windows too.
Requires ffmpeg and ffprobe on PATH, Python 3, and at least one engine — parakeet-mlx / mlx_whisper (Apple Silicon), onnx-asr Parakeet, or whisper.cpp found via WHISPER_CPP_BIN, PATH, or WHISPER_CPP_DIR.
Integrates Nothing. No MCP server, no network service, no browser. It is a wrapper around its engines — subprocesses, except onnx Parakeet, which runs in-process — which is why other skills can call it without inheriting a dependency.
Called by read-video-locally, extract-video-subtitles, and extract-gdrive-transcript all route here rather than rolling their own speech-to-text invocation. One primitive, shared.
Its state None. The manifest declares state: false and means it — nothing under ~/.agents/, no database, no index, no memory of the last run. Two things look like state and are not: ~/.cache/huggingface is huggingface's model cache, populated and owned by the hub client and shared with everything else on the machine (onnx Parakeet keeps its weights in ~/.cache/transcribe-media for the same reason), and the <stem>.transcript-<model-tag>/ folder is the output you asked for, sitting beside your recording where you can see it.
Safe to delete Both, freely. Deleting a transcript folder loses a transcript; deleting the huggingface cache costs one re-download. Neither breaks the skill, because there is nothing for it to lose.
Cleans up after itself The intermediate audio.wav — ~100 MB per hour — is removed in a finally block on every exit, success, failure, or interrupt, unless --keep-wav. The older success-only cleanup stranded gigabytes on exactly the paths that failed.

The engine is probed for, not inferred

select_engine() walks ENGINE_ORDER and takes the first engine that probes: parakeet-mlx, then mlx_whisper (each via shutil.which plus platform.machine() == "arm64"), then onnx-asr Parakeet (importable in this interpreter), then whisper.cpp — WHISPER_CPP_BIN, else whisper-cli, main, or whisper on PATH, else a walk of WHISPER_CPP_DIR. Capability, not platform — the same box can lose an engine to a failed upgrade and still transcribe. Parakeet goes first because it makes ~30% fewer errors than Whisper turbo on meeting audio and was trained to stay silent over silence. A Whisper --model, or a --language outside Parakeet's 25, routes straight to Whisper; --engine forces one.

Every audio track, mixed and levelled

ffprobe first: -select_streams a -show_entries stream=index counts the audio tracks. Screen recorders split mic, system and room across separate tracks and ffmpeg's default stream pick silently takes one — which may be the silent one. So the filter graph names all of them: 

[0:a:0][0:a:1]…amix=inputs=N:duration=longest:normalize=0,
loudnorm=I=-16:TP=-1.5:LRA=11[a]   → -ac 1 -ar 16000 audio.wav

loudnorm lifts the mix to −16 LUFS because far-field room audio lands near −36 dB and that is the input Whisper hallucinates on. LRA=11 keeps the dynamic range and TP=-1.5 prevents clipping, so this is not "make everything loud". It is applied to the throwaway wav; the source file is never touched.

Three defences against one failure

The repetition loop gets attacked at three points, because none of them is sufficient alone. Track mixing removes the silent-track case. Loudness normalization removes the too-quiet case. And --condition-on-previous-text False — passed on every mlx_whisper run, not offered as a remedy — removes the mechanism that sustains a loop once it starts, since Whisper otherwise feeds each window's output back as the next window's prompt.

What survives all three is caught after the fact. check_not_stuck() scans the .txt for consecutive identical lines and fails the run at STUCK_RUN = 50 in a row over at least STUCK_MIN_LINES = 20 lines. The thresholds are measured, not guessed: real transcripts in this corpus top out near 36 repeats, stuck ones start near 180. Partial output is kept for inspection and the error names the culprit line and its count.

One schema out, whichever engine ran

Parakeet and whisper.cpp both emit sub-word tokens in their own JSON layouts. parakeet_to_result() and whisper_cpp_to_result() rewrite them into OpenAI Whisper's result shape (Parakeet's raw output is kept as <stem>.parakeet.json, the source of truth), and merge_words() merges tokens into words on the rule that a token not starting with a space continues the previous one. Callers see {text, segments, language} with word timings either way, and never branch on engine.

A bug that cost four recordings their GPU time. subprocess with text=True decodes using the locale encoding — cp1252 on Windows. One byte outside it raises inside the reader thread, which does not propagate: run() returns with that stream set to None, and the failure surfaces much later as unsupported operand +: 'NoneType' and 'str'. Every capture here now pins encoding="utf-8", errors="replace".

What the caller actually gets

Outputs land in <stem>.transcript-<model-tag>/ next to the source, the tag stripped down by model_tag() so mlx-community/parakeet-tdt-0.6b-v3 becomes parakeet-tdt-0.6b-v3, mlx-community/whisper-large-v3-turbo becomes turbo, and two models can coexist. A [transcribe-media OK] engine=… model=… words=… format=… -> … header goes to stderr; the transcript path alone goes to stdout, last line, so | tail -1 is a contract rather than a trick. Failure prints TRANSCRIBE_FAILED … to stderr and exits non-zero.
