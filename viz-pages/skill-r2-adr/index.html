↓  WHY IT EXISTS

One repo had 1 ADR, another had 23

ADRs got written unevenly, and the unevenness had a cause. ai-setup had one. timeline-studio had twenty-three. Same author, same agents, same habits otherwise.

The only trigger lived in Matt Pocock's domain-modeling skill: a three-part test, hard to reverse and surprising and a real trade-off. It is a good test. But it sat in a skill that loads when someone is already thinking about a domain model, and it reached everything else indirectly, through grill-me-viz. A change that made a questionable decision during ordinary building never walked past it.

The contrast case is Grey Lovelace's Decky repo: 35 ADRs in six days. Its trigger was shorter and blunter, "a decision another developer would question", and it sat in CONTRIBUTING.md, which Claude Code loads on every session. The record got written because the rule was already in the room.

r2-adr keeps Decky's trigger and puts it where the work happens, and borrows the format from the one published ADR skill that matched what was wanted.

It fires on four things, and none are a command

  • A change makes a decision another developer would question. A dependency, a pattern, a convention, a rejected obvious approach, a constraint the code can't show. The agent writes the ADR in the same change, without asking, then names it in the handover: "Recorded docs/adr/2026-11-13-run-builds-in-worktrees.md". You delete a wrong one in review.
  • Before changing code an ADR governs. List docs/adr/, read every ADR whose title touches it, follow it.
  • Superseding an ADR when the decision itself changes.
  • Reviewing a change for a missing ADR, and migrating old numbered ADRs to the dated shape.

The rule is not left to the skill alone. It is also written into AGENTS.md §3, Kelpie's build prompt, r2-pr's body template, r2-gauntlet's review pass and grill-me-viz, so it is met wherever the work starts.

Work that follows an existing pattern or an existing ADR needs no new one. The trigger is about questionable decisions, not every decision.

What r2-adr refuses to do

  • No index file. No README.md listing, no --update-index. An index is a second place to forget; the dated filenames sort themselves.
  • It does not migrate a team's or client's repo on its own. Numbered ADRs there are migrated only after the team agrees. The lint will still flag them.
  • A missing ADR is a warning, never a block. The review pass names the decision and the ADR it needs, and the change still ships.
  • It does not invent a format. Section headings, the template and the review checklist come from upstream. Only the filename, the Status line and the trigger are ours.
  • Migrated alternatives are reconstructed, and say so. An old record that never listed alternatives gets them rebuilt from code and history, with a line in More Information labelling that.

What adr-lint checks

adr-lint.ts takes no arguments and finds docs/adr/ at the git root, or takes folders and files. It prints ok and exits 0, or one line per problem and exits 1. A repo with no docs/adr/ prints ok (no docs/adr).

Dated filename YYYY-MM-DD-slug.md, lowercase and dashes, and the date must be a real one (2026-02-31 fails).
Numbered names rejected 0007-use-postgres.md fails with a pointer to migrate it. This is the check that surfaces old ADRs.
H1, then Status Line 1 is # Title, no YAML frontmatter, and the next non-blank line matches the Status regex: Accepted, Proposed, Deprecated or Superseded by [file](file), then a comma and a real date.
Three sections, in order ## Context and Problem Statement, ## Decision, ## Alternatives Considered. Missing or out of order both fail.
No placeholders A leftover {TITLE} or template brace fails. Judged outside code fences and inline code, so an ADR may quote markdown.
Links resolve Every relative .md link must exist next to the file, which is what keeps a Superseded by pointing at something real.
Lint is the floor, not the judge. It checks shape. Whether the decision is worth recording, or the alternatives are honest, is a review job, and a missing ADR only ever earns a warning.
