↓  WHY IT EXISTS

Reading about a build is not judging it

Before this skill, a finished build was handed over as a PR draft plus a film of the diff. Joseph read and watched, but never used the thing. Prototypes showed that walking through the real build is better, but each one was made by hand, with its own stage, its own guide and its own way of getting words back to the agent.

The first prototype also taught the hardest lesson. Its Send "never arrived": no decision had been picked, so Send was disabled, and a disabled button that says nothing looks like a button that was pressed. Reproduced 2026-10-24, task ai-walkthrough-viz-skill.

When to fire it

A build agent runs it at the end of a build, or when the user says "walkthrough", "walk me through it" or "walkthrough viz".

  • viz create walk-<task-id> --from "$WALK/template" makes the page.
  • bun "$WALK/from-spec.ts" <run>/spec.json <viz>/walk.json writes a skeleton from the signed spec: one step per ✓ example.
  • Fill the steps, stage throwaway copies of the build, run viz verify, then hand over the URL.
  • The human follows the guide, reacts as it strikes them, decides once, presses Send.

What it doesn't do

  • Web and CLI changes only. A skill, prose or refactor change has no walkthrough yet.
  • Accept is final. Accept + Send approves the task with your words, then greys out: there is nothing more to send. To ask for anything, press Changes instead.
  • Pins in the app's iframe land on the frame, not on the element under it.
  • Outside a Kelpie run, Send has no pane to reach. The page says so instead of claiming a Send.

Spec, steps, stage, act, decide, Send

Everything starts from the signed spec.json. from-spec.ts turns each ✓ example into a step in walk.json and rejects any say that judges. The page then reads walk.json and drives the real build.

Why Send says so

The feedback widget's own Send closes the tab and says "Sent ✓" whether or not anything reached the agent. So Send relays first and does not wait on it. The page shows Delivered or Not delivered, and Not delivered keeps the words in a box you can copy. "The agent has no live pane" counts as not delivered.

Accept is approval. Accept + Send runs kelpie approve with your words, comments included, as the spec page's Sign off runs signoff; the page then says Approved or Not delivered. Changes + Send relays your notes to the build agent instead.
