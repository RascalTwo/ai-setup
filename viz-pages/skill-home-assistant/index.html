↓  WHY IT EXISTS

The house had names the agent couldn't see

Ask an agent to turn on the desk plug and it has two problems. Entity ids keep whatever a device was paired as, so "Desk" may be switch.plug_a, and the agent has no way to know that. And the obvious call, a curl with a bearer token, puts a credential with the full rights of your account into the transcript.

home-assistant answers both: one script holds the token, and find reads names, areas, devices and labels from the running instance rather than from a list someone wrote down and forgot to update.

Ask what exists, then call it

The skill fires on smart home requests. Three of the commands add something the API alone doesn't give you, and api reaches everything else: 

ha.py find office desk --domain switch
ha.py on switch.plug_a
ha.py api GET /api/services
ha.py api POST /api/services/climate/set_temperature '{"entity_id": "climate.office", "temperature": 70}'

What it doesn't do

  • It does not mint credentials. You create the token in your profile and paste it at a hidden prompt. The skill never logs in for you.
  • It does not speak WebSocket. Entity aliases and registry edits sit outside the documented REST endpoints, so find can't search an alias directly.
  • It does not know your house. It learns your devices and automations by asking Home Assistant.
  • It can't stop an automation. A confirmed change is true when reported. An automation can reverse it later.

Where it lives

Integrates The Home Assistant REST API, including its template endpoint.
Requires python3, standard library only, on macOS, Linux or Windows.
Its state None in the agent state directory. Your instance URL and token are configuration in ~/.config/home-assistant/.
Safe to delete? Deleting the skill loses nothing. Deleting the config means creating and saving a new token, and the old one stays valid until you revoke it in your profile.

Why lookup goes through a template

/api/states carries names but not areas, devices or labels. Home Assistant's template engine can reach those, so find posts one Jinja template to /api/template that walks states and returns JSON, then requires every search word to appear in the combined text.

Two checks at the boundary

on and off accept only ids shaped like domain.object, which also keeps out Home Assistant's special target all. api accepts only paths starting with /api/, because the path is appended to the URL and anything else could send the token to another host.
