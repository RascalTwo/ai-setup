The trap it exists for

Azure gives you a console log stream, and reaching for it is the obvious move. The skill states the catch plainly: az containerapp logs show --type console often returns empty results for crashed containers. The replica you most need to hear from is the one least likely to answer — so an empty result reads like "no logs exist" when the logs exist fine, just somewhere else.

That single line is most of the skill's value. Everything after it is the detour, written down so nobody rediscovers it at 5pm during a failed deploy.

Two questions, two sources

System events tell you the shape of the failure — is it even getting an image, is it starting and dying, is it starting and never binding? That's --type system --tail 100, and there are three patterns worth grepping for:

  • ReplicaUnhealthy / Startup probe failed — the app isn't binding to its port in time.
  • ContainerBackOff / Persistent Failure to start container — crash loop.
  • ImagePullBackOff — image registry or tag issue.

Console logs tell you why: the exception, the missing config, the line that actually threw. Neither source substitutes for the other, which is why the skill walks both instead of picking one.

The workspace ID isn't on the app

The detour's awkward part: you can't query Log Analytics without a workspace ID, and the container app doesn't carry one. It's on the managed environment, so you hop app → environment → workspace before you can ask a single question.

ENV_NAME=$(az containerapp show -n <APP> -g <RG> \
  --query "properties.managedEnvironmentId" -o tsv | xargs -I{} basename {})

WORKSPACE_ID=$(az containerapp env show -n "$ENV_NAME" -g <RG> \
  --query "properties.appLogsConfiguration.logAnalyticsConfiguration.customerId" -o tsv)

managedEnvironmentId comes back as a full ARM resource ID, hence the basename — the env show command wants the bare name.

Then one KQL query, with deliberate limits

az monitor log-analytics query -w "$WORKSPACE_ID" --analytics-query \
  "ContainerAppConsoleLogs_CL
   | where ContainerAppName_s == '<APP>'
   | where TimeGenerated > ago(1h)
   | order by TimeGenerated desc
   | take 80
   | project TimeGenerated, Log_s, RevisionName_s" -o table

A one-hour window and eighty lines — enough to catch a deploy that just failed, small enough to actually read. The skill is explicit that the output may be large and that you should read all of it rather than skim, hunting for stack traces, Application run failed, and above all lines from the most recent revision — the one with the highest --NNNNNN suffix. Old revisions are still in the table and will happily tell you about a bug you fixed yesterday.

If you don't know the app name, that's step one, not a blocker: az containerapp list --query "[].{name:name, resourceGroup:resourceGroup}" -o table. What the skill does assume is that az login has already happened — it does not authenticate for you.

The pattern table, and its accent

Once you have the trace, the skill maps the common lines to causes:

Log patternLikely cause
ConflictingBeanDefinitionExceptionDuplicate Spring bean names across packages
connection refused (DB / service)Missing or wrong env vars / secrets
NoSuchBeanDefinitionExceptionMissing dependency or config class
Port already in use / never bindsWrong SERVER_PORT, or a crash before listen
ImagePullBackOffWrong image tag, registry auth, or ACR not reachable

Three of those five are Spring-specific, and that's worth saying out loud: this table was written from the failures it was actually used on. It's a head start, not a taxonomy. The retrieval steps above are language-agnostic; the interpretation step is where your own stack takes over.

Where it stops

At the cause. The last line of the skill is "fix the source code or configuration and redeploy" — an instruction to you, not a step it performs. It doesn't patch, doesn't roll back, doesn't re-trigger a deploy, and doesn't touch the container app's configuration. Nothing it runs mutates anything; every command is a read.

A narrow skill that ends where the risk starts. Its whole job is turning "the deploy failed and the logs are empty" into a specific line of your own code.
