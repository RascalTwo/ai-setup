Inference over interview

You described the thing once. A pipeline that answers with twenty clarifying questions has made you do the work twice. r2-sdlc's first cardinal rule is to try to answer every question itself — from your input, the codebase, CLAUDE.md, the project's conventions — and ask only what it genuinely cannot determine.

So it doesn't quiz, it redlines: it hands you a finished draft and you edit or approve it. understood.md gets a problem, a solution, acceptance criteria as GIVEN/WHEN/THEN, and — crucially — an Assumptions list, so what it inferred is visible and you can catch a miss. Its Ambiguities section is for genuine A/B questions only; the skill says outright that zero is acceptable and often correct.

The three stops

  • Approving understood.md — what we're building. Nothing proceeds until you say so.
  • Approving design.md — how. Approach, touch points, an ordered test plan, style notes lifted from neighbouring files, technical risks. Approval can be terse.
  • A design pivot — and only that. If implementation or a Tier-1 reviewer discovers the design is actually wrong, it stops, describes the gap, and proposes a specific change for you to approve. It doesn't forge ahead.

If the design rests on something hard to reverse — an architectural pattern, a new dependency, a migration — Phase 2 invokes steelman on it before the draft ever reaches you, so what you're redlining is already pressure-tested. Skipped for small, mechanical changes.

Strict TDD means strict

Phase 3 walks the test plan vertically — one full red→green cycle per behavior, easiest first, so the cycles start cheap. No bulk-writing tests then bulk-implementing.

# per behavior, in test-plan order
write the test        GWT, one behavior, committed to a layer
run it                must FAIL — and fail for the RIGHT reason
write the impl        minimum to pass. no speculative cases.
run it                green
run everything prior  no regressions → next behavior

"Fails for the right reason" is the inviolable part: a missing import or a syntax error is not a red test, and the fix goes in the test, not the implementation. Refactoring stays local here — trivial renames, obvious duplication. Architecture is Phase 4's job.

Two tiers, and the order is the point

Tier 1 asks "is it right?" Two read-only reviewers run in parallel, each with a different oracle: fidelity-reviewer checks the implementation against design.md; qa-validator exercises the feature against understood.md. Tier 2 asks "is it good?" — and rather than hardcoding a roster, it hands the change to r2-gauntlet, which fans out the whole quality panel and returns one deduped, consensus-ranked report.

Tier 2 does not run until Tier 1 is clean, because polishing code that's about to change is spent tokens. Each tier is capped at two fix-and-re-review iterations; if it's still failing after that, it escalates to you with the outstanding findings. Reviewers never touch the code — they report, the pipeline decides, and every finding gets an explicit applied-or-deferred call.

On Codex, Tier 2 is a fallback. The gauntlet hasn't been ported yet, so there it spawns the five .codex/agents quality reviewers directly and synthesizes their findings by hand. Same phase, smaller panel.

Everything is written down, and none of it is in your repo

Each run lives at ~/.claude/pipeline-runs/<repo-id>/<slug>/ — the two documents plus a pipeline-state.md tracking phase, approvals and iteration counts. Never inside the repo, never committed. Start the same story twice and it finds the old run and asks whether to resume or restart.

It hands the change back

Phase 7 produces a summary — what was built, each acceptance criterion met or not, tests added, both tiers' results, which reviewer suggestions were applied and which are yours to triage, files touched. Then it stops. No auto-commit, no auto-push, no auto-PR. Ever. The summary is a decent PR description; opening the PR is your move.

And it doesn't skip phases for small work — the scale scales instead. A five-line fix gets a two-line design.
